โค้ดหัวใจของเกมทุกบทตั้งแต่บทที่ 5 คือ **วงวนเกม (Game Loop)** ซึ่งจะได้เห็นครั้งแรกในใบงานของบทนี้:
```python
running = True
while running:
    for event in pygame.event.get():      # 1. รับเหตุการณ์ (ปุ่ม เมาส์ ปิดหน้าต่าง)
        if event.type == pygame.QUIT:
            running = False
    screen.fill((0, 0, 0))                # 2. ล้างจอด้วยสีดำ
    # 3. อัปเดตตำแหน่ง  4. วาดวัตถุ  (บทที่ 5 เป็นต้นไป)
    pygame.display.flip()                 # 5. แสดงภาพที่วาดเสร็จ
    clock.tick(60)                        # 6. คุมอัตราเฟรมไม่เกิน 60 FPS
```

## 2. การแก้ปัญหาด้วยโปรแกรม: วิเคราะห์โจทย์ → ออกแบบ → เขียน → ทดสอบ

### ทำไมไม่ลงมือพิมพ์โค้ดทันที
ผู้เริ่มต้นมักพิมพ์โค้ดก่อนแล้วค่อยคิด ผลคือ "โค้ดรันได้แต่ผิด" ซึ่งอันตรายกว่า error เพราะโปรแกรมไม่เตือน (ดูตัวอย่าง `dotv3` กับเวกเตอร์ 4 มิติในบทที่ 2) การแก้ปัญหาอย่างเป็นระบบมี 4 ขั้น:

| ขั้น | คำถามที่ต้องตอบ | ผลลัพธ์ |
|---|---|---|
| 1. วิเคราะห์โจทย์ (Analyze) | อินพุตคืออะไร เอาต์พุตคืออะไร มีข้อจำกัด/กรณีพิเศษอะไร | รายการ input/output |
| 2. ออกแบบ (Design) | ทำทีละขั้นอย่างไร แยกเป็นฟังก์ชันย่อยอะไรได้บ้าง | pseudocode / ผังงาน |
| 3. เขียนโค้ด (Code) | แปลง pseudocode เป็นไพทอนทีละบรรทัด | ไฟล์ `.py` / `.ipynb` |
| 4. ทดสอบ (Test) | ผลลัพธ์ตรงกับที่คำนวณมือหรือไม่ กรณีพิเศษผ่านหรือไม่ | trace table + ผลรัน |

### ตัวอย่างที่ 1: ค่าเฉลี่ยของตัวเลข 3 จำนวน
**วิเคราะห์:** อินพุต = จำนวน 3 ค่า (`n1`, `n2`, `n3`) · เอาต์พุต = ค่าเฉลี่ย · ข้อจำกัด = ต้องหารด้วย `/` ไม่ใช่ `//` เพื่อไม่ให้เศษหาย

**ออกแบบ (pseudocode):**
```text
1. กำหนด n1, n2, n3
2. total ← n1 + n2 + n3
3. avg ← total / 3
4. แสดง avg
```

**เขียนโค้ด** (จากบทที่ 2):
```python
n1, n2, n3 = 5, 10, 15
total = n1 + n2 + n3
avg = total / 3
print(f"average of {n1} {n2} and {n3} is {avg}.")
```
```
average of 5 10 and 15 is 10.0.
```

**ทดสอบ:** คำนวณมือ $(5+10+15)/3 = 30/3 = 10$ ตรงกับผลรัน `10.0` (เป็น float เพราะ `/`)

![วงจรแก้ปัญหา 4 ขั้น วิเคราะห์ ออกแบบ เขียนโค้ด ทดสอบ พร้อมผลงานของแต่ละขั้นจากตัวอย่างค่าเฉลี่ยของ 5, 10, 15](/infographics/01/problem-solving-cycle-part1.svg)

**วิธีอ่านภาพ** (การ์ดสีด้านซ้ายคือชื่อขั้น ลูกศรชี้ไปที่ "ผลงาน" ของขั้นนั้นด้านขวา)
1. ① วิเคราะห์: เขียนให้ชัดว่าอินพุตคือ `n1, n2, n3 = 5, 10, 15` เอาต์พุตคือค่าเฉลี่ย และข้อจำกัดคือต้องหารด้วย `/`
2. ② ออกแบบ: ได้ pseudocode 4 บรรทัด (กำหนดค่า → รวม → หาร 3 → แสดงผล)
3. ③ เขียนโค้ด: แปลง pseudocode เป็นไพทอนทีละบรรทัด
4. ④ ทดสอบ: คำนวณมือ $(5 + 10 + 15)/3 = 30/3 = 10$ แล้วเทียบกับผลรัน `10.0` — ตรงกันจึงผ่าน (กรอบสีเขียว)
5. เส้นประสีแดงทางซ้ายคือทางวนกลับ: ถ้าผลทดสอบไม่ตรง ให้กลับไปแก้ที่ขั้น ① หรือ ② แล้วเริ่มรอบใหม่ กล่อง ✗/✓ ด้านล่างย้ำว่า "รันได้ไม่ error" ยังไม่ได้แปลว่าถูก

### ตัวอย่างที่ 2: ลูกบอลตกภายใต้ความโน้มถ่วง (จากบทที่ 5)
กฎการเคลื่อนที่ในเกมคือ "ตำแหน่งเปลี่ยนตามความเร็ว แล้วความเร็วเปลี่ยนตามความโน้มถ่วง" โดยใช้ค่าคงที่ `GRAVITY = 0.1` ตามโค้ดต้นฉบับ `ball.py`
```python
GRAVITY = 0.1
y, vy = 100, 0
for frame in range(1, 6):
    y += vy            # ตำแหน่งเปลี่ยนตามความเร็ว
    vy += GRAVITY      # ความเร็วเพิ่มตามความโน้มถ่วง
    print(frame, round(y, 2), round(vy, 2))
```

### ตารางไล่ค่า (Trace Table)
ตารางไล่ค่าคือการ "เป็นคอมพิวเตอร์ด้วยมือ" ไล่ค่าตัวแปรทีละรอบตามลำดับคำสั่ง — ต้องทำตามลำดับบรรทัดจริง (`y += vy` **ก่อน** `vy += GRAVITY`)

| เฟรม | `y` หลัง `y += vy` | `vy` หลัง `vy += 0.1` |
|---|---|---|
| เริ่ม | 100 | 0 |
| 1 | 100 + 0 = 100 | 0.1 |
| 2 | 100 + 0.1 = 100.1 | 0.2 |
| 3 | 100.1 + 0.2 = 100.3 | 0.3 |
| 4 | 100.3 + 0.3 = 100.6 | 0.4 |
| 5 | 100.6 + 0.4 = 101.0 | 0.5 |

```
1 100 0.1
2 100.1 0.2
3 100.3 0.3
4 100.6 0.4
5 101.0 0.5
```

> [!warning] ลำดับบรรทัดมีผลต่อคำตอบ
> ถ้าสลับเป็น `vy += GRAVITY` ก่อน `y += vy` เฟรมที่ 1 จะได้ `y = 100.1` ไม่ใช่ `100` ข้อสอบไล่ค่าทีละเฟรมในบทที่ 5–7 วัดตรงจุดนี้

> [!tip] จุดสังเกตจากตาราง
> `y` ตกเร็วขึ้นเรื่อย ๆ (เพิ่ม 0, 0.1, 0.2, 0.3, 0.4) เพราะ `vy` โตเป็นเส้นตรง นี่คือการตกแบบมีความเร่ง (Accelerated Motion) ที่จะเรียนในบทที่ 5

![ตารางไล่ค่าลูกบอลตก 5 เฟรม แสดงว่า y ใช้ค่า vy ของแถวก่อน ได้ y = 101.0 ที่เฟรม 5 และผลเมื่อสลับลำดับบรรทัด](/infographics/01/problem-solving-cycle-part2.svg)

**วิธีอ่านภาพ**
1. ① ในโค้ดคือ `y += vy` ซึ่งทำ **ก่อน** จึงใช้ค่า `vy` ที่ได้จากแถวก่อนหน้า — ในตาราง ลูกศรสีม่วงลากจากค่า `vy` (สีเขียว) ของแถวบนลงมาเป็นตัวบวกในแถวถัดไป เช่น เฟรม 3: $100.1 + 0.2 = 100.3$
2. ② คือ `vy += 0.1` ซึ่งทำทีหลัง ค่าใหม่นี้จึงถูกใช้ในเฟรมถัดไป (0 → 0.1 → 0.2 → … → 0.5)
3. แถวกรอบสีส้มคือคำตอบเฟรมที่ 5: `y = 101.0`, `vy = 0.5`
4. ③ เมื่อเห็นแบบแผน (ระยะตกแต่ละเฟรม 0, 0.1, 0.2, 0.3, 0.4) จึงสรุปเป็นสูตร $y_n = 100 + 0.1 \times \frac{n(n-1)}{2}$ ตรวจที่ $n = 5$ ได้ 101.0 ตรงกับตาราง และหาเฟรมที่ 10 ได้ทันทีเป็น 104.5
5. กล่อง ✗ แสดงผลเมื่อสลับเป็น ② ก่อน ①: เฟรม 1 ได้ `y = 100.1` และเฟรม 5 ได้ `y = 101.5` ซึ่งผิดจากโค้ดจริง (กล่อง ✓: เฟรม 1 = 100, เฟรม 5 = 101.0)

### หาคำตอบเฟรมที่ n โดยไม่ต้องไล่ทุกเฟรม
จากตาราง ระยะที่ตกในเฟรมที่ $k$ คือ $g(k-1)$ (0, 0.1, 0.2, …) เมื่อรวมกัน $n$ เฟรมจะได้
$$y_n = y_0 + g\,(0 + 1 + \dots + (n-1)) = y_0 + g\,\frac{n(n-1)}{2}$$
ตรวจที่ $n = 5$: $100 + 0.1 \times \frac{5 \times 4}{2} = 100 + 1.0 = 101.0$ ตรงกับตาราง และใช้หาเฟรมที่ 10 ได้ทันที: $100 + 0.1 \times 45 = 104.5$ นี่คือตัวอย่างของการใช้ trace table หา **แบบแผน** ก่อน แล้วค่อยสรุปเป็นสูตร ซึ่งต้องตรวจกลับด้วยการรันจริงทุกครั้ง (ขั้นที่ 4)

```text
                                 │ใช่

                         vy ← vy + 0.1

```

> ถ้ารันเซลล์ที่ใช้ตัวแปร `avg` ก่อนเซลล์ที่สร้าง `avg` จะได้ `NameError` และถ้าแก้โค้ดเซลล์บนแล้วไม่รันซ้ำ เซลล์ล่างจะยังใช้ค่าเก่า เมื่อสับสนให้ **Runtime → Restart and run all** เพื่อรันใหม่ทั้งหมดตามลำดับ

![โค้ด x = 5 และ x = x + 1 รันเป็นไฟล์ .py สองครั้งได้ 6 ทั้งสองครั้ง แต่รันเซลล์เดิมซ้ำใน Notebook ได้ 6 แล้ว 7 พร้อมผลหลัง Restart](/infographics/01/py-vs-ipynb.svg)

**วิธีอ่านภาพ** (กล่องสีส้มคือค่า `x` ในหน่วยความจำ กล่องสีเขียวคือสิ่งที่แสดงออกมา)
1. ① ไฟล์ `.py`: ทุกครั้งที่รัน หน่วยความจำเริ่มจาก "ว่าง" → `x = 5` → `x = 6` → พิมพ์ `6` รันครั้งที่ 2 ก็เริ่มว่างใหม่ จึงได้ `6` เสมอ
2. ② Notebook: รันเซลล์ A (`In[1]`) → kernel จำ `x = 5` ไว้ ยังไม่มีผลแสดง
3. ③ รันเซลล์ B (`In[2]`) → `x` กลายเป็น 6 และแสดง `Out[2]: 6`
4. ④ (แถวกรอบม่วง) รันเซลล์ B **ซ้ำ** (`In[3]`) → kernel ยังจำ `x = 6` จากรอบก่อน จึงได้ `x = 7` และ `Out[3]: 7` ทั้งที่โค้ดในเซลล์ไม่ได้เปลี่ยน
5. ⑤ Restart kernel → หน่วยความจำว่าง ⑥ ถ้ารันเซลล์ B ก่อน A จะได้ `NameError` เพราะยังไม่มี `x`
6. กรอบสีส้มด้านล่างคือคำตอบแบบข้อสอบ: รัน A ครั้งเดียวแล้วรัน B 3 ครั้ง ได้ 6 → 7 → 8 — กล่อง ✗/✓ ย้ำให้นับจำนวนครั้งที่รันจริงจาก `In[ ]` ไม่ใช่จำนวนเซลล์ที่เห็นบนจอ

### ไล่ค่าการรันเซลล์ผิดลำดับ
| การกระทำ | `x` ใน kernel หลังรัน | ผลที่แสดง |
|---|---|---|
| รันเซลล์ A `x = 5` | 5 | — |
| รันเซลล์ B `x = x + 1; x` | 6 | `Out[2]: 6` |
| รันเซลล์ B ซ้ำ | 7 | `Out[3]: 7` |
| Restart kernel | (ไม่มี `x`) | — |
| รันเซลล์ B ก่อน A | (ไม่มี `x`) | `NameError: name 'x' is not defined` |

ข้อสอบมักถามว่า "รันเซลล์นี้ 3 ครั้งได้ค่าเท่าใด" ให้ไล่ค่าตามจำนวนครั้งที่รันจริง ไม่ใช่ตามจำนวนเซลล์ที่เห็นบนหน้าจอ

### โครงสร้างของ Traceback
เมื่อโปรแกรมผิดพลาดตอนรัน ไพทอนพิมพ์ **Traceback** ให้อ่านจาก **บรรทัดสุดท้ายก่อน** (ชนิดและข้อความของ error) แล้วย้อนขึ้นไปดูว่าเกิดที่ไฟล์ใด บรรทัดใด
```python
print(nmae)
```
```
Traceback (most recent call last):
  File "lab01.py", line 1, in <module>
    print(nmae)
          ^^^^
NameError: name 'nmae' is not defined
```
อ่านว่า: ชนิด `NameError` · ข้อความ "ชื่อ `nmae` ยังไม่ถูกนิยาม" · เกิดที่ `lab01.py` บรรทัด 1 · เครื่องหมาย `^^^^` ชี้ตำแหน่งในบรรทัด → สะกดชื่อตัวแปรผิด

### Traceback ที่มีหลายชั้น (เมื่อเรียกฟังก์ชัน)
เมื่อ error เกิดในฟังก์ชัน Traceback จะแสดงทุกชั้นของการเรียก โดยเรียง **จากชั้นนอกสุดลงไปชั้นในสุด** (most recent call last คือชั้นที่เกิดล่าสุดอยู่ล่างสุด)
```python
def average(total, n):
    return total / n

print(average(30, 0))
```
```
Traceback (most recent call last):
  File "lab01.py", line 4, in <module>
    print(average(30, 0))
          ^^^^^^^^^^^^^^
  File "lab01.py", line 2, in average
    return total / n
           ~~~~~~^~~
ZeroDivisionError: division by zero
```

![Traceback ของ ZeroDivisionError ที่มี 2 ชั้น พร้อมป้ายหมายเลข 1–4 บอกลำดับการอ่าน การไล่ค่าหาต้นเหตุ และกล่องเทียบ SyntaxError](/infographics/01/traceback-anatomy.svg)

**วิธีอ่านภาพ** (กล่องบนคือโค้ด กล่องดำคือ Traceback ที่ได้ ป้ายหมายเลขคือลำดับการอ่าน ไม่ใช่บนลงล่าง)
1. ① อ่านบรรทัดสุดท้ายก่อน: `ZeroDivisionError: division by zero` บอกชนิดว่าเป็นการหารด้วยศูนย์
2. ② ชั้นล่างสุด `line 2, in average` คือบรรทัดที่พังจริง และ `^` ชี้ที่เครื่องหมาย `/` (แถบสีส้มในโค้ด)
3. ③ ชั้นบน `line 4, in <module>` คือผู้เรียกที่ส่ง `average(30, 0)` ทำให้ `n = 0` (แถบสีน้ำเงินในโค้ด)
4. ④ หัว `most recent call last` เตือนว่าชั้นที่เกิดล่าสุดอยู่ล่างสุด
5. แถวชิปตรงกลางไล่ค่าให้เห็นต้นเหตุ: บรรทัด 4 ส่ง `total = 30, n = 0` → บรรทัด 2 คำนวณ `30 / 0` → `ZeroDivisionError` ถ้าแก้ที่ผู้เรียกเป็น `average(30, 3)` จะได้ `10.0` (กรอบสีเขียว)
6. กล่อง ✗/✓ เตือนว่าอย่าไปแก้สูตรบรรทัด 2 ที่ถูกอยู่แล้ว และกล่องสีม่วงล่างสุดเทียบกับ `SyntaxError` ที่ไม่มีหัว `Traceback` เพราะโปรแกรมยังไม่เริ่มทำงาน

บทเรียนสำคัญคือ บรรทัดที่พัง (บรรทัด 2) **ไม่จำเป็นต้องเป็นบรรทัดที่ผิด** ในตัวอย่างนี้สูตร `total / n` ถูกต้องแล้ว แต่ผู้เรียกในบรรทัด 4 ส่งค่า `n = 0` เข้าไป จึงต้องไล่ขึ้นไปดูชั้นบนเสมอ วิธีแก้ทำได้ 2 ทาง คือแก้ที่ผู้เรียกให้ส่งค่าที่ถูกต้อง หรือป้องกันในฟังก์ชันด้วย `if n == 0:` ก่อนหาร (หลักเดียวกับ `if direction.length() > 0:` ในเกมบทที่ 6–8)

### ชนิดข้อผิดพลาดที่พบบ่อย
| ชนิด | เกิดเมื่อ | ตัวอย่างโค้ด | บรรทัดสุดท้ายของ Traceback |
|---|---|---|---|
| `SyntaxError` | ไวยากรณ์ผิด โปรแกรม **ไม่เริ่มรันเลย** | `print("Hello"` | `SyntaxError: '(' was never closed` |
| `IndentationError` | ย่อหน้าผิด (ชนิดย่อยของ SyntaxError) | `for i in range(3):` แล้วบรรทัดถัดไปไม่ย่อหน้า | `IndentationError: expected an indented block after 'for' statement on line 1` |
| `NameError` | ใช้ชื่อที่ยังไม่นิยาม | `print(nmae)` | `NameError: name 'nmae' is not defined` |
| `TypeError` | ชนิดข้อมูลไม่เข้ากัน | `"age: " + 20` | `TypeError: can only concatenate str (not "int") to str` |
| `ValueError` | ชนิดถูกแต่ค่าใช้ไม่ได้ | `int("abc")` | `ValueError: invalid literal for int() with base 10: 'abc'` |
| `ZeroDivisionError` | หารด้วยศูนย์ | `10 / 0` | `ZeroDivisionError: division by zero` |
| `IndexError` | ดัชนีเกินลิสต์ | `[1, 2, 3][3]` | `IndexError: list index out of range` |
| `ModuleNotFoundError` | ไม่พบไลบรารี | `import pygame` | `ModuleNotFoundError: No module named 'pygame'` |

> [!note] SyntaxError ต่างจาก error อื่น
> `SyntaxError`/`IndentationError` ถูกตรวจพบ **ก่อน** โปรแกรมเริ่มทำงาน จึงไม่มีบรรทัดไหนรันเลยแม้บรรทัดแรก ๆ จะถูกต้อง ส่วน `NameError`, `TypeError` ฯลฯ เป็น **ข้อผิดพลาดขณะรัน (Runtime Error)** บรรทัดก่อนหน้าทำงานไปแล้ว

### แก้ `TypeError` ด้วยการแปลงชนิดหรือ f-string
```python
age = 20
print("age: " + str(age))     # แปลงเป็น str ก่อนต่อ
print(f"age: {age}")          # หรือใช้ f-string (แนะนำ)
print("age:", age)            # หรือคั่นด้วยจุลภาค
```
```
age: 20
age: 20
age: 20
```
เรื่องนี้จะกลับมาในบทที่ 3 เมื่อใช้ `input()` ซึ่งคืนค่าเป็น `str` เสมอ (`"15" + "5"` ได้ `"155"`)

> [!tip] ขั้นตอนแก้ bug อย่างเป็นระบบ
> 1. อ่านบรรทัดสุดท้ายของ Traceback → รู้ชนิดและข้อความ
> 2. ดูเลขบรรทัดและเครื่องหมาย `^` → รู้ตำแหน่ง
> 3. ตั้งสมมติฐาน (สะกดผิด? ชนิดผิด? ยังไม่รันเซลล์บน?) แล้วแก้ **ทีละอย่าง**
> 4. รันซ้ำ ถ้า error เปลี่ยนชนิด แปลว่าคืบหน้า

> [!question]- ฝึกทำ: โค้ดต่อไปนี้เกิดข้อผิดพลาดชนิดใด และบรรทัดแรกจะพิมพ์ออกมาหรือไม่
> ```python
> print("start")
> total = 10
> print("total = " + total)
> ```
> > [!success]- เฉลย
> > พิมพ์ `start` ก่อน แล้วเกิด `TypeError: can only concatenate str (not "int") to str` ที่บรรทัด 3 เพราะเป็น runtime error บรรทัดก่อนหน้าทำงานไปแล้ว แก้ด้วย `f"total = {total}"`

> [!question]- ฝึกทำ: โค้ดต่อไปนี้เกิดข้อผิดพลาดชนิดใด และบรรทัดแรกจะพิมพ์ออกมาหรือไม่
> ```python
> print("start")
> for i in range(3):
> print(i)
> ```
> > [!success]- เฉลย
> > `IndentationError` — ไม่พิมพ์ `start` เลย เพราะไวยากรณ์ถูกตรวจก่อนรัน ต้องย่อหน้า `print(i)` เข้าไป 4 ช่องว่าง

> [!question]- ฝึกทำ: `print(len("Pygame"), "5" + "5", 5 + 5)` แสดงผลอะไร
> > [!success]- เฉลย

### 5.2 เงื่อนไขและการวนซ้ำ — [EN-001-002 บท 03](https://en-001-002-computer-programming.vercel.app/module/03)
```python

    grade = "A"

    grade = "B"
else:
    grade = "C"
```

- `if/elif/else` ตรวจจากบนลงล่าง เข้าเงื่อนไขแรกที่จริงแล้วหยุด
- `range(1, 6, 2)` → 1, 3, 5 (ไม่รวม 6)
- `while` วนจน `count < 5` เป็นเท็จ: 0 → 2 → 4 → 6 (ตรวจเงื่อนไขก่อนทุกรอบ จึงหยุดที่ 6 ไม่ใช่ 5)

ใช้ในเกม: วงวนเกม `while running:` (บท 5) และ `if self.y + self.radius >= SCREEN_HEIGHT:` ตรวจชนพื้น (บท 5)

![ทายผลก่อนรันส่วนที่ 1: การหาร 7 ด้วย 2 สามแบบ การตรวจ if/elif เมื่อ score = 72 ค่าจาก range(1, 6, 2) และตารางไล่ค่า while จนได้ 6](/infographics/01/basics-review-part1.svg)

**วิธีอ่านภาพ**
1. ① แบ่งของ 7 ชิ้นทีละ 2 ชิ้น: ได้ 3 กลุ่มเต็ม (กรอบเขียว) เหลือเศษ 1 (กรอบแดงประ) จึงได้ `7 // 2 = 3` และ `7 % 2 = 1` ส่วน `7 / 2 = 3.5` เป็นการหารปกติที่ได้ float และ `2 ** 3 = 2 × 2 × 2 = 8`
2. ② `score = 72`: ตรวจ `72 >= 80` เท็จ (แดง) → ตรวจ `72 >= 70` จริง (เขียว) → `grade = "B"` แล้วหยุด ไม่ตรวจ `else` อีก
3. ③ เส้นจำนวน: `range(1, 6, 2)` เริ่มที่ 1 กระโดดทีละ +2 ได้ 1, 3, 5 และไม่รวม 6
4. ④ ตารางไล่ค่า `while count < 5:` ตรวจเงื่อนไขก่อนทุกรอบ: 0 < 5 → 2, 2 < 5 → 4, 4 < 5 → 6, แล้ว 6 < 5 เป็นเท็จจึงออกจากลูป คำตอบในกรอบสีส้มคือ `6`
5. กล่อง ✗/✓: อย่าตอบ 5 ตามเลขในเงื่อนไข (`count` ไม่เคยเท่ากับ 5 เลย) และอย่าเทียบ float ด้วย `==` (`0.1 + 0.2 == 0.3` เป็น `False`) ให้ใช้ `round(0.1 + 0.2, 2)` ได้ `0.3`

### 5.6 คลาสและวัตถุ — [EN-001-002 บท 08](https://en-001-002-computer-programming.vercel.app/module/08)
```python
class Ball:
    def __init__(self, x, vx):      # ตัวสร้าง (Constructor) ทำงานตอน Ball(...)
        self.x = x                  # แอตทริบิวต์ (Attribute) ของวัตถุนี้
        self.vx = vx

    def move(self):                 # เมธอด (Method) รับ self เสมอ
        self.x += self.vx

b = Ball(400, 3)
b.move()
b.move()
print(b.x)
```
```
406
```
`self` คือวัตถุที่กำลังถูกเรียก (`b`) · `b.move()` เท่ากับ `Ball.move(b)` · วัตถุแต่ละตัวมี `x`, `vx` ของตนเอง จึงสร้างลูกบอล 100 ลูกที่เคลื่อนที่อิสระกันได้

**วิธีอ่านภาพ**
1. ① ฟังก์ชัน: `area(3)` ไม่ส่ง `h` จึงใช้ค่าปริยาย 2 ได้ $3 \times 2 = 6$ ส่วน `area(3, 4)` ได้ $3 \times 4 = 12$ กรอบประสีม่วงคือ `x = 10` ภายใน `change()` ซึ่งเป็นคนละตัวกับ `x = 5` ข้างนอกและหายไปเมื่อจบฟังก์ชัน `print(x)` จึงได้ `5`
2. ② ลิสต์: หลัง `append(20)` ได้ 4 ช่อง ดัชนีบน 0–3 และดัชนีลบล่าง −4 ถึง −1 จึงได้ `ns[0] = 5`, `ns[-1] = 20`, `len(ns) = 4`, ค่าเฉลี่ย $50 / 4 = 12.5$ และ `ns[1:3]` คือช่องสีม่วงดัชนี 1–2 = `[10, 15]`
3. ③ พจนานุกรม: `ball["x"] += ball["vx"]` ได้ $400 + 3 = 403$ และ `ball.get("vy", 0)` คืน `0` เพราะไม่มีคีย์ `"vy"` (ถ้าใช้ `ball["vy"]` จะเกิด `KeyError`)
4. ④ คลาส: `Ball(400, 3)` ตั้ง `b.x = 400` → `move()` ครั้งที่ 1 ได้ 403 → ครั้งที่ 2 ได้ 406 คำตอบในกรอบสีส้มคือ `print(b.x)` = `406`
5. กล่อง ✗/✓: ลิสต์ 4 ตัวมีดัชนีแค่ 0–3 การเรียก `ns[4]` จึงเกิด `IndexError` ดัชนีสุดท้ายคือ `len(ns) - 1 = 3` หรือใช้ `ns[-1]`
