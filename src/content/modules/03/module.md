## 1. input() และการแปลงชนิดข้อมูล

### `input()` คืนค่าเป็นสายอักขระเสมอ
```python
n1 = input("Enter n1:")      # ผู้ใช้พิมพ์ 15 → n1 = "15"  (ชนิด str)
n2 = input("Enter n2:")      # ผู้ใช้พิมพ์ 5  → n2 = "5"
print(n1 + n2)               # 155   ← ต่อสายอักขระ ไม่ใช่บวกเลข
print(int(n1) + int(n2))     # 20    ← แปลงเป็น int ก่อนจึงบวกเลข
print(type(n1))              # <class 'str'>
```
ไม่ว่าผู้ใช้จะพิมพ์ตัวเลขหรือตัวอักษร `input()` ส่งกลับมาเป็น `str` เสมอ ตัวดำเนินการ `+` ระหว่าง `str` สองตัวคือ **การต่อสายอักขระ (Concatenation)** จึงได้ `"155"` — โปรแกรมไม่ error แต่ให้คำตอบผิด ซึ่งอันตรายกว่า error เพราะไม่มีใครเตือน

![เปรียบเทียบการบวกสายอักขระ "15" + "5" ได้ "155" กับการแปลงด้วย int ก่อนบวกได้ 20](/infographics/03/input-str-vs-int-part1.svg)

**วิธีอ่านภาพ** (สีแดงคือ `str` สีเขียวคือ `int` สีส้มคือคำตอบ)
1. ① ผู้ใช้กดแป้น 1, 5, Enter → `input()` ส่งกลับสายอักขระ `"15"` ซึ่งเป็นตัวอักษร 2 ช่อง (`'1'` กับ `'5'`) ไม่ใช่ตัวเลขสิบห้า และ `n2` ได้ `"5"` ตรวจด้วย `type(n2)` จะได้ `<class 'str'>`
2. ② กล่องซ้าย (✗ แดง): `n1 + n2` เป็น `str + str` ไพทอนจึง "ต่อ" ตัวอักษร ได้ 3 ช่อง `"155"` กล่องขวา (✓ เขียว): `int("15") = 15` และ `int("5") = 5` จึงเป็น `int + int` ที่ "บวก" ได้ `20`
3. กรอบสีส้มสรุปผลของการป้อน 15 และ 5: `"155"` เทียบกับ `20`
4. กล่อง ✗/✓ เตือนว่า `print` ไม่แสดงเครื่องหมายคำพูด `"155"` กับ `155` จึงดูเหมือนกันบนจอ เมื่อสงสัยให้ใช้ `type()` ตรวจ

### ไพทอนตัดสินใจอย่างไรว่า `+` คือ "บวก" หรือ "ต่อ"
ไพทอนดูชนิดของ **ทั้งสองฝั่ง** ของ `+` ก่อนทำงานทุกครั้ง แล้วเลือกพฤติกรรมตามตารางนี้

| ฝั่งซ้าย | ฝั่งขวา | `+` ทำอะไร | ตัวอย่าง | ผลลัพธ์ |
|---|---|---|---|---|
| `int` | `int` | บวกเลข | `15 + 5` | `20` |
| `str` | `str` | ต่อสายอักขระ | `"15" + "5"` | `"155"` |
| `int` | `float` | บวกเลข (ผลเป็น `float`) | `15 + 0.5` | `15.5` |
| `str` | `int` | ไม่รู้จะทำอะไร | `"10" + 20` | `TypeError` |

ไล่ทีละขั้นของ `print(n1 + n2)` เมื่อผู้ใช้พิมพ์ 15 และ 5
1. `n1 = input("Enter n1:")` → ผู้ใช้กด 1, 5, Enter → `input()` คืนสายอักขระ `"15"` (ตัวอักษร 2 ตัว ไม่ใช่ตัวเลขสิบห้า)
2. `n2 = input("Enter n2:")` → ได้ `"5"`
3. `n1 + n2` → ไพทอนเห็น `str + str` จึงเลือก "ต่อ" → `"15" + "5"` = `"155"`
4. `print("155")` แสดง `155` บนจอ — ดูด้วยตาไม่ออกว่าเป็นสายอักขระ เพราะ `print` ไม่แสดงเครื่องหมายคำพูด จึงต้องใช้ `type(n1)` ตรวจเมื่อสงสัย

### ฟังก์ชันแปลงชนิด (Type Conversion)
| ฟังก์ชัน | ตัวอย่าง | ผลลัพธ์ | หมายเหตุ |
|---|---|---|---|
| `int()` | `int("15")`, `int(3.9)` | `15`, `3` | ตัดทศนิยมทิ้ง ไม่ปัดเศษ (`int(-3.7)` = `-3`) |
| `float()` | `float("2.5")`, `float(4)` | `2.5`, `4.0` | รับได้ทั้งสายอักขระและจำนวนเต็ม |
| `str()` | `str(55)` | `"55"` | บทที่ 4 ใช้ `len(str(item))` หาความกว้างของตัวเลข |

> [!warning] `int("3.5")` เกิด `ValueError`
> `int()` แปลงสายอักขระได้เฉพาะที่เป็นจำนวนเต็มล้วน เช่น `"15"` ถ้าผู้ใช้พิมพ์ `3.5` ต้องใช้ `float("3.5")` ส่วน `int(3.5)` (รับ float ไม่ใช่ str) ทำได้และได้ `3`

### รูปแบบที่ใช้ในคาบ: รับและแปลงในบรรทัดเดียว
```python
n1 = int(input("Enter n1:"))
n2 = int(input("Enter n2:"))
n3 = int(input("Enter n3:"))
total = n1 + n2 + n3
avg = total / 3
print(f"average of {n1} {n2} and {n3} is {avg}.")   # ป้อน 15 5 10 → 10.0
```
ลำดับการทำงานของ `int(input("Enter n1:"))` คือ ข้างในก่อน: `input()` แสดงข้อความ `Enter n1:` รอผู้ใช้พิมพ์ → ได้ `"15"` → `int("15")` ได้ `15` → เก็บใน `n1`

![ตารางชนิดข้อมูลสองฝั่งของเครื่องหมายบวก ลำดับการทำงานของ int(input()) และฟังก์ชันแปลงชนิดพร้อมผลลัพธ์](/infographics/03/input-str-vs-int-part2.svg)

**วิธีอ่านภาพ** (ภาพนี้ต่อจากภาพก่อนหน้า จึงเริ่มที่หมายเลข ③)
1. ③ ตาราง: ไพทอนดูชนิดของ **ทั้งสองฝั่ง** ของ `+` ก่อน — `int + int` บวกได้ `20`, `str + str` ต่อได้ `"155"`, `int + float` บวกได้ `15.5` และ `str + int` ไม่รู้จะทำอะไรจึงเกิด `TypeError` (กล่องสีม่วง)
2. ④ `int(input("Enter n1:"))` ทำงานจากวงเล็บในสุดออกมา: `input()` แสดง `Enter n1:` รอ → ได้ `"15"` → `int("15")` → `15` → เก็บใน `n1` กล่องสีเขียวใต้แถวชิปไล่ตัวอย่างเต็ม: ป้อน 15, 5, 10 ได้ $15 + 5 + 10 = 30$ และ $30 / 3 = 10.0$
3. ⑤ ฟังก์ชันแปลงชนิด: `int(3.9) = 3` และ `int(-3.7) = -3` คือการตัดทศนิยมทิ้ง (ไม่ปัดเศษ) `str(55)` ได้สายอักขระ `"55"` และ `"7" * 2` ได้ `"77"` (ทำซ้ำ ไม่ใช่ 14)
4. กล่อง ✗/✓: ผู้ใช้พิมพ์ทศนิยม `3.5` แล้วใช้ `int("3.5")` จะเกิด `ValueError` ต้องใช้ `float("3.5")` ได้ `3.5`

### การคูณสายอักขระ
`"7" * 2` ไม่ใช่ 14 แต่เป็น `"77"` (ทำซ้ำสายอักขระ 2 ครั้ง) หลักเดียวกับ `"#" * 5` ที่ได้ `"#####"` ซึ่งจะใช้ในหัวข้อที่ 5

## 2. ลิสต์และเมท็อดพื้นฐาน

### การสร้างและเข้าถึงด้วยดัชนี
```python
ns = [5, 10, 15, 20, 30]
print(ns[0])      # 5   ตัวแรก (ดัชนีเริ่มที่ 0)
print(ns[-1])     # 30  ตัวสุดท้าย (ดัชนีลบนับจากท้าย)
print(len(ns))    # 5   จำนวนสมาชิก
ns[1] = 7         # แก้ไขค่าได้ (Mutable) → [5, 7, 15, 20, 30]
```

| ดัชนี | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| ค่า | 5 | 10 | 15 | 20 | 30 |
| ดัชนีลบ | -5 | -4 | -3 | -2 | -1 |

ลิสต์ที่มี 5 สมาชิกมีดัชนีสูงสุดคือ `4` (= `len(ns) - 1`) การเรียก `ns[5]` จะเกิด `IndexError: list index out of range`

> [!note] ลิสต์ vs ทูเพิล
> ทูเพิล `(1, 2, 3)` จากบทที่ 2 **แก้ไขไม่ได้** (`t[0] = 9` → `TypeError`) ส่วนลิสต์ `[1, 2, 3]` แก้ไข เพิ่ม ลบ ได้ จึงเหมาะกับข้อมูลที่เปลี่ยนตลอดเวลา เช่น รายการลูกบอลหรือกระสุนในเกม

### เมท็อดที่ใช้ในคาบ (ไล่ค่าจาก `ns = [5, 10, 15, 20, 30]`)
```python
ns = [5, 10, 15, 20, 30]
ns.append(40)     # เพิ่มท้าย        → [5, 10, 15, 20, 30, 40]
ns.insert(1, 7)   # แทรกที่ตำแหน่ง 1  → [5, 7, 10, 15, 20, 30, 40]
ns.pop()          # ลบตัวสุดท้าย คืน 40 → [5, 7, 10, 15, 20, 30]
ns.pop(1)         # ลบตำแหน่ง 1 คืน 7  → [5, 10, 15, 20, 30]
ns[1] = 5         # แก้ค่า              → [5, 5, 15, 20, 30]
ns.remove(5)      # ลบค่า 5 ตัวแรกที่พบ → [5, 15, 20, 30]
```

![ลิสต์ ns ก่อนและหลังคำสั่ง append insert pop และ pop(1) พร้อมดัชนีของแต่ละช่องและช่องที่ถูกเลื่อน](/infographics/03/list-methods-part1.svg)

**วิธีอ่านภาพ** (แต่ละแถวคือสภาพของ `ns` **หลัง** ทำคำสั่งทางซ้าย ตัวเลขเหนือช่องคือดัชนี)
1. แถว "เริ่มต้น" คือ `[5, 10, 15, 20, 30]` ยาว 5
2. ① `append(40)` เพิ่มช่องสีเขียวที่ท้าย ไม่มีช่องใดเลื่อน ความยาวเป็น 6
3. ② `insert(1, 7)` เปิดที่ดัชนี 1 ใส่ `7` (สีเขียว) ช่อง `10, 15, 20, 30, 40` จึงเลื่อนจากดัชนี 1–5 ไปเป็น 2–6 (สีน้ำเงิน ดัชนีเปลี่ยน)
4. ③ `pop()` นำตัวท้ายออกและคืนค่า `40` (กล่องแดงประ) ไม่มีช่องใดเลื่อน
5. ④ `pop(1)` นำ `7` ที่ดัชนี 1 ออกและคืนค่า ช่องที่ตามมาเลื่อนกลับ 1 ช่องเพื่อปิดช่องว่าง
6. กรอบสีส้ม: หลัง 4 คำสั่ง ลิสต์กลับมาเป็น `[5, 10, 15, 20, 30]` โดย `pop` คืน 40 และ 7 — กล่อง ✗/✓ เตือนว่าหลัง `insert(1, 7)` ค่า `ns[2]` เปลี่ยนจาก 15 เป็น 10

### ทำไมดัชนีจึงเลื่อน
ลิสต์ในไพทอนเก็บสมาชิกเรียงติดกันตามดัชนี 0, 1, 2, … โดยไม่มีช่องว่างตรงกลาง ดังนั้น
1. `ns.insert(1, 7)` ต้อง "เปิดที่" ที่ดัชนี 1 → สมาชิกเดิมที่ดัชนี 1–5 (`10, 15, 20, 30, 40`) ขยับไปเป็นดัชนี 2–6 → ใส่ `7` ลงดัชนี 1 → ความยาวเพิ่มจาก 6 เป็น 7
2. `ns.pop(1)` นำ `7` ออก → สมาชิกที่ดัชนี 2–6 ขยับกลับมาเป็น 1–5 เพื่อปิดช่องว่าง → ความยาวลดเหลือ 5
3. ผลที่ตามมา: หลัง `insert`/`pop` กลางลิสต์ ค่า `ns[2]` ไม่ใช่ค่าเดิมอีกต่อไป (ก่อน insert `ns[2]` = 15 หลัง insert `ns[2]` = 10) — นี่คือรากของบั๊ก "ลบสมาชิกขณะวนลิสต์" ในกล่องเตือนด้านล่าง

| เมท็อด/ฟังก์ชัน | ทำอะไร | คืนค่า | เปลี่ยนลิสต์เดิมหรือไม่ |
|---|---|---|---|
| `ns.append(x)` | เพิ่ม x ต่อท้าย | `None` | เปลี่ยน |
| `ns.insert(i, x)` | แทรก x ที่ดัชนี i สมาชิกเดิมเลื่อนขวา | `None` | เปลี่ยน |
| `ns.pop()` | ลบตัวสุดท้าย | สมาชิกที่ลบ | เปลี่ยน |
| `ns.pop(i)` | ลบตัวที่ดัชนี i | สมาชิกที่ลบ | เปลี่ยน |
| `ns.remove(x)` | ลบ **ค่า** x ตัวแรกที่พบ (ไม่ใช่ดัชนี) | `None` | เปลี่ยน |
| `ns.copy()` หรือ `ns[:]` | สร้างสำเนา | ลิสต์ใหม่ | ไม่เปลี่ยน |
| `sum(ns)`, `len(ns)`, `max(ns)`, `min(ns)` | ผลรวม จำนวน มากสุด น้อยสุด | ตัวเลข | ไม่เปลี่ยน |
| `x in ns` | ตรวจว่ามีค่า x หรือไม่ | `True`/`False` | ไม่เปลี่ยน |

> [!warning] `pop(i)` กับ `remove(x)` ต่างกัน
> `ns.pop(1)` ลบสมาชิก **ตำแหน่ง** 1 ส่วน `ns.remove(1)` ลบสมาชิกที่มี **ค่า** 1 ถ้าไม่มีค่านั้นจะ `ValueError` และ `append()` คืน `None` ดังนั้น `ns = ns.append(40)` จะทำให้ `ns` กลายเป็น `None`

### ลิสต์สองชื่ออ้างถึงลิสต์เดียวกัน
```python
a = [1, 2, 3]
b = a             # ไม่ได้สำเนา — b คือชื่อที่สองของลิสต์เดียวกัน
b.append(4)
print(a)          # [1, 2, 3, 4]  ← a เปลี่ยนด้วย
c = a.copy()      # สำเนาจริง
c.append(5)
print(a, c)       # [1, 2, 3, 4] [1, 2, 3, 4, 5]
```
นี่คือเหตุผลที่บทที่ 2 บอกว่าส่งตัวเลขเข้าฟังก์ชันแล้วแก้ค่าภายใน ตัวแปรภายนอกไม่เปลี่ยน แต่ส่ง **ลิสต์** แล้ว `append()` ลิสต์ภายนอกจะเปลี่ยนด้วย (บทที่ 4 ใช้หลักนี้ทำสแตก `spush(stack, x)`)

![การแก้ค่า ns[1] = 5 การลบค่าด้วย remove เทียบ pop(i) กับ remove(x) และชื่อ a กับ b ที่ชี้ไปลิสต์เดียวกันเทียบกับ copy](/infographics/03/list-methods-part2.svg)

**วิธีอ่านภาพ** (ต่อจากภาพก่อนหน้า เริ่มที่ `ns = [5, 10, 15, 20, 30]` และหมายเลข ⑤)
1. ⑤ `ns[1] = 5` แทนค่าในช่องเดิม (ช่องสีส้ม 10 → 5) ไม่มีช่องใดเลื่อน ได้ `[5, 5, 15, 20, 30]`
2. ⑥ `ns.remove(5)` ลบ **ค่า** 5 ตัวแรกที่พบ คือดัชนี 0 (กล่องแดงประ) ช่องที่เหลือเลื่อนดัชนีลง ได้ `[5, 15, 20, 30]` — 5 อีกตัวยังอยู่
3. ⑦ จาก `[5, 15, 20, 30]`: `pop(1)` ลบตาม **ตำแหน่ง** 1 คืน `15` เหลือ `[5, 20, 30]` ส่วน `remove(1)` ลบตาม **ค่า** 1 ซึ่งไม่มีในลิสต์ จึงเกิด `ValueError`
4. ⑧ ป้ายชื่อสีม่วง `a` และ `b` ชี้ไปลิสต์ก้อนเดียวกัน `b.append(4)` จึงทำให้ `print(a)` ได้ `[1, 2, 3, 4]` ส่วน `c = a.copy()` ชี้ไปลิสต์ก้อนใหม่ `c.append(5)` จึงไม่กระทบ `a`
5. กล่อง ✗/✓: `ns = ns.append(40)` ทำให้ `ns` เป็น `None` เพราะ `append()` คืน `None` ให้เรียก `ns.append(40)` เฉย ๆ ซึ่งแก้ลิสต์เดิมเป็น `[5, 15, 20, 30, 40]`

### ลิสต์ของวัตถุ (ภาพรวมสู่บทที่ 5)
```python
balls = []
for i in range(N):
    balls.append(Ball(...))   # สร้างลูกบอล N ลูกเก็บในลิสต์
for ball in balls:
    ball.move()               # สั่งทุกลูกเคลื่อนที่ในลูปเดียว
```
ในเกมยิงยานอวกาศ กระสุน ศัตรู และลูกบอลทุกลูกถูกเก็บในลิสต์แบบนี้ ยิงกระสุนคือ `bullets.append(...)` และกระสุนหลุดจอคือ `bullets.remove(...)`

> [!danger] อย่าลบสมาชิกจากลิสต์ที่กำลังวนอยู่
> ```python
> xs = [1, 2, 2, 3]
> for x in xs:
>     if x == 2:
>         xs.remove(x)
> print(xs)          # [1, 2, 3]  ← ลบไม่หมด เพราะเมื่อลบตัวที่ดัชนี 1 ตัวถัดไปเลื่อนมาแทนแล้วถูกข้าม
> ```
> วิธีที่ถูก: วนบนสำเนา `for x in xs[:]:` จะได้ `[1, 3]` (บทที่ 8 ใช้วิธีนี้ลบกระสุนที่ชนศัตรู)

> [!question]- ฝึกทำ: จงบอกค่าของ `ns` หลังแต่ละคำสั่ง เริ่มจาก `ns = [2, 4, 6]`: `ns.insert(0, 1)` → `ns.append(8)` → `x = ns.pop(2)` → `ns[0] = 9`
> > [!success]- เฉลย
> > `[1, 2, 4, 6]` → `[1, 2, 4, 6, 8]` → `[1, 2, 6, 8]` (x = 4) → `[9, 2, 6, 8]`

> [!question]- ฝึกทำ: จงบอกผลลัพธ์
> ```python

> xs.append(a)
> print(xs)
> ```
> > [!success]- เฉลย
> > `[6, 7, 9, 3]` — insert ได้ `[3, 6, 7, 9]`, pop(0) เอา 3 ออกได้ `[6, 7, 9]`, append(3) ต่อท้าย

> [!question]- ฝึกทำ: `a = [1, 2, 3]; b = a; b.append(4); print(a)` แสดงผลอะไร
> > [!success]- เฉลย
> > `[1, 2, 3, 4]` เพราะ `b = a` ไม่ได้สร้างสำเนา ทั้งสองชื่ออ้างถึงลิสต์เดียวกัน (ต้องใช้ `a.copy()`)

## 3. ค่าเฉลี่ย ผลรวม และการวนซ้ำบนลิสต์

### จากสูตรสู่โค้ด
ค่าเฉลี่ยเลขคณิต (Arithmetic Mean) ของข้อมูล $x_1, x_2, \dots, x_n$ คือ
$$\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i$$

| วิธี | โค้ด | ข้อจำกัด |
|---|---|---|
| ตัวแปรแยก (บทที่ 2) | `avg = (n1 + n2 + n3) / 3` | ใช้ได้กับ 3 ค่าเท่านั้น |
| ลิสต์ + ฟังก์ชันในตัว (บทนี้) | `avg = sum(ns) / len(ns)` | กี่ค่าก็ได้ |
| วนซ้ำเอง | `total = 0` → `for x in ns: total += x` → `total / len(ns)` | กี่ค่าก็ได้ เห็นกลไก |
| แต่ละแถวของตาราง (บทที่ 4) | `[sum(row) / len(row) for row in scores]` | ลิสต์ซ้อนลิสต์ |

```python
ns = [5, 10, 15, 20, 30]
avg = sum(ns) / len(ns)     # 80 / 5 = 16.0
print(sum(ns), len(ns), max(ns), min(ns), avg)   # 80 5 30 5 16.0
```

### ไล่ค่าทีละรอบของการวนซ้ำ
```python
total = 0
for x in ns:          # วนทีละสมาชิก ไม่ต้องใช้ดัชนี
    total += x
print(total / len(ns))
```

| รอบ | `x` | `total` ก่อน | `total` หลัง |
|---|---|---|---|
| 1 | 5 | 0 | 5 |
| 2 | 10 | 5 | 15 |
| 3 | 15 | 15 | 30 |
| 4 | 20 | 30 | 50 |
| 5 | 30 | 50 | 80 |

จบลูป `total = 80` → `80 / 5 = 16.0` ตรงกับ `sum(ns)`

![การวนซ้ำ for x in ns สะสม total จาก 0 เป็น 80 ทีละรอบ แถบสะสม และการหาร 80 ด้วย 5 ได้ 16.0](/infographics/03/mean-loop-part1.svg)

**วิธีอ่านภาพ** (สีน้ำเงินคือ `x` ของแต่ละรอบ สีเขียวคือ `total` สะสม)
1. ① `for x in ns:` หยิบสมาชิกทีละช่องจากซ้ายไปขวา รอบ 1–5 ได้ `x` = 5, 10, 15, 20, 30 โดยไม่ต้องใช้ดัชนี
2. ② ตารางไล่ค่า: แต่ละแถว "total หลัง = total ก่อน + x" เช่น รอบ 4: $30 + 20 = 50$ และ `total` หลังของแถวหนึ่งกลายเป็น `total` ก่อนของแถวถัดไป
3. แถบสะสมด้านล่างตาราง (1 หน่วย = 8 px) แสดงภาพเดียวกัน: ต่อชิ้น +5, +10, +15, +20, +30 จนปลายแถบอยู่ที่ 5, 15, 30, 50, 80
4. ③ จบลูปแล้วหารด้วยจำนวนสมาชิก: $80 / 5 = 16.0$ (กรอบสีส้ม) และตรวจกับ `sum(ns) = 80`, `len(ns) = 5` ได้ตรงกัน
5. กล่อง ✗/✓: `sum([1, 2, 3, 4]) // 4` ได้ `2` (เศษหาย) แต่ `/` ได้ `2.5` — ลิสต์ `ns` นี้หารลงตัวจึงได้ 16 ทั้งสองแบบ ทำให้มองไม่เห็นบั๊ก

> [!warning] `/` กับ `//` ในการหาค่าเฉลี่ย
> `sum([1, 2, 3, 4]) / 4` ได้ `2.5` แต่ `sum([1, 2, 3, 4]) // 4` ได้ `2` เศษหายไป จึง **ห้ามใช้ `//` หาค่าเฉลี่ย** (ใน `[5, 10, 15, 20, 30]` บังเอิญหารลงตัวได้ 16 ทั้งสองแบบ จึงอาจไม่ทันสังเกตบั๊ก)

### `for x in ns` กับ `for i in range(len(ns))`
| รูปแบบ | ได้อะไรในแต่ละรอบ | ใช้เมื่อ |
|---|---|---|
| `for x in ns:` | ค่าสมาชิก `x` | ต้องการแค่ค่า (หาผลรวม นับ) |
| `for i in range(len(ns)):` | ดัชนี `i` แล้วเข้าถึงด้วย `ns[i]` | ต้องการตำแหน่ง หรือต้องแก้ค่า `ns[i] = ...` |

### หาค่ามากสุดด้วยมือ (กลไกของ `max()`)
```python
ns = [12, 7, 20, 3, 9]
biggest = ns[0]           # เริ่มจากตัวแรก
for x in ns:
    if x > biggest:
        biggest = x       # พบตัวใหญ่กว่าก็เปลี่ยน
print(biggest)            # 20
```
ไล่ค่า: `biggest` = 12 → (7 ไม่เปลี่ยน) → 20 → (3, 9 ไม่เปลี่ยน) → 20 — บทที่ 8 ใช้แนวคิด "เริ่มจากตัวแรกแล้วเทียบทีละตัว" หาศัตรูที่อยู่ใกล้ยานที่สุด

![ตารางไล่ค่าการหาค่ามากสุดของ 12, 7, 20, 3, 9 ได้ 20 และแผนภูมิแท่งเทียบกับค่าเฉลี่ย 10.2 ที่มี 2 ตัวมากกว่า](/infographics/03/mean-loop-part2.svg)

**วิธีอ่านภาพ**
1. ① เริ่มที่ `biggest = ns[0] = 12` กล่องสีม่วงอธิบายว่าทำไมไม่เริ่มที่ 0: ถ้าข้อมูลติดลบทั้งหมด เช่น `[-3, -7]` จะได้คำตอบ 0 ซึ่งไม่อยู่ในลิสต์
2. ② ตารางไล่ค่า: ทุกรอบถาม `x > biggest ?` มีเพียงรอบ 3 (`20 > 12` จริง สีเขียว) ที่เปลี่ยน `biggest` เป็น 20 รอบอื่นเท็จ (สีเทา) ค่าจึงคงเดิม คำตอบในกรอบสีส้มคือ `20` เท่ากับ `max(ns)`
3. ③ แผนภูมิแท่ง: ค่าเฉลี่ย $51 / 5 = 10.2$ คือเส้นประสีส้ม แท่งสีเขียวที่สูงกว่าเส้นคือ 12 และ 20 จึงตอบว่า **2 ตัว** (โจทย์เดียวกับฝึกทำข้อที่ 2 ด้านล่าง)
4. กล่อง ✗/✓: เริ่ม `biggest = 0` กับ `[-3, -7]` ได้ `0` (ผิด) ส่วนเริ่ม `biggest = ns[0]` ได้ `-3` ถูกต้องเสมอ

## 4. การสุ่ม การแจกแจง และแผนภูมิด้วย Matplotlib/pandas

### สุ่มค่าเดียวด้วยมอดูล `random`
```python
import random
random.uniform(-5, 5)      # จำนวนจริงสุ่มในช่วง [-5, 5]  → ความเร็วเริ่มต้นของลูกบอล (บทที่ 5)
random.randint(0, 255)     # จำนวนเต็มสุ่ม 0–255 รวมปลายทั้งสองข้าง → สุ่มสี RGB
random.seed(2)             # ตั้งเมล็ดสุ่ม ให้ลำดับสุ่มเหมือนเดิมทุกครั้งที่รัน
```

> [!note] `randint(a, b)` รวม b แต่ `range(a, b)` ไม่รวม b
> `random.randint(1, 6)` ได้ 1–6 (ทอยลูกเต๋า) ต่างจาก `range(1, 6)` ที่ได้ 1–5 เป็นจุดที่สับสนบ่อย

### การแจกแจงแบบสม่ำเสมอ (Uniform Distribution)
ทุกค่าในช่วง $[a, b]$ มีโอกาสเกิดเท่ากัน ค่าเฉลี่ยทางทฤษฎี $= \dfrac{a+b}{2}$
```python
import numpy as np
xs = np.random.uniform(low=0, high=100, size=100)   # 100 ค่าในช่วง 0–100
np.random.rand(100) * 100                           # แบบเดียวกัน: สุ่ม 0–1 แล้วขยายเป็น 0–100
```
`random.uniform(-5, 5)` มีค่าเฉลี่ย 0 ลูกบอลจึงไม่มีแนวโน้มวิ่งไปทิศใดทิศหนึ่ง และ `uniform(0, 100)` มีค่าเฉลี่ย 50

### การแจกแจงแบบปกติ (Normal Distribution)
ข้อมูลกระจุกรอบค่าเฉลี่ย $\mu$ (`loc`) โดยมีส่วนเบี่ยงเบนมาตรฐาน $\sigma$ (`scale`) เป็นตัวบอกความกว้างของการกระจาย
```python
ys = np.random.normal(loc=50, scale=15, size=100)   # μ = 50, σ = 15
```

> [!info] กฎ 68–95–99.7
> | ช่วง | สัดส่วนข้อมูลโดยประมาณ | เมื่อ `loc=50, scale=15` |
> |---|---|---|
> | $\mu \pm \sigma$ | 68% | 35–65 |
> | $\mu \pm 2\sigma$ | 95% | 20–80 |
> | $\mu \pm 3\sigma$ | 99.7% | 5–95 |
>
> จาก 100 จุด จึงคาดว่าประมาณ 95 จุดอยู่ในช่วง 20–80 และมีเพียง 2–3 จุดที่หลุดช่วง 5–95 (รันจริงด้วย `np.random.seed(2)` ได้ 93 จุดใน 20–80 และ 98 จุดใน 5–95 ใกล้เคียงทฤษฎี)

| | Uniform | Normal |
|---|---|---|
| รูปร่างบน scatter plot | จุดกระจายทั่วพื้นที่สม่ำเสมอ | จุดกระจุกกลาง บางลงเมื่อห่างออก |
| ค่าต่ำสุด/สูงสุด | ไม่เกินช่วง `low`–`high` แน่นอน | **ไม่มีขอบเขต** อาจเกิน 100 หรือติดลบได้ (ค่าสูงสุดในการรันตัวอย่างคือ 111.63) |
| พารามิเตอร์ | `low`, `high` | `loc` (μ), `scale` (σ) |

![กราฟความหนาแน่นของการแจกแจงแบบสม่ำเสมอ 0–100 เทียบกับแบบปกติ μ = 50 σ = 15 พร้อมแถบ 68-95-99.7 และจุดข้อมูลจริง 100 ค่า](/infographics/03/uniform-vs-normal-part1.svg)

**วิธีอ่านภาพ** (วาดตามสเกลจริงบนแกนเดียวกัน −10 ถึง 120 จุดใต้กราฟคือข้อมูลจริง 100 ค่าจาก `np.random.seed(2)` โดยสุ่ม uniform ก่อนแล้วจึงสุ่ม normal)
1. ① แบบสม่ำเสมอ (สีเขียว): กราฟเป็นสี่เหลี่ยมสูง $1/100 = 0.01$ เท่ากันทุกจุด และหยุดทันทีที่ 0 กับ 100 จุดข้อมูลจึงกระจายเต็มช่วงและไม่มีจุดนอกช่วงเลย ค่าเฉลี่ยทฤษฎี $(0 + 100)/2 = 50$
2. ② แบบปกติ (สีส้ม): ระฆังสูงสุด $\frac{1}{15\sqrt{2\pi}} \approx 0.0266$ ที่ μ = 50 แถบเข้มถึงอ่อนคือ $\mu \pm \sigma$ (35–65), $\mu \pm 2\sigma$ (20–80), $\mu \pm 3\sigma$ (5–95) จุดข้อมูลกระจุกกลางและบางลงที่ขอบ
3. จุดสีแดงคือค่าสูงสุด 111.63 ที่หลุดเกิน 100 — แบบปกติไม่มีขอบเขต
4. ③ ตารางเปรียบเทียบรูปบน scatter ขอบเขตค่า และพารามิเตอร์ของทั้งสองแบบ กล่อง ✗/✓ เตือนว่าการตั้ง `loc = 50` ไม่ได้ทำให้ค่าอยู่ใน 0–100 ถ้าต้องการค่าไม่หลุดช่วงให้ใช้ uniform หรือตรวจค่าเอง

### อ่านกฎ 68–95–99.7 เป็นจำนวนจุด
กฎนี้บอก **สัดส่วน** จึงแปลงเป็นจำนวนจุดได้โดยคูณกับจำนวนข้อมูลทั้งหมด ทำทีละขั้นกับ `normal(loc=50, scale=15, size=100)`
1. หาขอบช่วง: $\mu \pm k\sigma$ → $k=1$: $50 \pm 15$ = 35–65, $k=2$: $50 \pm 30$ = 20–80, $k=3$: $50 \pm 45$ = 5–95
2. คูณสัดส่วนกับ `size`: $0.6827 \times 100 \approx 68$, $0.9545 \times 100 \approx 95$, $0.9973 \times 100 \approx 99.7$ จุด
3. เทียบกับการรันจริง (seed 2): ได้ 66, 93 และ 98 จุดตามลำดับ — ใกล้เคียงแต่ไม่เท่าทฤษฎีเป๊ะ เพราะ 100 จุดเป็นตัวอย่างขนาดเล็ก ถ้าเพิ่ม `size` เป็น 100,000 สัดส่วนจะเข้าใกล้ 68.27%, 95.45%, 99.73% มากขึ้น
4. นอกช่วง $\mu \pm 2\sigma$ มีประมาณ $100\% - 95\% = 5\%$ แบ่งเป็นหางซ้ายและขวาข้างละประมาณ 2.5%

![กฎ 68-95-99.7 แปลงเป็นจำนวนจุดจาก 100 จุด เทียบค่าทฤษฎี 68.3 95.5 99.7 กับผลรันจริง 66 93 98](/infographics/03/uniform-vs-normal-part2.svg)

**วิธีอ่านภาพ** (สีน้ำเงินคือค่าทฤษฎี สีส้มคือผลรันจริงด้วย seed 2)
1. ① หาขอบช่วง $50 \pm 15k$: $k = 1$ ได้ 35–65, $k = 2$ ได้ 20–80, $k = 3$ ได้ 5–95 แถบเล็กด้านขวาวาดช่วงเหล่านี้บนสเกล 0–100
2. ② คูณสัดส่วนกับ `size = 100`: $0.6827 \times 100 \approx 68.3$, $0.9545 \times 100 \approx 95.5$, $0.9973 \times 100 \approx 99.7$ จุด แล้วเทียบแท่งน้ำเงิน (ทฤษฎี) กับแท่งส้ม (รันจริง 66, 93, 98) — ใกล้เคียงแต่ไม่เท่าเป๊ะเพราะ 100 จุดเป็นตัวอย่างเล็ก
3. ③ นอกช่วง 20–80 ทฤษฎีมีประมาณ 5% คือหางละ 2.5 จุด ส่วนรันจริงได้หางซ้าย (< 20) 3 จุด และหางขวา (> 80) 4 จุด รวม $7 = 100 - 93$
4. กรอบสีเขียวคือคำตอบที่ใช้ตอบข้อสอบ: คาดว่าอยู่ในช่วง 20–80 ประมาณ **95 จุด** — กล่อง ✗/✓ ย้ำว่ากฎนี้เป็นค่าโดยประมาณ ให้คาดด้วย "สัดส่วน × size" เช่น $0.68 \times 1000 \approx 680$ จุด

> [!tip] ทำไมกราฟแบบสม่ำเสมอจึง "เตี้ย" กว่า
> พื้นที่ใต้กราฟความหนาแน่นทุกแบบต้องเท่ากับ 1 (ความน่าจะเป็นรวม 100%) แบบสม่ำเสมอแผ่ความน่าจะเป็นออกเท่า ๆ กันบนความกว้าง 100 หน่วย จึงสูงได้แค่ $1/100$ ส่วนแบบปกติรวมความน่าจะเป็นไว้ใกล้ μ จึงสูงกว่าตรงกลาง แต่ต้องเตี้ยลงที่หางเพื่อให้พื้นที่รวมยังเป็น 1

## 5. สามเหลี่ยมชิดขวาด้วย linespace และ Top-Down Design

### `linespace(s, n)`: ช่องว่าง s ตัวตามด้วย # n ตัว
```python
def linespace(s, n):
    for i in range(s):
        print(" ", end="")      # ช่องว่าง s ตัว
    for i in range(n):
        print("#", end="")      # # n ตัว
    print()                     # ขึ้นบรรทัดใหม่

linespace(2, 3)                 # "  ###"
```
ฟังก์ชันนี้ต่อยอด `line(n)` จากบทที่ 2 ด้วยพารามิเตอร์ `s` เพิ่มเข้ามา ทำให้ "เลื่อน" รูปไปทางขวาได้

### สามเหลี่ยมชิดขวา
```python
def triangle(n):
    for i in range(n):
        linespace(n - i - 1, i + 1)

triangle(4)
```
```
   #
  ##
 ###
####
```

| แถว `i` | ช่องว่าง `n - i - 1` | `#` จำนวน `i + 1` | ความยาวรวม |
|---|---|---|---|
| 0 | 3 | 1 | 4 |
| 1 | 2 | 2 | 4 |
| 2 | 1 | 3 | 4 |
| 3 | 0 | 4 | 4 |

ทุกแถวยาว $(n - i - 1) + (i + 1) = n$ เสมอ รูปจึงชิดขวาพอดี — ถ้าช่องว่างกับ `#` รวมกันไม่เท่ากับ `n` รูปจะเบี้ยว

![ตารางช่องของ triangle(4) แสดงช่องว่างและเครื่องหมาย # ในแต่ละแถว เทียบกับเวอร์ชันที่ลืมลบ 1](/infographics/03/right-triangle-grid.svg)

**วิธีอ่านภาพ** (ช่องเทาคือช่องว่าง ช่องน้ำเงินคือ `#` และ 1 ช่อง = 1 ตัวอักษร)
1. ① โค้ด: `triangle(n)` เรียก `linespace(n - i - 1, i + 1)` แถวละครั้ง และ `linespace(s, n)` พิมพ์ช่องว่าง s ตัวตามด้วย `#` n ตัว เช่น `linespace(2, 3)` ได้ `"  ###"`
2. ② ตาราง 4 × 4 ไล่ทีละแถว: `i = 0` → `linespace(3, 1)` ช่องว่าง 3 + `#` 1 = 4 ช่อง, `i = 1` → 2 + 2, `i = 2` → 1 + 3, `i = 3` → 0 + 4 ทุกแถวรวม 4 ช่อง เส้นประสีส้มจึงเป็นขอบขวาที่ตรง
3. ③ ตารางหาสูตร: `#` = `i + 1` (1, 2, 3, 4) และช่องว่าง = `n − i − 1` (3, 2, 1, 0) รวมกันได้ $(n - i - 1) + (i + 1) = n$ ทุกแถว
4. ④ นับทั้งรูป: `#` รวม $1 + 2 + 3 + 4 = \frac{n(n+1)}{2} = 10$ ตัว และช่องว่างรวม $3 + 2 + 1 + 0 = \frac{n(n-1)}{2} = 6$ ช่อง
5. กล่องล่างสุดเทียบ 3 สูตร: ✓ `linespace(n-i-1, i+1)` ยาว 4 ทุกแถวชิดขวา · ✗ `linespace(n-i, i+1)` ยาว 5 ทั้งก้อนเลื่อนขวา 1 ช่อง (ข้ามเส้นประ) · ✗ `linespace(i, i+1)` ได้รูปเฉียงเป็นขั้นบันได

### หาสูตร `n - i - 1` และ `i + 1` ด้วยตัวเอง
เมื่อเจอโจทย์รูปแบบ ให้เขียนตารางจำนวนช่องว่างและ `#` ของแต่ละแถวก่อน แล้วหาความสัมพันธ์กับ `i`
1. นับจากรูปเป้าหมาย `n = 4`: จำนวน `#` ของแถว `i = 0, 1, 2, 3` คือ 1, 2, 3, 4 → เพิ่มทีละ 1 เริ่มที่ 1 → `i + 1`
2. ความยาวทุกแถวต้องเท่ากับ `n` (ขอบขวาตรง) → ช่องว่าง = `n - (i + 1)` = `n - i - 1` → 3, 2, 1, 0
3. ตรวจแถวแรกและแถวสุดท้าย: `i = 0` ได้ `linespace(3, 1)` = `"   #"` และ `i = n - 1 = 3` ได้ `linespace(0, 4)` = `"####"` ถูกต้องทั้งสองปลาย
4. ลองกับ `n` อื่นทันที เช่น `n = 5` แถวแรกต้องได้ `linespace(4, 1)` — ถ้าสูตรใช้ได้กับทุก `n` แปลว่าไม่ได้ "จำค่า" แต่เข้าใจโครงสร้างจริง

> [!warning] ลืม `- 1` ใน `n - i - 1`
> ถ้าเขียน `linespace(n - i, i + 1)` ทุกแถวจะยาว $n + 1$ รูปยังชิดขวาแต่เลื่อนไปทางขวา 1 ช่องทั้งก้อน และถ้าเขียน `linespace(i, i + 1)` จะได้รูปเฉียงเหมือนขั้นบันได ไม่ใช่สามเหลี่ยม

### จำนวน `#` ทั้งหมด
`triangle(n)` พิมพ์ `#` รวม $1 + 2 + \dots + n = \dfrac{n(n+1)}{2}$ ตัว เท่ากับสามเหลี่ยมชิดซ้ายของบทที่ 2 (`triangle(4)` → 10 ตัว, `triangle(10)` → 55 ตัว) ส่วนช่องว่างมี $\dfrac{n(n-1)}{2}$ ตัว (`triangle(4)` → 6 ช่อง)

### Top-Down Design: ประกอบรูปจากฟังก์ชันพื้นฐานเดียว
| ฟังก์ชัน | หน้าที่ | เรียกใช้ |
|---|---|---|
| `linespace(s, n)` | ช่องว่าง s ตัว + # n ตัว | — (ฟังก์ชันพื้นฐาน) |
| `triangle(n)` ชิดขวา | สามเหลี่ยมชิดขวา | `linespace(n - i - 1, i + 1)` |
| `pyramid(n)` | พีระมิดกึ่งกลาง | `linespace(n - i - 1, 2*i + 1)` |
| `tree()` (บทที่ 2) | ต้นไม้ | `top_leaf()`, `bottom_leaf()`, `clone()` → `linespace()` |

ข้อดีของการมี `linespace` เป็นฐานเดียว: อยากเปลี่ยน `#` เป็น `*` ทุกรูป แก้ที่เดียว ทดสอบ `linespace(2, 3)` ให้ถูกก่อนแล้วรูปใหญ่จะถูกตาม — ดูเพิ่มที่ [EN-001-002 บท 04 ฟังก์ชัน](https://en-001-002-computer-programming.vercel.app/module/04)
