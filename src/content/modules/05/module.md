> บทนี้เริ่มสร้างเกมด้วยไลบรารี **Pygame** ตั้งแต่ **วงวนเกม (Game Loop)** ที่ทำซ้ำทุกเฟรม ระบบพิกัดจอภาพที่แกน y ชี้ลง การวาดรูปทรงเรขาคณิต ไปจนถึงการจำลอง **ลูกบอลเด้ง (Bouncing Ball)** ภายใต้ความโน้มถ่วง (Gravity) การหน่วง (Damping) และการสะท้อนเมื่อชนขอบ โดยไล่ค่าตำแหน่งและความเร็วทีละเฟรมด้วย **วิธีของออยเลอร์ (Euler Method)** จากนั้นพัฒนาโค้ดจากการเก็บข้อมูลด้วย **พจนานุกรม (Dictionary)** ไปเป็น **คลาส (Class)** เพื่อสร้างลูกบอลนับร้อยลูก และสร้างตัวละครด้วย **สไปรต์ (Sprite)** — ทุกเรื่องในบทนี้คือโครงของเกมยิงยานอวกาศในบทที่ 6–8

## 1. วงวนเกมและระบบพิกัดจอภาพ

### โครงสร้างโปรแกรมเกม
โปรแกรมเกมไม่ได้ทำงานจากบนลงล่างแล้วจบ แต่ **วนซ้ำตลอดเวลา** จนกว่าผู้เล่นจะปิดหน้าต่าง แต่ละรอบของการวนซ้ำเรียกว่า **เฟรม (Frame)** และในแต่ละเฟรมต้องทำ 6 ขั้นตามลำดับเสมอ

```python
import pygame

SCREEN_WIDTH, SCREEN_HEIGHT = 800, 600
FPS = 60
BLACK = (0, 0, 0)

pygame.init()                                              # เริ่มระบบของ Pygame
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption("My First Game")
clock = pygame.time.Clock()

running = True
while running:
    for event in pygame.event.get():          # 1. รับเหตุการณ์ (Event) เช่น กดปิดหน้าต่าง
        if event.type == pygame.QUIT:
            running = False
    screen.fill(BLACK)                        # 2. ล้างจอด้วยสีพื้นหลัง
    # ...                                     # 3. อัปเดตสถานะ (ตำแหน่ง ความเร็ว การชน)
    # ...                                     # 4. วาดทุกอย่างลงบน screen
    pygame.display.flip()                     # 5. แสดงภาพที่วาดเสร็จขึ้นจอ
    clock.tick(FPS)                           # 6. คุมอัตราเฟรม ไม่ให้เกิน 60 เฟรม/วินาที
pygame.quit()
```

`while running:` คือการวนซ้ำแบบไม่รู้จำนวนรอบล่วงหน้า ทบทวนได้ที่ [EN-001-002 บท 03 การควบคุมการไหลของโปรแกรม](https://en-001-002-computer-programming.vercel.app/module/03)

### ทำไมต้องครบทั้ง 6 ขั้น
| ขั้น | คำสั่ง | หากไม่มี |
|---|---|---|
| 1 รับเหตุการณ์ | `pygame.event.get()` | หน้าต่างค้าง กดปิดไม่ได้ (ระบบปฏิบัติการมองว่าโปรแกรมไม่ตอบสนอง) |
| 2 ล้างจอ | `screen.fill(BLACK)` | ภาพเฟรมก่อนค้างอยู่ กลายเป็นรอยทางยาวตามการเคลื่อนที่ |
| 3 อัปเดต | `ball.move()` / `group.update()` | วัตถุไม่ขยับ |
| 4 วาด | `ball.draw(screen)` / `group.draw(screen)` | จอว่างเปล่า |
| 5 แสดงภาพ | `pygame.display.flip()` | มองไม่เห็นสิ่งที่วาด เพราะวาดลงบัฟเฟอร์หลังจอ |
| 6 คุมเฟรม | `clock.tick(60)` | เกมวิ่งเร็วเท่าที่เครื่องทำได้ เครื่องเร็ววัตถุก็วิ่งเร็ว |

> [!important] ลำดับที่ต้องจำ
> **event → fill → update → draw → flip → tick** — วาดลงบน `screen` ก่อน แล้วค่อย `flip()` ครั้งเดียวท้ายเฟรม (Double Buffering) ภาพจึงไม่กะพริบ

![วงจร 6 ขั้นของวงวนเกม event, fill, update, draw, flip, tick เรียงเป็นวงพร้อมคำสั่ง Pygame ของแต่ละขั้น](/infographics/05/game-loop.svg)

อ่านภาพตามลูกศรตามเข็มนาฬิกาจากกล่องที่ 1 ด้านบน ครบหนึ่งรอบวงคือ **หนึ่งเฟรม** แล้ววนกลับมาเริ่มที่ขั้นที่ 1 ใหม่ กล่องมุมซ้ายบนคือคำสั่งที่ทำ **ครั้งเดียว** ก่อนเข้าวงวน ส่วนกล่องสีแดงมุมขวาบนคือทางออกเดียวของวงวน: เมื่อพบเหตุการณ์ `QUIT` ในขั้นที่ 1 ตัวแปร `running` จะเป็น `False` และโปรแกรมจะออกจาก `while` ไปเรียก `pygame.quit()` ข้อความกลางวงย้ำว่าขั้น 2–4 ทำงานกับ **บัฟเฟอร์หลังจอ** ผู้เล่นยังไม่เห็นอะไร จนกระทั่งขั้นที่ 5 สลับบัฟเฟอร์ขึ้นจอในคราวเดียว

### ทำไมลำดับจึงสลับกันไม่ได้
- **fill ต้องมาก่อน draw** — ถ้าล้างจอหลังวาด สิ่งที่วาดจะถูกลบทิ้งก่อนแสดง จอจะเป็นสีพื้นล้วน
- **update ต้องมาก่อน draw** — ถ้าวาดก่อนอัปเดต ภาพที่เห็นจะช้ากว่าสถานะจริงไป 1 เฟรม (ยังทำงานได้ แต่การชนจะดูไม่ตรง)
- **flip ต้องอยู่หลัง draw ทั้งหมด** — ถ้าเรียก `flip()` กลางทาง ผู้เล่นจะเห็นภาพที่วาดไม่ครบ (บางวัตถุหายไปบางเฟรม จึงดูกะพริบ)
- **tick อยู่ท้ายสุด** — `clock.tick(60)` จะ "รอ" ให้ครบเวลา 16.7 ms นับจากเฟรมก่อน ถ้าวางไว้ต้นวงก็ยังคุมอัตราเฟรมได้ แต่ธรรมเนียมคือวางท้ายเพื่อให้อ่านง่ายว่าจบเฟรมแล้ว

### อัตราเฟรม (Frame Rate)
`clock.tick(60)` จำกัดไม่ให้เกิน 60 **เฟรมต่อวินาที (Frames Per Second: FPS)** ดังนั้น

- แต่ละเฟรมห่างกันประมาณ $1000/60 \approx 16.7$ มิลลิวินาที
- วัตถุที่ขยับ 5 พิกเซล/เฟรม จะเคลื่อนที่ $5 \times 60 = 300$ พิกเซล/วินาที
- ถ้าโปรแกรมจำลองหยุดที่ `FRAME_LIMIT = 600` เฟรม จะทำงานประมาณ $600/60 = 10$ วินาที
- `clock.get_fps()` อ่านอัตราเฟรมจริง ถ้าคำนวณหนัก (เช่น ตรวจชน 100,000 คู่ในบทที่ 8) ค่าจะต่ำกว่า 60

ข้อสอบมักให้ `FRAME_LIMIT` กับ `FPS` แล้วถามว่าโปรแกรมทำงานกี่วินาที หรือถามว่าแต่ละเฟรมห่างกันกี่มิลลิวินาที ใช้สองสูตรนี้

$$\text{เวลาทำงาน (วินาที)} = \frac{\texttt{FRAME\_LIMIT}}{\texttt{FPS}} \qquad\qquad \text{เวลาต่อเฟรม (ms)} = \frac{1000}{\texttt{FPS}}$$

| `FRAME_LIMIT` | `FPS` | เวลาทำงาน | เวลาต่อเฟรม |
|---|---|---|---|
| 600 | 60 | 600 ÷ 60 = **10 วินาที** | 1000 ÷ 60 ≈ 16.7 ms |
| 900 | 30 | 900 ÷ 30 = **30 วินาที** | 1000 ÷ 30 ≈ 33.3 ms |
| 1200 | 50 | 1200 ÷ 50 = **24 วินาที** | 1000 ÷ 50 = 20 ms |

เวลานี้เป็น **ค่าอย่างน้อย** เพราะ `tick(FPS)` คุมไม่ให้ **เร็วเกิน** FPS เท่านั้น ถ้าเครื่องช้าจนทำได้ไม่ถึง FPS โปรแกรมจะใช้เวลานานกว่าที่คำนวณ

### ถ้าขาดหรือสลับคำสั่ง จะเห็นอะไรบนจอ
ตารางนี้รวมคำถามแนว "ถ้าลบบรรทัดนี้ออกจะเกิดอะไรขึ้น" ซึ่งออกสอบบ่อยที่สุดในหัวข้อนี้ ให้ตอบโดยนึกถึงหน้าที่ของคำสั่งนั้นในวงวน

| การเปลี่ยนแปลง | สิ่งที่เห็น | เหตุผล |
|---|---|---|
| ไม่มี `for event in pygame.event.get()` | หน้าต่าง **ค้าง/ไม่ตอบสนอง** กดปิดไม่ได้ | ระบบปฏิบัติการส่งเหตุการณ์มาแต่ไม่มีใครรับ จึงมองว่าโปรแกรมแฮงก์ และไม่มีทางพบ `QUIT` |
| ไม่มี `screen.fill(...)` | วัตถุที่เคลื่อนที่ทิ้ง **รอยทาง (Trail)** เป็นแถบยาว | ภาพของทุกเฟรมก่อนหน้ายังค้างอยู่บนบัฟเฟอร์ |
| วาด **ก่อน** `fill` (draw → fill → flip) | จอเป็น **สีพื้นล้วน** (เช่น ดำทั้งจอ) ไม่เห็นวัตถุเลย | `fill` ทาสีทับทั้งจอ ลบสิ่งที่เพิ่งวาดก่อนจะถึง `flip` |
| ไม่มี `pygame.display.flip()` | **ไม่เห็นอะไรเลย** (จอดำ/ว่าง) แม้โค้ดวาดทำงาน | ทุกอย่างวาดลงบัฟเฟอร์หลังจอ ไม่เคยถูกสลับขึ้นมาแสดง |
| ไม่มี `clock.tick(FPS)` | เกม **เร็วผิดปกติ** และ **เร็วไม่เท่ากันในแต่ละเครื่อง** (CPU ทำงานเต็มที่) | วนเร็วที่สุดเท่าที่เครื่องทำได้ เช่น ขยับ 5 px/เฟรม ที่ 1000 เฟรม/วินาที = 5000 px/วินาที |
| `flip()` อยู่ระหว่างการวาด | วัตถุบางตัว **กะพริบ** | ผู้เล่นเห็นภาพที่ยังวาดไม่ครบ |

**ลำดับการวาด (Drawing Order)** — สิ่งที่วาดทีหลังจะทับสิ่งที่วาดก่อน เหมือนระบายสีทับบนผืนผ้าใบ เช่น

```python
screen.fill(BLACK)
pygame.draw.rect(screen, BLUE, (300, 200, 200, 200))      # สี่เหลี่ยมวาดก่อน
pygame.draw.circle(screen, RED, (400, 300), 80)           # วงกลมวาดทีหลัง
pygame.display.flip()
```
สิ่งที่เห็น: สี่เหลี่ยมสีน้ำเงิน 200×200 มีวงกลมสีแดงรัศมี 80 **ทับอยู่ด้านบน** ตรงกลาง (วงกลมอยู่ภายในสี่เหลี่ยมทั้งหมด เพราะ 400 ± 80 และ 300 ± 80 อยู่ในช่วง x 300–500, y 200–400) ถ้าสลับสองบรรทัด สี่เหลี่ยมจะทับวงกลมจนมองไม่เห็นวงกลมเลย — ในเกมจึงวาด พื้นหลัง → ศัตรู → ยาน → คะแนน (ตัวหนังสือบนสุด)

### ระบบพิกัดจอภาพ (Screen Coordinate)
| | กราฟคณิตศาสตร์ / Matplotlib | จอภาพ Pygame |
|---|---|---|
| จุดกำเนิด (0, 0) | กลางกราฟ / มุมล่างซ้าย | **มุมบนซ้าย** |
| แกน x | ไปทางขวา | ไปทางขวา |
| แกน y | **ขึ้น** | **ลง** |
| กึ่งกลางจอ 800×600 | — | `(800//2, 600//2) = (400, 300)` |

ผลที่ตามมาในโค้ดตลอดทั้งรายวิชา:
- ความโน้มถ่วงทำให้ตก "ลง" → `vy += GRAVITY` ใช้ค่า **บวก** (บทนี้)
- กดปุ่มขึ้น → `input_dir.y -= 1` ใช้ค่า **ลบ** (บทที่ 6)
- วาดเส้นทางลูกบอลด้วย Matplotlib ต้อง `plt.gca().invert_yaxis()` ภาพจึงตรงกับจอ

### สี่เหลี่ยมขอบเขต `pygame.Rect`
ภาพและสไปรต์ทุกตัวมีกรอบสี่เหลี่ยม `rect` ที่มุมบนซ้าย $(x, y)$ กว้าง $w$ สูง $h$

| แอตทริบิวต์ | ค่า | ตัวอย่าง `topleft = (120, 80)` ขนาด 50×50 |
|---|---|---|
| `left`, `top` | $x$, $y$ | 120, 80 |
| `right`, `bottom` | $x + w$, $y + h$ | 170, 130 |
| `centerx`, `centery` | $x + w/2$, $y + h/2$ | 145, 105 |
| `center` | $(x + w/2,\ y + h/2)$ | (145, 105) |

กำหนดค่าให้แอตทริบิวต์ใดก็ได้ เช่น `rect.right = SCREEN_WIDTH` จะเลื่อนทั้งกรอบให้ขอบขวาชิดจอพอดี (ใช้ในสุนัข หัวข้อ 5)

![เปรียบเทียบแกนพิกัดคณิตศาสตร์ที่ y ชี้ขึ้นกับจอ Pygame 800×600 ที่ y ชี้ลง และภาพขยายของ pygame.Rect(120, 80, 50, 50) พร้อมชื่อแอตทริบิวต์](/infographics/05/screen-coords.svg)

ภาพบนซ้ายคือกราฟคณิตศาสตร์ที่ (0, 0) อยู่กลางและจุด (3, 2) อยู่ **เหนือ** แกน x ภาพบนขวาคือจอ 800×600 ย่อตามสเกลจริง สังเกตว่าจุด (600, 120) อยู่ **สูงกว่า** กึ่งกลาง (400, 300) เพราะค่า y น้อยกว่า และลูกศรสีส้มแสดงว่าความโน้มถ่วงต้องเป็น **บวก** จึงจะดึงลูกบอลลงล่าง ภาพล่างขยาย `Rect(120, 80, 50, 50)` 3 เท่า: ไม้บรรทัดด้านบนอ่านค่า x (`left` 120, `centerx` 145, `right` 170) ไม้บรรทัดด้านซ้ายอ่านค่า y (`top` 80, `centery` 105, `bottom` 130) ทุกค่าในตารางขวามาจากสูตร "มุมบนซ้าย + ขนาด" เท่านั้น

> [!tip] ทำไมต้องรู้แอตทริบิวต์ของ Rect
> การตรวจชนขอบเขียนได้สั้นที่สุดเมื่อเลือกแอตทริบิวต์ให้ตรงกับขอบที่สนใจ เช่น ชนขอบขวาใช้ `rect.right >= SCREEN_WIDTH` แทน `rect.x + rect.width >= SCREEN_WIDTH` และการวางวัตถุไว้กลางจอใช้ `rect.center = (400, 300)` บรรทัดเดียว ไม่ต้องคำนวณมุมบนซ้ายเอง

> [!question]- ฝึกทำ: ถ้า `FPS = 30` และ `FRAME_LIMIT = 900` โปรแกรมจำลองจะทำงานประมาณกี่วินาที และยานที่เคลื่อนที่ 4 พิกเซล/เฟรม ที่ 60 FPS จะไปได้ไกลเท่าใดใน 2.5 วินาที

> > [!success]- เฉลย
> > วงกลมของทุกเฟรมซ้อนทับกันเป็นเส้นทางโค้งทึบ เพราะไม่มีใครลบภาพเฟรมก่อนหน้า (บางครั้งใช้เป็นลูกเล่นวาด "รอยทาง" โดยตั้งใจ)

## 2. การวาดรูปทรงและสี่เหลี่ยมจัตุรัสแนบในวงกลม

### คำสั่งวาดพื้นฐาน
| รูปทรง | คำสั่ง | พารามิเตอร์ตำแหน่ง |
|---|---|---|
| วงกลม (Circle) | `pygame.draw.circle(screen, color, (cx, cy), radius)` | **จุดศูนย์กลาง** และรัศมี |
| สี่เหลี่ยม (Rectangle) | `pygame.draw.rect(screen, color, (x, y, w, h))` | **มุมบนซ้าย** กว้าง w สูง h |
| เส้นตรง (Line) | `pygame.draw.line(screen, color, start, end, width)` | จุดเริ่ม จุดปลาย ความหนา |
| กรอบสี่เหลี่ยม | `pygame.draw.rect(screen, color, rect, 1)` | ความหนา 1 = วาดเฉพาะเส้นขอบ (ใช้วาดกริดบทที่ 8) |

สีเป็นทูเพิล `(R, G, B)` แต่ละค่า 0–255: ดำ `(0, 0, 0)` ขาว `(255, 255, 255)` แดง `(255, 0, 0)` เขียว `(0, 255, 0)` น้ำเงิน `(0, 0, 255)` เหลือง `(255, 255, 0)` และสีสุ่ม `(random.randint(0, 255), random.randint(0, 255), random.randint(0, 255))`

### ระบบสี RGB: ผสมแสงแบบบวก
จอภาพสร้างสีจากหลอดแสง 3 สีในแต่ละพิกเซล คือ แดง (Red) เขียว (Green) และน้ำเงิน (Blue) ค่าในทูเพิลบอก **ความสว่างของแสงแต่ละสี** 0 = ปิด 255 = สว่างสุด (ใช้ 8 บิตต่อช่อง จึงได้ $2^8 = 256$ ระดับ) การรวมแสงเป็น **การผสมแบบบวก (Additive Color Mixing)** ยิ่งเปิดแสงหลายสียิ่งสว่าง ตรงข้ามกับการผสมสีน้ำหรือหมึกพิมพ์ที่ยิ่งผสมยิ่งเข้ม

| ชื่อสี | ทูเพิล `(R, G, B)` | ได้จาก |
|---|---|---|
| ดำ (Black) | `(0, 0, 0)` | ปิดแสงทุกสี |
| ขาว (White) | `(255, 255, 255)` | แดง + เขียว + น้ำเงิน เต็มที่ |
| แดง (Red) | `(255, 0, 0)` | แม่สีแสง |
| เขียว (Green) | `(0, 255, 0)` | แม่สีแสง |
| น้ำเงิน (Blue) | `(0, 0, 255)` | แม่สีแสง |
| เหลือง (Yellow) | `(255, 255, 0)` | แดง + เขียว |
| ฟ้าอมเขียว (Cyan) | `(0, 255, 255)` | เขียว + น้ำเงิน |
| ม่วงแดง / ชมพูบานเย็น (Magenta) | `(255, 0, 255)` | แดง + น้ำเงิน |
| เทา (Gray) | `(128, 128, 128)` | ทั้งสามช่องเท่ากันที่ระดับกลาง |

![แผนภาพการผสมแสงแบบบวก วงกลมแดง เขียว น้ำเงิน ซ้อนกันได้เหลือง ฟ้าอมเขียว ม่วงแดง และขาวตรงกลาง พร้อมตารางสีตัวอย่าง 9 สีและทูเพิล RGB](/infographics/05/rgb-colors.svg)

ฝั่งซ้ายวาดวงกลมแสง 3 วงบนพื้นดำ (จอที่ปิดแสง) บริเวณที่สองวงซ้อนกันคือผลบวกของแสงสองสี เช่น แดง + เขียว = เหลือง `(255, 255, 0)` และตรงกลางที่ทั้งสามวงซ้อนกันคือขาว ฝั่งขวาคือตารางสีตัวอย่างกับทูเพิลที่ใช้ในโค้ด ให้สังเกตว่าทุกสีในตารางยกเว้นเทาใช้ค่าเพียง 0 หรือ 255 จึงเป็น "มุม" ทั้ง 8 ของลูกบาศก์สี

วิธีอ่านทูเพิลที่ไม่เคยเห็น: ดูว่าช่องใดมีค่ามาก
- `(255, 165, 0)` แดงเต็ม + เขียวครึ่งหนึ่ง → ส้ม (Orange)
- `(0, 0, 128)` น้ำเงินครึ่งเดียว → น้ำเงินเข้ม (Navy)
- `(200, 200, 200)` ทั้งสามช่องเท่ากัน → เทาอ่อน (ค่าเท่ากันเสมอคือเฉดเทา 0 = ดำ ถึง 255 = ขาว)
- `(255, 255, 255)` กับ `(0, 0, 0)` ต่างกันที่ "ความสว่าง" ไม่ใช่ "เฉดสี"

> [!warning] กับดักเรื่องสี
> - เหลืองคือ `(255, 255, 0)` (แดง + เขียว) ไม่ใช่ `(255, 0, 255)` ซึ่งคือม่วงแดง — อย่าใช้ความรู้ผสมสีน้ำ (เหลือง + น้ำเงิน = เขียว) กับแสง
> - ค่าเกิน 255 หรือติดลบ เช่น `(300, 0, 0)` ทำให้ Pygame แจ้ง `ValueError: invalid color argument`
> - สีต้องเป็นทูเพิล/ลิสต์ 3 ค่า (หรือ 4 ค่าถ้ามีความโปร่งใส Alpha) ลำดับคือ R, G, B เสมอ

> [!warning] วงกลมใช้จุดศูนย์กลาง แต่สี่เหลี่ยมใช้มุมบนซ้าย
> ต้องการสี่เหลี่ยมด้าน $a$ ให้ศูนย์กลางอยู่ที่ $(c_x, c_y)$ ต้องเลื่อนมุมบนซ้ายไป $(c_x - a/2,\ c_y - a/2)$ เช่น สี่เหลี่ยม 60×40 ศูนย์กลาง (300, 200) → `pygame.draw.rect(screen, YELLOW, (270, 180, 60, 40))`

### ตัวอย่าง `first_gam.py`
```python
import math
import pygame

WIDTH, HEIGHT = 800, 600
BLACK, GREEN, BLUE, RED = (0, 0, 0), (0, 255, 0), (0, 0, 255), (255, 0, 0)

circle_x, circle_y = WIDTH//2, HEIGHT//2        # (400, 300) กึ่งกลางจอ
circle_radius = HEIGHT//2                       # 300 → วงกลมสูงเต็มจอพอดี
a = 2*math.sqrt(circle_radius**2/2)             # ≈ 424.26 ด้านของสี่เหลี่ยมแนบในวงกลม
rect_x, rect_y = circle_x - a//2, circle_y - a//2   # (188.0, 88.0) มุมบนซ้าย

...                                             # pygame.init(), set_mode, clock เหมือนหัวข้อ 1
while running:
    ...                                         # event.get() / QUIT
    screen.fill(BLACK)
    pygame.draw.circle(screen, GREEN, (circle_x, circle_y), circle_radius)
    pygame.draw.rect(screen, BLUE, (rect_x, rect_y, a, a))
    pygame.draw.line(screen, RED, (rect_x, rect_y), (rect_x + a, rect_y + a), 20)   # ทแยง ↘
    pygame.draw.line(screen, RED, (rect_x, rect_y + a), (rect_x + a, rect_y), 20)   # ทแยง ↗
    pygame.display.flip()
    clock.tick(60)
```
สิ่งที่เห็น: วงกลมสีเขียวสูงเต็มจอ ภายในมีสี่เหลี่ยมจัตุรัสสีน้ำเงินที่มุมทั้งสี่แตะเส้นรอบวงพอดี และกากบาทสีแดงหนา 20 พิกเซลตามเส้นทแยงมุม ตัดกันที่ (400, 300)

> [!tip] ลำดับการวาดสำคัญ
> สิ่งที่วาดทีหลังจะทับสิ่งที่วาดก่อน (เหมือนวางกระดาษซ้อนกัน) จึงต้องวาด พื้นหลัง → วงกลม → สี่เหลี่ยม → เส้น ถ้าสลับวาดวงกลมหลังสุด จะเห็นแต่วงกลมเขียว

### พิสูจน์: ทำไม $a = 2\sqrt{r^2/2}$
สี่เหลี่ยมจัตุรัสที่ **แนบในวงกลม (Inscribed Square)** มีมุมทั้งสี่อยู่บนเส้นรอบวง เส้นทแยงมุมของมันจึงเป็น **เส้นผ่านศูนย์กลาง** ยาว $2r$ จากทฤษฎีบทพีทาโกรัส

$$a^2 + a^2 = (2r)^2 \;\Rightarrow\; 2a^2 = 4r^2 \;\Rightarrow\; a = \sqrt{2r^2} = r\sqrt{2}$$

และโค้ดเขียนว่า $2\sqrt{r^2/2} = 2 \cdot \dfrac{r}{\sqrt{2}} = r\sqrt{2}$ ซึ่งเท่ากันพอดี

| ค่า | สูตร | ผลลัพธ์เมื่อ $r = 300$ |
|---|---|---|
| ด้าน $a$ | $r\sqrt{2}$ | $424.26$ |
| ครึ่งด้าน `a//2` | หารปัดลง | `212.0` (ค่าจริง 212.13) |
| มุมบนซ้าย | $(400 - 212,\ 300 - 212)$ | `(188.0, 88.0)` |
| มุมล่างขวา | $(188 + a,\ 88 + a)$ | $(612.26,\ 512.26)$ |
| พื้นที่ | $a^2 = 2r^2$ | $180{,}000$ |

![วงกลมรัศมี 300 และสี่เหลี่ยมจัตุรัสแนบในด้าน 424.26 บนจอ 800×600 วาดตามสเกล พร้อมพิกัดมุมบนซ้าย (188, 88) และมุมล่างขวา (612.26, 512.26)](/infographics/05/inscribed-square.svg)

ภาพนี้ย่อจอ 800×600 ลง 70% โดยคงสัดส่วนทุกอย่าง เส้นกริดห่างกัน 100 พิกเซล วงกลมสีเขียวสูงเต็มจอพอดีเพราะ $r = 300 = 600/2$ มุมทั้งสี่ของสี่เหลี่ยมสีน้ำเงินแตะเส้นรอบวง และเส้นทแยงสีแดงทั้งสองเส้นเป็นเส้นผ่านศูนย์กลางยาว $2r = 600$ ตัดกันที่ (400, 300) กล่องด้านขวาไล่การคำนวณจากพีทาโกรัสไปจนได้มุมบนซ้าย (188.0, 88.0) ที่ส่งเข้า `pygame.draw.rect` ส่วนมุมล่างขวาคำนวณจาก $188 + 424.26 = 612.26$

### ขั้นตอนคิดเมื่อเจอโจทย์วาดรูปทรงซ้อนกัน
1. หา **จุดอ้างอิงร่วม** ก่อน (ในที่นี้คือกึ่งกลางจอ) แล้วคำนวณทุกรูปทรงจากจุดนั้น
2. หาความสัมพันธ์ทางเรขาคณิต (เส้นทแยงของสี่เหลี่ยม = เส้นผ่านศูนย์กลางของวงกลม)
3. แปลงเป็นพารามิเตอร์ที่คำสั่งวาดต้องการ — วงกลมต้องการศูนย์กลาง สี่เหลี่ยมต้องการมุมบนซ้าย เส้นต้องการจุดปลายสองจุด
4. ตรวจด้วยการแทนค่ากลับ เช่น มุมบนซ้าย (188, 88) ห่างจาก (400, 300) เท่ากับ $\sqrt{212^2 + 212^2} \approx 299.8 \approx r$ จึงอยู่บนเส้นรอบวงจริง (คลาด 0.2 เพราะ `a//2` ปัดลง)

> [!note] คอมเมนต์ในโค้ดต้นฉบับเขียนว่า "ความสูงของสามเหลี่ยมด้านเท่า"
> แต่ค่าที่คำนวณจริงคือ **ด้านของสี่เหลี่ยมจัตุรัสแนบในวงกลม** และสังเกตว่า `a//2` ได้ `212.0` (float ที่ปัดลง) ไม่ใช่ `212.13` จึงเกิดความคลาดเคลื่อนไม่ถึง 1 พิกเซล ซึ่งมองไม่เห็นบนจอ

### วาดวัตถุผ่านเมท็อดของคลาส
```python
class Ball:
    def draw(self, screen):
        pygame.draw.circle(screen, self.color, (int(self.x), int(self.y)), self.radius)
```
ตำแหน่งเก็บเป็นจำนวนจริง (เช่น 405.997) เพื่อความแม่นยำสะสม แต่พิกเซลบนจอเป็นจำนวนเต็ม จึงแปลงด้วย `int()` ตอนวาดเท่านั้น

> [!question]- ฝึกทำ: จอ 1000×800 วาดวงกลมรัศมี 400 ที่กึ่งกลางจอ และสี่เหลี่ยมแนบในตามสูตรเดียวกับ `first_gam.py` จงหาจุดศูนย์กลาง ด้าน $a$ และ `(rect_x, rect_y)`
> > [!success]- เฉลย
> > ศูนย์กลาง (500, 400); $a = 400\sqrt{2} \approx 565.69$; `a//2 = 282.0` → `(218.0, 118.0)`

> [!question]- ฝึกทำ: วงกลมรัศมี 50 จงหาด้านและพื้นที่ของสี่เหลี่ยมจัตุรัสแนบใน และถ้ากลับกัน ต้องการวงกลมที่แนบในสี่เหลี่ยมจัตุรัสด้าน 200 รัศมีเป็นเท่าใด
> > [!success]- เฉลย
> > $a = 50\sqrt{2} \approx 70.71$ พื้นที่ $a^2 = 2r^2 = 5000$ ส่วนวงกลมแนบในสี่เหลี่ยมด้าน 200 มี $r = 200/2 = 100$

> [!question]- ฝึกทำ: จงเขียนทูเพิลของสีเหลือง ฟ้าอมเขียว และม่วงแดง และบอกว่า `(0, 255, 255)` กับ `(128, 128, 128)` คือสีอะไร
> > [!success]- เฉลย
> > เหลือง `(255, 255, 0)` = แดง + เขียว · ฟ้าอมเขียว `(0, 255, 255)` = เขียว + น้ำเงิน · ม่วงแดง `(255, 0, 255)` = แดง + น้ำเงิน · `(0, 255, 255)` คือฟ้าอมเขียว (Cyan) และ `(128, 128, 128)` คือเทา เพราะทั้งสามช่องเท่ากัน

> [!question]- ฝึกทำ: โค้ดวาด `pygame.draw.circle(screen, RED, (400, 300), 100)` ก่อน แล้วจึง `pygame.draw.rect(screen, GREEN, (350, 250, 100, 100))` จะเห็นอะไรตรงกลางจอ
> > [!success]- เฉลย
> > สี่เหลี่ยมจัตุรัสสีเขียว 100×100 (ศูนย์กลาง (400, 300) พอดี) **ทับ** อยู่บนวงกลมแดง เห็นขอบวงกลมแดงล้อมรอบ เพราะวาดทีหลังจึงอยู่ด้านบน — สีไม่ผสมกันเป็นเหลือง เพราะ `draw` เขียนทับพิกเซลเดิม ไม่ได้บวกแสง

## 3. การเคลื่อนที่แบบออยเลอร์และความโน้มถ่วง

### เวลาแบบไม่ต่อเนื่อง (Discrete Time)
ฟิสิกส์ในตำราใช้เวลาต่อเนื่อง แต่เกมคำนวณได้ทีละ **เฟรม** ถ้ากำหนดให้ 1 เฟรม = 1 หน่วยเวลา จะได้

$$\mathbf{p}_{t+1} = \mathbf{p}_t + \mathbf{v}_t \qquad\qquad \mathbf{v}_{t+1} = \mathbf{v}_t + \mathbf{a}$$

**ตำแหน่ง (Position)** เปลี่ยนตามความเร็ว และ **ความเร็ว (Velocity)** เปลี่ยนตาม **ความเร่ง (Acceleration)** วิธีนี้เรียกว่า **วิธีของออยเลอร์ (Euler Method)** — เป็นการประมาณ แต่เมื่อเฟรมถี่ถึง 60 ครั้ง/วินาที ตาเรามองเห็นเป็นการเคลื่อนที่ต่อเนื่อง

### ลูกบอลภายใต้ความโน้มถ่วง (`ball.py`)
```python
GRAVITY = 0.1                 # ความเร่งคงที่ 0.1 พิกเซล/เฟรม² (แกน y ชี้ลง จึงเป็นบวก)
BOUNCE_DAMPING = 0.9          # เสียความเร็ว 10% ทุกครั้งที่ชนขอบ
DAMPING_COEFFICIENT = 0.999   # แรงต้านอากาศเล็กน้อย: ความเร็วเหลือ 99.9% ทุกเฟรม

def move(self):
    self.x += self.vx                 # 1. ตำแหน่งเปลี่ยนตามความเร็ว
    self.y += self.vy
    self.vy += GRAVITY                # 2. ความเร็วแนวดิ่งเพิ่มตามความโน้มถ่วง
    self.vx *= DAMPING_COEFFICIENT    # 3. หน่วงเล็กน้อยทุกเฟรม
    self.vy *= DAMPING_COEFFICIENT
    # ... ตรวจชนขอบ (หัวข้อ 4)
```

> [!important] ลำดับคำสั่งมีผลต่อคำตอบ
> โค้ดนี้ **ปรับตำแหน่งก่อน** แล้วจึงเปลี่ยนความเร็ว ดังนั้นถ้า `vy` เริ่มที่ 0 ตำแหน่ง y ใน **เฟรมแรกจะยังไม่เปลี่ยน** (100 + 0 = 100) ความโน้มถ่วงที่บวกเข้าไปจะไปมีผลในเฟรมถัดไป ข้อสอบไล่ค่าต้องทำตามลำดับบรรทัดในโค้ดเป๊ะ ๆ

### ไล่ค่าทีละเฟรม (x = 400, y = 100, vx = 3, vy = 0)
| เฟรม | x | y | vx | vy | วิธีคิด vy |
|---|---|---|---|---|---|
| เริ่มต้น | 400 | 100 | 3 | 0 | |
| 1 | 403 | 100 | 2.997 | 0.0999 | $(0 + 0.1) \times 0.999$ |
| 2 | 405.997 | 100.0999 | 2.994 | 0.1997 | $(0.0999 + 0.1) \times 0.999$ |
| 3 | 408.991 | 100.2996 | 2.991 | 0.2994 | $(0.1997 + 0.1) \times 0.999$ |

สังเกตว่า x เพิ่มเกือบคงที่ (ความเร็วคงที่ → เส้นตรง) ส่วน y เพิ่มมากขึ้นเรื่อย ๆ (ความเร่งคงที่ → **พาราโบลา**) และ vx ลดลงช้ามาก: หลัง 100 เฟรม $3 \times 0.999^{100} \approx 2.71$

![เส้นทางลูกบอล 300 เฟรมแรกบนจอ 800×600 วาดตามสเกล พร้อมลูกศรความเร็วที่เฟรม 0, 50, 101, 138, 200, 271 และตารางไล่ค่า 3 เฟรมแรก](/infographics/05/euler-trace.svg)

ภาพนี้ได้จากการรันโค้ด `move()` จริง 300 เฟรมแล้ววาดตำแหน่งลงบนจอที่ย่อ 60% จุดเทาห่างกันทุก 10 เฟรม ช่วงแรกจุดเกือบติดกันในแนวดิ่ง (vy ยังเล็ก) แล้วค่อย ๆ ห่างขึ้นเมื่อตกเร็วขึ้น ลูกศรคือเวกเตอร์ความเร็ว (ขยาย 12 เท่า) — ลูกศรสีน้ำเงินชี้ลงชันขึ้นเรื่อย ๆ เพราะ vy โตขึ้นทุกเฟรมขณะที่ vx เกือบคงที่ ส่วนลูกศรสีแดงคือความเร็ว **หลัง** สะท้อน: เฟรมที่ 101 ชนพื้น vy พลิกจาก +9.60 เป็น −8.64 และเฟรมที่ 138 ชนขอบขวา vx พลิกจาก +2.61 เป็น −2.35 ยอดของการเด้งแต่ละครั้งจึงต่ำลง ตารางด้านล่างเน้นสีแดงว่า y ของเฟรมที่ 1 ยังเป็น 100

### ทำไมเรียกว่า "ประมาณ"
ฟิสิกส์จริงที่ความเร่งคงที่ $g$ ให้ระยะตก $\tfrac{1}{2}gt^2$ แต่วิธีของออยเลอร์บวกความเร็ว "เดิม" ของต้นเฟรมเข้าตำแหน่ง ระยะสะสมหลัง $n$ เฟรม (ไม่คิดการหน่วง) จึงเป็น
$$0 + g + 2g + \dots + (n-1)g = \frac{n(n-1)}{2}g$$
ซึ่งน้อยกว่าค่าจริง $\tfrac{1}{2}gn^2$ อยู่ $\tfrac{1}{2}gn$ เช่น $g = 0.1$, $n = 10$ ได้ 4.5 แทน 5.0 — ความคลาดเคลื่อนนี้เล็กลงเมื่อเฟรมถี่ขึ้น และในเกมสิ่งที่สำคัญคือ **ความสม่ำเสมอ** ไม่ใช่ความแม่นยำระดับตำราฟิสิกส์

### ความเร็วคงที่ vs ความเร่งคงที่
| รูปแบบ | วัตถุในรายวิชา | โค้ด | เส้นทาง |
|---|---|---|---|
| ความเร็วคงที่ | กระสุน (บทที่ 8), ศัตรู (บทที่ 7) | `x += vx` | เส้นตรง |
| ความเร่งคงที่ | ลูกบอล (บทนี้) | `vy += GRAVITY` | พาราโบลา |
| เร่งตามปุ่ม + แรงเสียดทาน | ยานอวกาศ (บทที่ 6–7) | `velocity *= friction` | โค้งนุ่มนวล |

## 4. การสะท้อนเมื่อชนขอบและการหน่วง

### หลักการสะท้อน (Reflection)
ชนผนังแนวตั้ง (ซ้าย/ขวา) ให้กลับเครื่องหมาย **องค์ประกอบแนวนอน** ชนผนังแนวนอน (บน/ล่าง) ให้กลับ **องค์ประกอบแนวตั้ง**

$$\text{ชนซ้าย/ขวา: } (v_x, v_y) \to (-v_x,\ v_y) \qquad \text{ชนบน/ล่าง: } (v_x, v_y) \to (v_x,\ -v_y)$$

มุมตกกระทบเท่ากับมุมสะท้อน และอัตราเร็ว $\sqrt{v_x^2 + v_y^2}$ คงเดิม (ถ้าไม่มีการหน่วง)

### เงื่อนไขชนขอบของวงกลม
ลูกบอลที่จุดศูนย์กลาง $(x, y)$ รัศมี $r$ "แตะ" ขอบเมื่อ **ขอบของวงกลม** ไม่ใช่จุดศูนย์กลางถึงขอบจอ

| ขอบ | เงื่อนไข |
|---|---|
| ซ้าย | $x - r \le 0$ |
| ขวา | $x + r \ge$ `SCREEN_WIDTH` |
| พื้น (ล่าง) | $y + r \ge$ `SCREEN_HEIGHT` |

```python
    if self.x - self.radius <= 0 or self.x + self.radius >= SCREEN_WIDTH:
        self.vx = -self.vx * BOUNCE_DAMPING      # สะท้อนแนวนอน เสียความเร็ว 10%
    if self.y + self.radius >= SCREEN_HEIGHT:
        self.vy = -self.vy * BOUNCE_DAMPING      # สะท้อนจากพื้น
        self.y = SCREEN_HEIGHT - self.radius     # วางให้อยู่บนพื้นพอดี
```

### สะท้อนพร้อมเสียพลังงาน
`BOUNCE_DAMPING = 0.9` หมายถึงหลังชนเหลือความเร็ว 90% ลูกบอลจึงเด้งเตี้ยลงเรื่อย ๆ เหมือนลูกบอลจริง เทียบกับศัตรูในบทที่ 7 ที่ใช้ `vel.x *= -1` สะท้อนโดยไม่เสียความเร็วเลย

ตัวอย่าง: vx = 4 ชนขอบขวา → $-4 \times 0.9 = -3.6$ → วิ่งกลับไปชนขอบซ้าย → $-(-3.6) \times 0.9 = 3.24$ ชนครั้งที่ $n$ เหลือ $4 \times 0.9^n$

### ทำไมต้องวางตำแหน่งกลับ (แก้ปัญหาวัตถุติดผนัง)
สมมุติลูกบอลรัศมี 20 จอสูง 600 ตก **ทะลุ** พื้นไปที่ y = 590 (ขอบล่างของบอล = 610 > 600)

| วิธี | เฟรมที่ชน | เฟรมถัดไป |
|---|---|---|
| กลับทิศอย่างเดียว | vy = −4.5, y ยังเป็น 590 | y = 585.5 ขอบล่าง 605.5 ยัง ≥ 600 → **กลับทิศซ้ำ** vy ≈ +3.96 ตกลงอีก → ติดอยู่ที่พื้นสั่นไปมา |
| กลับทิศ + วางกลับ | vy = −4.5, **y = 580** | y = 575.5 ขอบล่าง 595.5 < 600 → ลอยขึ้นตามปกติ |

![เปรียบเทียบขอบล่างของลูกบอลทีละเฟรม 0 ถึง 6 ระหว่างการกลับทิศอย่างเดียวที่ติดอยู่ใต้พื้นกับการกลับทิศพร้อมวางตำแหน่งกลับที่ลอยขึ้นได้](/infographics/05/wall-bounce.svg)

กราฟทั้งสองใช้แกน y ชี้ลงเหมือนจอ เส้นดำหนาคือพื้น y = 600 และแถบสีแดงคือบริเวณที่ลูกบอล "ทะลุพื้น" ฝั่งซ้าย (กลับทิศอย่างเดียว) ขอบล่างของลูกบอลแกว่งอยู่ระหว่าง 605.5 ถึง 610 ในแถบสีแดง **ทุกเฟรม** จุดทึบทุกจุดแปลว่าเงื่อนไขชนเป็นจริงซ้ำทุกเฟรม vy จึงสลับเครื่องหมาย −4.50, 3.96, −3.65, … และเล็กลงเรื่อย ๆ ลูกบอลไม่มีวันขึ้นจากพื้น ฝั่งขวา (กลับทิศ + วางกลับ) มีจุดทึบเพียงเฟรม 0 ที่ถูกวางให้ขอบล่างอยู่ที่ 600 พอดี จากนั้น vy ติดลบต่อเนื่องและลูกบอลลอยขึ้น — ค่าทุกตัวในภาพได้จากการรันโค้ดจริงด้วย GRAVITY 0.1 และ DAMPING 0.999

> [!warning] กลับทิศอย่างเดียวไม่พอ
> ถ้าตรวจพบว่าทะลุขอบแล้วเพียงกลับทิศ เฟรมถัดไปวัตถุอาจยังอยู่นอกขอบ ทำให้กลับทิศซ้ำไปมา (ติดผนัง) จึงต้อง **วางตำแหน่งกลับเข้ามาที่ขอบ** ด้วย `self.y = SCREEN_HEIGHT - self.radius` หลักเดียวกับ `self.rect.right = SCREEN_WIDTH` ของสุนัข

> [!bug] กับดักใน `rect.py`
> คลาส `Rectangle` ยืมเงื่อนไข `self.x - self.size <= 0` มาจาก `Ball` แต่สี่เหลี่ยมวาดด้วย (x, y) เป็น **มุมบนซ้าย** ไม่ใช่จุดศูนย์กลาง ขอบซ้ายจริงคือ `x` และขอบขวาคือ `x + size` เงื่อนไขที่ถูกต้องคือ `self.x <= 0 or self.x + self.size >= SCREEN_WIDTH`

### เปรียบเทียบเงื่อนไขชนขอบ: วงกลม vs สี่เหลี่ยม
ความต่างทั้งหมดมาจาก "จุดอ้างอิง" ของรูปทรง วงกลมอ้างอิงที่ **จุดศูนย์กลาง** แต่สี่เหลี่ยมอ้างอิงที่ **มุมบนซ้าย**

| รูปทรง | ขอบซ้ายของวัตถุ | ขอบขวาของวัตถุ | เงื่อนไขชนซ้าย/ขวา |
|---|---|---|---|
| วงกลม `Ball` (x, y = ศูนย์กลาง) | `x - radius` | `x + radius` | `self.x - self.radius <= 0 or self.x + self.radius >= SCREEN_WIDTH` |
| สี่เหลี่ยม `Rectangle` (x, y = มุมบนซ้าย) | `x` | `x + size` | `self.x <= 0 or self.x + self.size >= SCREEN_WIDTH` |
| ✗ แบบที่ยืมมาผิด | `x - size` (ไม่ใช่ขอบจริง) | `x + size` (บังเอิญถูก) | `self.x - self.size <= 0 or ...` |

ไล่ค่าให้เห็นผลของบั๊ก: สี่เหลี่ยม `size = 40` เริ่ม `x = 100`, `vx = −5` จอกว้าง 800 (move แล้วตรวจชน กลับทิศด้วย `vx = -vx`)

| เฟรม | x (ถูก: `x <= 0`) | vx | x (ผิด: `x - 40 <= 0`) | vx |
|---|---|---|---|---|
| 1 | 95 | −5 | 95 | −5 |
| 11 | 45 | −5 | 45 | −5 |
| 12 | 40 | −5 | **40 → ชน** | **+5** |
| 19 | 5 | −5 | 75 | +5 |
| 20 | **0 → ชน** | **+5** | 80 | +5 |

แบบผิดเด้งกลับตั้งแต่ x = 40 จึงเห็น **ช่องว่าง 40 พิกเซล** ระหว่างสี่เหลี่ยมกับขอบซ้ายทุกครั้ง ส่วนขอบขวา `x + size >= 800` ถูกอยู่แล้วในทั้งสองแบบ (เช่น `size = 50` เริ่ม x = 740, vx = 5 → เฟรม 2 x = 750 และ 750 + 50 = 800 ชนพอดี) และถ้าสี่เหลี่ยมถูกสร้างที่ x < 40 ตั้งแต่ต้น (เช่น x = 20, vx = −4) เงื่อนไขผิดจะเป็นจริงทุกเฟรม vx สลับ +4, −4 ไปมา x แกว่งอยู่ระหว่าง 16 กับ 20 — **ติดผนังที่มองไม่เห็น**

### ลูกบอลตกถึงพื้นเมื่อใด
จากตารางหัวข้อ 3 ลูกบอลรัศมี 15 เริ่ม y = 100 ต้องตกลงมา $585 - 100 = 485$ พิกเซล ความเร็วเพิ่มราว 0.1 ต่อเฟรม ระยะสะสมหลัง $n$ เฟรมประมาณ $0.05n^2$ → $n \approx \sqrt{485/0.05} \approx 98$ เฟรม (รันจริงได้เฟรมที่ 101 เพราะการหน่วง 0.999 ทำให้ช้าลงเล็กน้อย) ขณะชน vy ≈ 9.60 และหลังสะท้อน vy ≈ −8.64

> [!question]- ฝึกทำ: ลูกบอลรัศมี 20 บนจอสูง 600 อยู่ที่ y = 590 และ vy = 5 ขณะตรวจการชนพื้น (BOUNCE_DAMPING = 0.9) ค่า y และ vy ใหม่คือเท่าใด
> > [!success]- เฉลย
> > $590 + 20 = 610 \ge 600$ จึงชน → vy = $-5 \times 0.9 = -4.5$ และ y = $600 - 20 = 580$

> [!question]- ฝึกทำ: ศัตรูความเร็ว (1.5, −2) ชนขอบบนของจอ (ไม่เสียพลังงาน) ความเร็วใหม่คือเท่าใด
> > [!success]- เฉลย
> > $(1.5,\ 2)$ กลับเฉพาะแกน y — ชนขอบบนหมายถึง vy ติดลบ (กำลังขึ้น) ต้องกลับเป็นบวก (ลง)

> [!question]- ฝึกทำ: ถ้าต้องการให้ลูกบอลสะท้อนจาก **ขอบบน** ด้วย จงเขียนเงื่อนไขและการวางตำแหน่งกลับ
> > [!success]- เฉลย
> > ```python
> > if self.y - self.radius <= 0:
> >     self.vy = -self.vy * BOUNCE_DAMPING
> >     self.y = self.radius
> > ```

## 5. จากพจนานุกรมสู่คลาสและสไปรต์

### เวอร์ชันพจนานุกรม (`ball_sim.py`)
```python
ball = {"x": 400, "y": 100, "vx": 3, "vy": 0, "radius": 15, "color": RED}

def move_ball(ball):
    ball["x"] += ball["vx"]
    ball["y"] += ball["vy"]
    ball["vy"] += GRAVITY
    ...                               # หน่วงและตรวจชนขอบ เหมือนหัวข้อ 3–4 แต่เขียนด้วย ball["..."]

def draw_ball(screen, ball):
    pygame.draw.circle(screen, ball["color"], (int(ball["x"]), int(ball["y"])), ball["radius"])
```
ใช้ได้ แต่ข้อมูล (`ball`) กับฟังก์ชัน (`move_ball`, `draw_ball`) แยกกันอยู่ พิมพ์คีย์ผิดเช่น `ball["vX"]` จะ `KeyError` ตอนรันเท่านั้น และจะสร้างลูกบอลเพิ่มต้องเขียนพจนานุกรมใหม่ทีละตัว ทบทวนพจนานุกรมที่ [EN-001-002 บท 05 การออกแบบจากบนลงล่าง](https://en-001-002-computer-programming.vercel.app/module/05)

### เวอร์ชันคลาส (`ball.py` + `ball_sim_v2.py`)
```python
class Ball:
    def __init__(self, x, y, vx, vy, radius, color):   # คอนสตรักเตอร์ (Constructor)
        self.x, self.y = x, y                           # แอตทริบิวต์ (Attribute)
        self.vx, self.vy = vx, vy
        self.radius = radius
        self.color = color

    def move(self):                                     # เมท็อด (Method)
        self.x += self.vx
        self.y += self.vy
        self.vy += GRAVITY
        ...                                             # หน่วงและตรวจชนขอบ (หัวข้อ 3–4)

    def draw(self, screen):
        pygame.draw.circle(screen, self.color, (int(self.x), int(self.y)), self.radius)
```
```python
from ball import Ball                 # นำเข้าคลาสจากแฟ้ม ball.py (มอดูล)

ball = Ball(400, 100, 3, 0, 15, RED)  # สร้างวัตถุ → เรียก __init__ อัตโนมัติ
while running:
    ...
    ball.move()                       # self คือ ball ตัวนี้
    ball.draw(screen)
```

| พจนานุกรม | คลาส |
|---|---|
| `ball["x"] += ball["vx"]` | `self.x += self.vx` |
| `move_ball(ball)` | `ball.move()` |
| ข้อมูลกับฟังก์ชันแยกกัน | รวมข้อมูลและพฤติกรรมไว้ด้วยกัน (Encapsulation) |
| เพิ่มลูกบอลต้องสร้างพจนานุกรมใหม่ทีละตัว | สร้าง 100 ลูกด้วยการวนซ้ำ |

`self` อ้างถึง **วัตถุตัวที่เรียกเมท็อด** วัตถุแต่ละตัวจึงมี `x`, `vx` ของตัวเองแยกจากกัน ทบทวนคลาสที่ [EN-001-002 บท 08 คลาสและวัตถุ](https://en-001-002-computer-programming.vercel.app/module/08)

### ลูกบอล N ลูก (`ball_sim_v3.py`)
```python
N = 100
balls = []
for i in range(N):
    ball = Ball(100 + i*20, 100, 3 * (-1)**i, 0, 15, RED)   # vx สลับ +3, −3
    balls.append(ball)

while running:
    ...
    for ball in balls:
        ball.move()
        ball.draw(screen)
```
$(-1)^i$ ให้ค่า $1, -1, 1, -1, \dots$ ลูกบอลลำดับคู่จึงวิ่งขวา ลำดับคี่วิ่งซ้าย

| i | x เริ่มต้น | vx |
|---|---|---|
| 0 | 100 | 3 |
| 1 | 120 | −3 |
| 2 | 140 | 3 |
| 3 | 160 | −3 |
| 4 | 180 | 3 |

ลูกบอลที่ i = 35 ขึ้นไปมี x เริ่มต้น $\ge 800$ อยู่นอกจอขวา — เมื่อ `x + 15 >= 800` เป็นจริงตั้งแต่เฟรมแรก ความเร็วจะถูกกลับทิศทุกเฟรม (ติดผนัง) เพราะโค้ดชนซ้าย/ขวา **ไม่ได้วางตำแหน่งกลับ** ต่างจากพื้น นี่คือเหตุผลที่หัวข้อ 4 เน้นเรื่องการวางตำแหน่งกลับ

### สไปรต์ (`dog.py`)
Pygame มีคลาสแม่ `pygame.sprite.Sprite` ให้สืบทอด วัตถุที่มี `image` และ `rect` จะถูกจัดการด้วย `pygame.sprite.Group` ได้ทั้งกลุ่ม

```python
class Dog(pygame.sprite.Sprite):                   # สืบทอด (Inheritance) จาก Sprite
    def __init__(self, x, y, vx, image_path):
        super().__init__()                         # เรียกคอนสตรักเตอร์ของคลาสแม่ก่อนเสมอ
        img = pygame.image.load(image_path).convert_alpha()      # โหลดภาพพื้นหลังโปร่งใส
        self.image_right = pygame.transform.scale(img, (100, 100))
        self.image_left = pygame.transform.flip(self.image_right, True, False)   # กลับซ้าย–ขวา
        self.image = self.image_right if vx > 0 else self.image_left
        self.rect = self.image.get_rect(topleft=(x, y))
        self.vx = vx

    def update(self):                              # เขียนทับ (Override) เมท็อดของ Sprite
        self.rect.x += self.vx
        if self.rect.right >= SCREEN_WIDTH:        # ชนขอบขวา
            self.rect.right = SCREEN_WIDTH         # วางให้อยู่พอดีขอบ
            self.vx = -self.vx                     # กลับทิศ
            self.image = self.image_left           # หันซ้าย
        elif self.rect.left <= 0:                  # ชนขอบซ้าย
            self.rect.left = 0
            self.vx = -self.vx
            self.image = self.image_right
```
```python
all_sprites = pygame.sprite.Group()
all_sprites.add(Dog(100, 400, 5, "images/dog.png"))
while running:
    ...
    all_sprites.update()           # เรียก update() ของสไปรต์ทุกตัว
    all_sprites.draw(screen)       # วาด image ของทุกตัวที่ตำแหน่ง rect
```

| สิ่งที่ Group ต้องการ | ความหมาย |
|---|---|
| `self.image` | พื้นผิว (Surface) ที่จะวาด |
| `self.rect` | ตำแหน่งและขนาด ใช้ทั้งวาดและตรวจชน (บทที่ 8) |
| `update()` | ถูกเรียกโดย `group.update()` ทุกเฟรม |

> [!tip] ทำไมเก็บภาพซ้ายและขวาแยกกัน
> `flip` ทุกเฟรมสิ้นเปลืองและเสี่ยงกลับภาพซ้ำจนสับสน จึงเตรียมไว้สองภาพแล้วสลับเฉพาะตอนชนขอบ หลักเดียวกับยานอวกาศบทที่ 6 ที่หมุนจาก `original_image` ทุกครั้ง

### ไล่ค่าสุนัข (กว้าง 80 จอกว้าง 640 เริ่ม `rect.x = 15`, `vx = −5`)
| update ครั้งที่ | rect.x | vx | ภาพ |
|---|---|---|---|
| 1 | 10 | −5 | ซ้าย |
| 2 | 5 | −5 | ซ้าย |
| 3 | 0 → ชนซ้าย | **5** | **ขวา** |
| 4 | 5 | 5 | ขวา |

> [!warning] `rect.x` เป็นจำนวนเต็ม
> ถ้าให้ `vx = 0.3` แล้ว `self.rect.x += self.vx` ค่าจะถูกปัดเป็นจำนวนเต็มทุกเฟรม สุนัขจะไม่ขยับเลย ในบทที่ 6–8 จึงเก็บตำแหน่งเป็น `pygame.math.Vector2` (จำนวนจริง) แล้วค่อยแปลงไปวาง `rect`

### การสืบทอดจาก `pygame.sprite.Sprite` ตอบอย่างไรในข้อสอบ
`class Dog(pygame.sprite.Sprite):` อ่านว่า "คลาส `Dog` **สืบทอด (Inherit)** จากคลาส `Sprite`"

| คำถาม | คำตอบ |
|---|---|
| `Dog` มีความสัมพันธ์กับ `Sprite` อย่างไร | `Dog` เป็น **คลาสลูก (Child Class / Subclass)** ของ `Sprite` ส่วน `Sprite` เป็น **คลาสแม่ (Parent Class / Superclass)** — `Dog` ได้เมท็อดของ `Sprite` ทั้งหมด เช่น `kill()`, `alive()`, `groups()` มาใช้โดยไม่ต้องเขียนเอง |
| `super().__init__()` ทำหน้าที่อะไร | เรียกคอนสตรักเตอร์ของคลาสแม่ เพื่อ **เตรียมส่วนที่เป็น Sprite** ภายในวัตถุ (เช่น ชุดข้อมูลว่าสไปรต์นี้อยู่ใน Group ใดบ้าง) ก่อนที่คลาสลูกจะกำหนด `image`, `rect` ของตัวเอง |
| ถ้าลืม `super().__init__()` | สร้างวัตถุได้ปกติ แต่พังตอน `all_sprites.add(dog)` (หรือ `pygame.sprite.Group(dog)`, `dog.kill()`) ด้วย `AttributeError` เพราะแอตทริบิวต์ภายในที่คลาสแม่ควรสร้างไม่มีอยู่ |
| `isinstance(dog, pygame.sprite.Sprite)` | `True` — วัตถุของคลาสลูกนับเป็นวัตถุของคลาสแม่ด้วย |
| สไปรต์ต้องมีอะไรบ้าง | `self.image` (ภาพ) · `self.rect` (ตำแหน่ง/ขนาด) · เมท็อด `update()` (ถูกเรียกโดย `group.update()`) |

รันจริงด้วย pygame 2.6.1 เมื่อลืม `super().__init__()`:
```python
class Dog(pygame.sprite.Sprite):
    def __init__(self):
        # ลืม super().__init__()
        self.image = pygame.Surface((80, 40))
        self.rect = self.image.get_rect()

all_sprites = pygame.sprite.Group()
all_sprites.add(Dog())
```
```
  File "...\pygame\sprite.py", line 161, in add_internal
    self.__g.add(group)
AttributeError: 'Dog' object has no attribute '_Sprite__g'
```
`__g` คือเซตของ Group ที่สไปรต์สังกัดอยู่ ซึ่ง `Sprite.__init__()` เป็นผู้สร้าง (ไพทอนเปลี่ยนชื่อเป็น `_Sprite__g` ภายใน) — เมื่อไม่เรียก `super().__init__()` จึงไม่มีแอตทริบิวต์นี้ ข้อความ error ไม่ได้บอกตรง ๆ ว่า "ลืม super" จึงต้องจำอาการนี้ไว้

**`isinstance()` กับคลาสของเราเอง** — ใช้แยกชนิดวัตถุที่ปนกันอยู่ในลิสต์หรือ Group เดียวกัน เช่น
```python
objs = [Bullet(100, 500), Rectangle(0, 0, 3, 40, RED), Bullet(200, 500)]
bullets = [o for o in objs if isinstance(o, Bullet)]
print(len(bullets))                         # 2
print(isinstance(objs[1], Bullet))          # False
```

**ทำไมใช้ `pygame.sprite.Group` เมื่อมีศัตรู 100 ตัว**

### การแปลงภาพด้วย `pygame.transform`
ทุกฟังก์ชันใน `pygame.transform` **คืนพื้นผิว (Surface) ใหม่** โดยไม่แก้ภาพเดิม จึงต้องเก็บผลลัพธ์ไว้ในตัวแปรเสมอ

| คำสั่ง | ผลลัพธ์ | ขนาดเมื่อภาพเดิม 80×40 |
|---|---|---|
| `pygame.transform.flip(img, True, False)` | กลับ **ซ้าย–ขวา** (สะท้อนแกนแนวตั้ง) ภาพหันไปอีกทาง | 80×40 |
| `pygame.transform.flip(img, False, True)` | กลับ **บน–ล่าง** (หัวกลับ) | 80×40 |
| `pygame.transform.scale(img, (100, 100))` | ย่อ/ขยายเป็นขนาดที่กำหนดพอดี ถ้าสัดส่วนเดิมไม่ใช่ 1:1 ภาพจะ **ยืด** | 100×100 |
| `pygame.transform.rotate(img, 90)` | หมุน **ทวนเข็มนาฬิกา** บนจอ 90° (มุมลบ = ตามเข็ม) | 40×80 |
| `pygame.transform.rotate(img, 45)` | หมุน 45° กรอบภาพ **โตขึ้น** เพื่อไม่ให้มุมภาพถูกตัด | 84×84 |

พารามิเตอร์ของ `flip(surface, flip_x, flip_y)` คือ "กลับแกน x ไหม" และ "กลับแกน y ไหม" — `True, False` จึงสลับซ้าย–ขวาซึ่งเป็นแบบที่ใช้บ่อยที่สุด (ตัวละครหันซ้าย/ขวา)

![ภาพสุนัขขนาด 80×40 ภายใต้การแปลง 6 แบบ ต้นฉบับ flip ซ้าย–ขวา flip บน–ล่าง scale เป็น 100×100 rotate 90 และ rotate 45 พร้อมกรอบขนาดพื้นผิวใหม่ และกล่องเปรียบเทียบการหมุนจาก original_image](/infographics/05/transforms.svg)

ทุกแผงวาดสุนัขตัวเดียวกันโดยหัวอยู่ทางขวาในภาพต้นฉบับ ให้ดูตำแหน่ง **หัว** เพื่อบอกการแปลง: flip ซ้าย–ขวาหัวไปอยู่ซ้าย flip บน–ล่างขาชี้ขึ้น rotate 90 หัวขึ้นไปอยู่ด้านบน (ทวนเข็ม) กรอบประคือขนาดพื้นผิวที่ฟังก์ชันคืนมา สังเกตว่า scale ทำให้สุนัขอ้วนขึ้นเพราะ 80×40 ถูกยืดเป็น 100×100 และ rotate 45 ได้กรอบ 84×84 ซึ่งใหญ่กว่าภาพเดิม กล่องล่างอธิบายว่าทำไมต้องหมุนจาก `original_image`

> [!important] ทำไมต้องเก็บ `original_image`
> ```python
> self.original_image = pygame.image.load("ship.png").convert_alpha()   # เก็บต้นฉบับครั้งเดียว
> ...
> self.image = pygame.transform.rotate(self.original_image, self.angle)  # ✓ หมุนจากต้นฉบับทุกเฟรม
> # self.image = pygame.transform.rotate(self.image, 10)                # ✗ หมุนภาพที่หมุนแล้วซ้ำ
> ```
> การหมุนแต่ละครั้งต้องประมาณค่าพิกเซลใหม่ ถ้าหมุนภาพที่หมุนแล้วซ้ำ ๆ ความคลาดเคลื่อนจะ **สะสม** ภาพเบลอลงเรื่อย ๆ และกรอบโตขึ้นทุกครั้ง — รันจริงกับพื้นผิว 80×40: หมุนทีละ 10° สิบครั้งได้กรอบ **251×247** แต่หมุนจากต้นฉบับครั้งเดียว 100° ได้แค่ **53×85** การหมุนจากต้นฉบับด้วยมุมสะสม `self.angle` จึงได้ภาพคมชัดและขนาดถูกต้องเสมอ (ยานอวกาศบทที่ 6 ใช้หลักนี้)

### เทมเพลตคำตอบ: เขียนคลาสวัตถุในเกม
โจทย์ "จงเขียนคลาส X ที่มี `__init__`, `move`/`update` และ `draw`" ใช้โครงเดียวกันทุกครั้ง: **`__init__` เก็บพารามิเตอร์ลง `self.` ทุกตัว → `move` เปลี่ยนตำแหน่งด้วยความเร็วแล้วตรวจขอบ → `draw` เรียก `pygame.draw...` ด้วยค่าจาก `self`**

**คลาส `Rectangle` (`rect.py`) — สี่เหลี่ยมเคลื่อนที่แนวนอน**
```python
import pygame
SCREEN_WIDTH = 800

class Rectangle:
    def __init__(self, x, y, vx, size, color):    # ① รับค่าเริ่มต้นทั้งหมด
        self.x = x                                # มุมบนซ้าย (float ได้)
        self.y = y
        self.vx = vx                              # ความเร็วแนวนอน พิกเซล/เฟรม
        self.size = size                          # ด้านของสี่เหลี่ยมจัตุรัส
        self.color = color                        # ทูเพิล (R, G, B)

    def move(self):                               # ② อัปเดตตำแหน่งทุกเฟรม
        self.x += self.vx                         # เคลื่อนที่แนวนอนเท่านั้น
        if self.x <= 0 or self.x + self.size >= SCREEN_WIDTH:   # ขอบซ้าย = x, ขอบขวา = x + size
            self.vx = -self.vx                    # กลับทิศ

    def draw(self, screen):                       # ③ วาดด้วยค่าใน self
        pygame.draw.rect(screen, self.color,
                         (int(self.x), int(self.y), self.size, self.size))
```
```python
r = Rectangle(100, 300, 5, 40, (0, 255, 255))      # สร้างวัตถุ: ฟ้าอมเขียว ด้าน 40
while running:
    ...
    r.move()
    r.draw(screen)
```

**คลาส `Bullet` — กระสุนวิ่งขึ้นแบบความเร็วคงที่ วาดเป็นสี่เหลี่ยมจัตุรัส**
```python
YELLOW = (255, 255, 0)

class Bullet:
    def __init__(self, x, y, speed=8, size=6, color=YELLOW):   # ค่าเริ่มต้น (Default) ของพารามิเตอร์
        self.x = x
        self.y = y
        self.speed = speed
        self.size = size
        self.color = color
        self.alive = True

    def update(self):
        self.y -= self.speed                       # y ลด = ขึ้นบนจอ
        if self.y + self.size < 0:                 # ขอบล่างของกระสุนพ้นขอบบนจอแล้ว
            self.alive = False                     # ทำเครื่องหมายไว้ลบทิ้ง

    def draw(self, screen):
        pygame.draw.rect(screen, self.color,
                         (int(self.x), int(self.y), self.size, self.size))
```
ไล่ค่า: `b = Bullet(400, 500)` แล้ว `update()` 5 ครั้ง → y = 500 − 8×5 = **460** · ต้อง `update()` จนกว่า y + 6 < 0 คือ y ≤ −8 ซึ่งเกิดที่ครั้งที่ 64 (500 − 8×64 = −12; ครั้งที่ 63 ได้ −4 ซึ่ง −4 + 6 = 2 ยังไม่พ้น)

| ส่วนของคลาส | สิ่งที่ผู้ตรวจมองหา | ข้อผิดพลาดที่พบบ่อย |
|---|---|---|
| `def __init__(self, ...)` | เก็บทุกพารามิเตอร์เป็น `self.ชื่อ` | เขียน `x = x` (ไม่มี `self.`) ค่าหายเมื่อจบ `__init__` |
| `def move(self)` / `update(self)` | `self.x += self.vx` + ตรวจขอบถูกจุดอ้างอิง | ใช้ `x - size` กับสี่เหลี่ยม · ลืม `self` ในวงเล็บ |
| `def draw(self, screen)` | รับ `screen` เป็นพารามิเตอร์ ใช้ `int()` ตอนวาด | ลืมรับ `screen` · ใช้ `self.x` ที่เป็น float โดยไม่แปลง (ควร `int()`) · ใส่ `(x, y)` สลับกับ `(w, h)` |
| การสร้างวัตถุ | ส่งอาร์กิวเมนต์ครบตามลำดับ ไม่ต้องส่ง `self` | `Rectangle(self, 100, ...)` |

> > ```python

> >     def draw(self, screen):
> >         half = self.size / 2
> >         pygame.draw.rect(screen, self.color,
> >                          (int(self.x - half), int(self.y - half), self.size, self.size))
> > ```

> [!question]- ฝึกทำ: จงเขียนคลาส `Rectangle` ที่รับ x, y, vx, size, color มีเมท็อด `move()` เคลื่อนที่แนวนอนและสะท้อนเมื่อชนขอบซ้าย/ขวาของจอกว้าง `SCREEN_WIDTH` และ `draw(screen)` โดย (x, y) เป็นมุมบนซ้าย
> > [!success]- เฉลย
> > ```python
> > class Rectangle:
> >     def __init__(self, x, y, vx, size, color):
> >         self.x, self.y, self.vx = x, y, vx
> >         self.size, self.color = size, color
> >     def move(self):
> >         self.x += self.vx
> >         if self.x <= 0 or self.x + self.size >= SCREEN_WIDTH:
> >             self.vx = -self.vx
> >     def draw(self, screen):
> >         pygame.draw.rect(screen, self.color, (int(self.x), int(self.y), self.size, self.size))
> > ```
> > จุดที่ต้องได้: เงื่อนไขขอบซ้ายคือ `self.x <= 0` (ไม่ใช่ `self.x - self.size <= 0` ซึ่งยืมจากวงกลม) และ `draw` รับ `screen`

> [!question]- ฝึกทำ: `class Enemy(pygame.sprite.Sprite):` ที่ `__init__` ไม่ได้เรียก `super().__init__()` จะเกิดอะไรเมื่อ `all_sprites.add(Enemy())` และ `Enemy` เป็นอะไรของ `Sprite`
> > [!success]- เฉลย
> > `Enemy` เป็นคลาสลูกของ `Sprite` · เกิด `AttributeError: 'Enemy' object has no attribute '_Sprite__g'` ตอน `add` เพราะส่วนภายในของ Sprite (เซตของ Group) ไม่ได้ถูกสร้าง แก้โดยใส่ `super().__init__()` เป็นบรรทัดแรกของ `__init__`
