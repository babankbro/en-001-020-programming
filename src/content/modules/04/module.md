## 1. ลิสต์ซ้อนลิสต์แทนตาราง 2 มิติ

### จากลิสต์ 1 มิติสู่ตาราง
บทที่ 3 เก็บคะแนนของนักศึกษาหนึ่งคนในลิสต์ `ns = [5, 10, 15, 20, 30]` แต่ถ้ามีนักศึกษา 3 คน คนละ 4 วิชา เราต้องการ **ตาราง** ซึ่งในไพทอนทำได้โดยให้สมาชิกแต่ละตัวของลิสต์เป็นลิสต์อีกชั้นหนึ่ง

```python
scores = [[55, 63, 77, 81],      # แถว 0: นักศึกษาคนที่ 1
          [65, 61, 67, 72],      # แถว 1: นักศึกษาคนที่ 2
          [97, 95, 92, 88]]      # แถว 2: นักศึกษาคนที่ 3
subjects = ["Math", "Science", "English", "Computer"]
names = ["Somchai", "Somsri", "Sompong"]

print(scores[0])          # [55, 63, 77, 81]  ← แถว 0 ทั้งแถว (เป็นลิสต์)
print(scores[0][2])       # 77                ← แถว 0 คอลัมน์ 2
print(scores[2][0])       # 97                ← แถว 2 คอลัมน์ 0
print(len(scores))        # 3                 ← จำนวนแถว
print(len(scores[0]))     # 4                 ← จำนวนคอลัมน์ (ความยาวของแถวแรก)
```

| นิพจน์ | ค่า | ความหมาย |
|---|---|---|
| `scores[1]` | `[65, 61, 67, 72]` | แถวที่ 1 (ลิสต์ย่อย) |
| `scores[1][2]` | `67` | แถว 1 คอลัมน์ 2 |
| `scores[-1][-1]` | `88` | แถวสุดท้าย คอลัมน์สุดท้าย |
| `len(scores)` | `3` | จำนวนแถว |
| `len(scores[0])` | `4` | จำนวนคอลัมน์ |
| `type(scores[0])` | `<class 'list'>` | แถวเป็นลิสต์ |
| `type(scores[0][0])` | `<class 'int'>` | ช่องเป็นจำนวนเต็ม |

> [!important] อ่านดัชนีจากนอกเข้าใน
> `scores[i][j]` คือ "เอาแถว `i` มาก่อน (`scores[i]` ได้ลิสต์) แล้วค่อยเอาสมาชิกตำแหน่ง `j` ของแถวนั้น" ดัชนีตัวแรกคือ **แถว (row)** ตัวที่สองคือ **คอลัมน์ (column)** เสมอ สลับกันแล้วจะได้ค่าผิดหรือ `IndexError`

![ตารางคะแนน 3 แถว 4 คอลัมน์ ไฮไลต์แถว 1 คอลัมน์ 2 และช่อง scores[1][2] = 67 พร้อมค่าเฉลี่ยแถวและคอลัมน์](/infographics/04/table-indexing.svg)

กรอบน้ำเงินคือ `scores[1]` ทั้งแถว (ลิสต์ `[65, 61, 67, 72]` ของ Somsri) กรอบเขียวประคือคอลัมน์ `j = 2` (English) และช่องสีส้มที่ทั้งสองกรอบตัดกันคือ `scores[1][2] = 67` กล่องล่างซ้ายแสดงว่าการเข้าถึงเกิดขึ้น 2 ขั้น ส่วนตัวเลขสีม่วงด้านขวาและด้านล่างคือค่าเฉลี่ยแถว (หารด้วย 4 คอลัมน์) และค่าเฉลี่ยคอลัมน์ (หารด้วย 3 แถว) ที่จะคำนวณในหัวข้อย่อยถัดไป

### ไพทอนประเมิน `scores[1][2]` ทีละขั้น
ไพทอนไม่ได้มองว่า `[1][2]` เป็นพิกัดคู่เดียว แต่ทำการเข้าถึงด้วยดัชนี **สองครั้งต่อกันจากซ้ายไปขวา**
1. `scores` → ลิสต์ชั้นนอกที่มีสมาชิก 3 ตัว (แต่ละตัวเป็นลิสต์)
2. `scores[1]` → สมาชิกตัวที่ 1 ของชั้นนอก คือ `[65, 61, 67, 72]` (ผลลัพธ์ยังเป็นลิสต์ จึงต่อ `[...]` ได้อีก)
3. `[65, 61, 67, 72][2]` → สมาชิกตัวที่ 2 ของแถวนั้น คือ `67` (ผลลัพธ์เป็น `int` ต่อ `[...]` อีกไม่ได้แล้ว)

ดังนั้น `scores[3][0]` พังที่ขั้นที่ 2 (มีแค่แถว 0–2) และ `scores[0][4]` พังที่ขั้นที่ 3 (แถวมีแค่คอลัมน์ 0–3) — เมื่อเจอ `IndexError` ให้ถามว่า "ดัชนีตัวไหนเกิน" โดยไล่ทีละขั้นแบบนี้

### เชื่อมกับเมทริกซ์
ในคณิตศาสตร์ เมทริกซ์ (Matrix) ขนาด $m \times n$ มีสมาชิกแถว $i$ คอลัมน์ $j$ เขียนว่า $a_{ij}$ — ในโค้ดก็คือ `table[i][j]` (ต่างกันตรงที่คณิตศาสตร์เริ่มนับที่ 1 แต่ไพทอนเริ่มที่ 0) บทที่ 6 จะใช้ `np.array` แทนลิสต์ซ้อนลิสต์เพื่อคูณเมทริกซ์การหมุน และบทที่ 8 ใช้ `cells[row][col]` แบ่งจอเกมเป็นกริดเพื่อตรวจการชน

### วนซ้ำทุกช่องด้วยลูปซ้อน
```python
for i in range(len(scores)):            # วนทีละแถว
    for j in range(len(scores[i])):     # วนทีละคอลัมน์ในแถวนั้น
        print(scores[i][j], end=" ")
    print()                              # ขึ้นบรรทัดใหม่เมื่อครบแถว
```
```
55 63 77 81 
65 61 67 72 
97 95 92 88 
```
ลูปนอกคุมแถว ลูปในคุมคอลัมน์ — หลักเดียวกับ `block(row, col)` ในบทที่ 2 ที่เรียก `line(col)` ซ้ำ `row` ครั้ง

### สร้างตารางทีละแถว
```python
table = []
for r in range(3):
    row = []                     # สร้างแถวใหม่ทุกรอบ (สำคัญ!)
    for c in range(3):
        row.append(r * 3 + c + 1)
    table.append(row)
print(table)                     # [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
```

> [!danger] อย่าสร้างตารางด้วย `[[0] * 3] * 2`
> ```python
> grid = [[0] * 3] * 2
> grid[0][0] = 9
> print(grid)        # [[9, 0, 0], [9, 0, 0]]  ← เปลี่ยนทั้งสองแถว!
> ```
> `* 2` ไม่ได้สร้างแถวใหม่ แต่ให้ทั้งสองตำแหน่งชี้ไปที่ลิสต์ **ตัวเดียวกัน** ต้องใช้ `[[0] * 3 for _ in range(2)]` ซึ่งสร้างลิสต์ใหม่ทุกรอบ (เรื่องเดียวกับสำเนาตื้นในหัวข้อที่ 3)

### ค่าเฉลี่ยรายแถวและรายคอลัมน์
ค่าเฉลี่ยเลขคณิต $\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i$ เมื่อนำมาใช้กับตาราง

```python
# ค่าเฉลี่ยแต่ละแถว (คะแนนเฉลี่ยของนักศึกษาแต่ละคน)
for i in range(len(scores)):
    avg = sum(scores[i]) / len(scores[i])
    print(f"{names[i]}: {avg:.2f}")

# ค่าเฉลี่ยแต่ละคอลัมน์ (คะแนนเฉลี่ยของแต่ละวิชา) — ต้องเดินลงทีละแถวในคอลัมน์เดียวกัน
for j in range(len(scores[0])):
    total = 0
    for i in range(len(scores)):
        total += scores[i][j]
    print(f"{subjects[j]}: {total / len(scores):.2f}")
```
```
Somchai: 69.00
Somsri: 66.25
Sompong: 93.00
Math: 72.33
Science: 73.00
English: 78.67
Computer: 80.33
```

| | Math | Science | English | Computer | ผลรวมแถว | เฉลี่ยแถว |
|---|---|---|---|---|---|---|
| Somchai | 55 | 63 | 77 | 81 | 276 | 276/4 = 69.00 |
| Somsri | 65 | 61 | 67 | 72 | 265 | 265/4 = 66.25 |
| Sompong | 97 | 95 | 92 | 88 | 372 | 372/4 = 93.00 |
| **ผลรวมคอลัมน์** | 217 | 219 | 236 | 241 | | |
| **เฉลี่ยคอลัมน์** | 217/3 ≈ 72.33 | 73.00 | 236/3 ≈ 78.67 | 241/3 ≈ 80.33 | | |

เขียนแบบย่อด้วย List Comprehension ได้ว่า
```python
row_avgs = [sum(row) / len(row) for row in scores]                              # [69.0, 66.25, 93.0]
col_avgs = [sum(row[j] for row in scores) / len(scores) for j in range(len(scores[0]))]
```
ค่าเฉลี่ยแถวหารด้วย `len(row)` (จำนวนคอลัมน์ = 4) แต่ค่าเฉลี่ยคอลัมน์หารด้วย `len(scores)` (จำนวนแถว = 3) — อย่าสลับกัน

## 2. การจัดรูปแบบตารางด้วย f-string และความกว้างคอลัมน์

### ปัญหา: คอลัมน์ไม่ตรงกัน
ถ้าพิมพ์ `print(item, end=" | ")` ตรง ๆ ค่า `7` กับ `12345` จะกินพื้นที่ไม่เท่ากัน ตารางจึงเบี้ยว วิธีแก้คือ **หาความกว้างที่เหมาะสมของแต่ละคอลัมน์** แล้วเติมช่องว่างให้ทุกค่ากว้างเท่ากัน

### ตัวระบุรูปแบบใน f-string (Format Specification)
| รูปแบบ | ผลลัพธ์ (`w = 8`) | ความหมาย |
|---|---|---|
| `f"[{'Math':<{w}}]"` | `[Math    ]` | ชิดซ้าย กว้าง 8 |
| `f"[{'Math':>{w}}]"` | `[    Math]` | ชิดขวา กว้าง 8 |
| `f"[{'Math':^{w}}]"` | `[  Math  ]` | กึ่งกลาง กว้าง 8 |
| `f"[{77:>5}]"` | `[   77]` | ตัวเลขชิดขวา กว้าง 5 |
| `f"{217/3:.2f}"` | `72.33` | ทศนิยม 2 ตำแหน่ง |
| `f"{217/3:8.2f}"` | `   72.33` | กว้าง 8 ทศนิยม 2 |

จุดสำคัญคือ **ความกว้างใส่เป็นตัวแปรได้** โดยซ้อนปีกกา `{w}` ไว้หลังเครื่องหมาย `<` — ทำให้เขียนฟังก์ชันพิมพ์ตารางที่ปรับความกว้างตามข้อมูลจริงได้

### หาความกว้างคอลัมน์ (`exam_table.py`)
```python
num_cols = len(table[0])
col_widths = [max(len(str(row[i])) for row in table) for i in range(num_cols)]
line_length = sum(col_widths) + (num_cols * 3)     # 3 = ความยาวของ " | "
```
อ่าน `col_widths` จากในออกนอก: สำหรับคอลัมน์ `i` แต่ละคอลัมน์ → หยิบ `row[i]` จากทุกแถว → แปลงเป็นสายอักขระด้วย `str()` → วัดความยาวด้วย `len()` → เลือกค่า **มากที่สุด** ด้วย `max()` ได้ความกว้างที่ค่ายาวสุดในคอลัมน์นั้นยังพอดี

> [!note] ทำไมต้อง `str()` ก่อน `len()`
> `len(77)` เกิด `TypeError` เพราะจำนวนเต็มไม่มีความยาว ต้องแปลงเป็น `"77"` ก่อนจึงนับได้ 2 ตัวอักษร และในขั้นพิมพ์ก็ใช้ `str(item)` ด้วยเหตุผลเดียวกัน (ค่าในตารางอาจปนกันทั้งตัวเลขและข้อความ)

ตัวอย่างไล่ค่า `t = [["ID", "Score"], [7, 100], [12345, 9]]`

| คอลัมน์ | ค่าในคอลัมน์ | ความยาวหลัง `str()` | `max` |
|---|---|---|---|
| 0 | `"ID"`, `7`, `12345` | 2, 1, 5 | 5 |
| 1 | `"Score"`, `100`, `9` | 5, 3, 1 | 5 |

ได้ `col_widths = [5, 5]` และ `line_length = (5 + 5) + 2 × 3 = 16`

### ฟังก์ชันพิมพ์ตาราง
```python
def print_table(table):
    num_cols = len(table[0])
    col_widths = [max(len(str(row[i])) for row in table) for i in range(num_cols)]
    line_length = sum(col_widths) + (num_cols * 3)
    print("-" * line_length)                            # เส้นบน
    for row in table:
        for i, item in enumerate(row):                  # i = ดัชนีคอลัมน์, item = ค่า
            print(f"{str(item):<{col_widths[i]}}", end=" | ")
        print()
    print("-" * line_length)                            # เส้นล่าง

print_table(scores)
```
```
--------------------
55 | 63 | 77 | 81 | 
65 | 61 | 67 | 72 | 
97 | 95 | 92 | 88 | 
--------------------
```
ทุกค่าเป็นเลข 2 หลัก จึงได้ `col_widths = [2, 2, 2, 2]` และ `line_length = 8 + 4 × 3 = 20` ตรงกับความยาวเส้นประ 20 ตัว

![ขั้นตอนคำนวณ col_widths ของตารางที่มีหัวตาราง จากความยาวของแต่ละช่อง ไปสู่ max ของแต่ละคอลัมน์ และ line_length = 48](/infographics/04/col-widths.svg)

ภาพนี้ใช้ตารางที่มีหัวคอลัมน์และชื่อนักศึกษา (ซึ่งจะสร้างในหัวข้อที่ 3) เพราะความกว้างแต่ละคอลัมน์ไม่เท่ากันจึงเห็นกลไกชัดกว่า ขั้นที่ 1 เขียน `len(str(ค่า))` ไว้มุมขวาของทุกช่อง ขั้นที่ 2 เลือกค่ามากสุดของแต่ละคอลัมน์ (ช่องกรอบส้ม) ได้ `col_widths = [7, 4, 7, 7, 8]` ขั้นที่ 3 คำนวณ `line_length` และขั้นที่ 4 แสดงแถวหัวตารางที่พิมพ์จริงทีละตัวอักษร ช่องฟ้าคือค่าที่เติมช่องว่างจนกว้างเท่า `col_widths[i]` ช่องเทาคือตัวคั่น `" | "` ผลรวมทุกช่วงเท่ากับ 48 พอดี

### ไล่ comprehension ของ `col_widths` ทีละชั้น
บรรทัด `[max(len(str(row[i])) for row in table) for i in range(num_cols)]` มีลูปสองชั้น อ่านจาก **ลูปนอกสุดทางขวา** ก่อน
1. `for i in range(num_cols)` → เลือกคอลัมน์ทีละคอลัมน์ `i = 0, 1, 2, …` (ลูปนอก ได้สมาชิก 1 ตัวของผลลัพธ์ต่อคอลัมน์)
2. `for row in table` → ในคอลัมน์ `i` เดินลงทุกแถว (ลูปใน)
3. `row[i]` → หยิบค่าคอลัมน์ `i` ของแถวนั้น → `str(...)` → `len(...)` ได้ความยาวหนึ่งตัวเลขต่อแถว
4. `max(...)` → เลือกความยาวมากสุดจากทุกแถว → ได้ความกว้างของคอลัมน์ `i`

เขียนเป็นลูปธรรมดาที่ให้ผลเหมือนกันได้ดังนี้ (เหมาะสำหรับไล่ค่าด้วยมือ)
```python
col_widths = []
for i in range(num_cols):            # ลูปนอก: ทีละคอลัมน์
    w = 0
    for row in table:                # ลูปใน: ทีละแถวในคอลัมน์ i
        w = max(w, len(str(row[i])))
    col_widths.append(w)
```

### `enumerate()` ให้ทั้งดัชนีและค่า
ลูป `for i, item in enumerate(row)` ได้ `i` (0, 1, 2, …) ไว้เลือก `col_widths[i]` และ `item` ไว้พิมพ์ในรอบเดียว แทนการเขียน `for i in range(len(row)): item = row[i]` — เราต้องการดัชนีเพราะ **ความกว้างของแต่ละคอลัมน์ไม่เท่ากัน**

> [!tip] ทำไม `line_length` ต้องบวก `num_cols * 3`
> แต่ละคอลัมน์พิมพ์ค่ากว้าง `col_widths[i]` แล้วตามด้วย `" | "` อีก 3 ตัวอักษร ดังนั้นความยาวบรรทัดจริง = ผลรวมความกว้าง + 3 × จำนวนคอลัมน์ ถ้าเปลี่ยนตัวคั่นเป็น `"|"` ต้องเปลี่ยน 3 เป็น 1 ด้วย

> [!question]- ฝึกทำ: `print(f"{str(77):<5}|{'ab':>4}|")` แสดงผลอะไร (นับช่องว่างให้ถูก)
> > [!success]- เฉลย
> > `77   |  ab|` — `77` ชิดซ้ายเติมช่องว่าง 3 ตัวให้ครบ 5, `ab` ชิดขวาเติมช่องว่าง 2 ตัวให้ครบ 4

> [!question]- ฝึกทำ: ตาราง `[["Name", "Score"], ["Somchai", 100], ["Bo", 7]]` มี `col_widths` และ `line_length` เท่าใด
> > [!success]- เฉลย
> > คอลัมน์ 0: 4, 7, 2 → 7; คอลัมน์ 1: 5, 3, 1 → 5 → `[7, 5]` และ `line_length = 12 + 6 = 18`

## 3. สำเนาตื้นและการแทรกหัวตาราง

### เป้าหมาย: เติมชื่อวิชาและชื่อนักศึกษา
ตาราง `scores` มีแต่ตัวเลข เราอยากได้ตารางที่มีหัวคอลัมน์ `Name | Math | …` และชื่อนักศึกษาหน้าแต่ละแถว **โดยไม่แก้ `scores` ต้นฉบับ** (เพราะยังต้องใช้คำนวณต่อ) โค้ดในคาบจึงเริ่มจาก `copy()`

```python
subject_show = subjects.copy()
subject_show.insert(0, "Name")        # ['Name', 'Math', 'Science', 'English', 'Computer']

    table_show[i + 1].insert(0, names[i])   # แทรกชื่อหน้าแถวที่ i+1 (เลื่อนเพราะมีหัวตาราง)

print_table(table_show)
```

`col_widths = [7, 4, 7, 7, 8]` (จาก `Somchai`, `Math`, `Science`, `English`, `Computer`) และ `line_length = 33 + 5 × 3 = 48` ตารางสวยตามต้องการ — แต่ลองพิมพ์ `scores` ดู


> [!warning] สำเนาตื้น (Shallow Copy)
> `scores.copy()` สร้างลิสต์ชั้นนอกใหม่ก็จริง แต่สมาชิกข้างในคือ **ลิสต์แถวตัวเดิม** (`table_show[1] is scores[0]` ได้ `True`) ดังนั้น `table_show[i + 1].insert(0, names[i])` จึงแทรกชื่อลงในแถวที่ `scores` ใช้ร่วมกันอยู่ — ต้นฉบับเปลี่ยนตามโดยไม่รู้ตัว ส่วน `subjects` ไม่เปลี่ยนเพราะ `subject_show.insert(...)` แก้ลิสต์ชั้นนอกที่เป็นสำเนาจริง

![แผนภาพหน่วยความจำของสำเนาตื้น: scores และ table_show มีลิสต์ชั้นนอกแยกกัน แต่ชี้ไปที่ลิสต์แถวทั้งสามตัวเดียวกัน](/infographics/04/shallow-copy.svg)

ให้มองตัวแปรเป็น "ป้ายชื่อ" และลิสต์เป็น "กล่อง" ที่มีช่องเก็บลูกศรชี้ไปยังกล่องอื่น `scores.copy()` สร้างกล่องชั้นนอกใบใหม่ (สีส้ม) ให้ `table_show` แต่ช่องในกล่องใหม่คัดลอกมาแค่ **ลูกศร** จึงชี้ไปยังลิสต์แถวทั้งสามตัวเดิมที่กล่องสีน้ำเงินของ `scores` ชี้อยู่ ช่องสีแดงคือชื่อที่ถูกแทรกผ่าน `table_show` ซึ่งปรากฏใน `scores` ด้วยเพราะเป็นกล่องเดียวกัน มีเพียงลิสต์หัวตาราง (ช่อง `[0]` ของ `table_show`) ที่เป็นของ `table_show` คนเดียว

### ไล่ทีละบรรทัดว่าอะไรถูกแก้
| บรรทัด | แก้กล่องไหน | `scores` เปลี่ยนไหม |
|---|---|---|
| `table_show = scores.copy()` | สร้างกล่องชั้นนอกใหม่ 3 ช่อง ชี้แถวเดิม | ไม่ |
| `table_show.insert(0, subject_show)` | กล่องชั้นนอกของ `table_show` (เพิ่มเป็น 4 ช่อง) | ไม่ (กล่องชั้นนอกของ `scores` ยังมี 3 ช่อง) |
| `table_show[1].insert(0, "Somchai")` | ลิสต์แถว 0 ซึ่ง `scores[0]` ก็ชี้อยู่ | **เปลี่ยน** |
| `table_show[2].insert(0, "Somsri")` | ลิสต์แถว 1 = `scores[1]` | **เปลี่ยน** |
| `table_show[3].insert(0, "Sompong")` | ลิสต์แถว 2 = `scores[2]` | **เปลี่ยน** |

หลักตรวจสอบ: ถ้าคำสั่งมีดัชนีชั้นนอกนำหน้า เช่น `table_show[1].insert(...)` แปลว่ากำลังแก้ **กล่องชั้นใน** ซึ่งสำเนาตื้นใช้ร่วมกับต้นฉบับ ตรวจได้ทันทีด้วย `table_show[1] is scores[0]` (ได้ `True`)

### ภาพจำ: สำเนาตื้นคัดลอกแค่ "กล่องนอก"
| คำสั่ง | ลิสต์ชั้นนอก | ลิสต์ชั้นใน (แถว) |
|---|---|---|
| `b = a` | ตัวเดียวกัน | ตัวเดียวกัน |
| `b = a.copy()` หรือ `a[:]` | **ใหม่** | ตัวเดียวกัน (ตื้น) |
| `b = copy.deepcopy(a)` | ใหม่ | **ใหม่** (ลึก) |

```python
a = [[1, 2], [3, 4]]
b = a.copy()
b.append([5, 6])      # แก้ชั้นนอกของ b → a ไม่เปลี่ยน
b[0].append(9)        # แก้ชั้นในที่ใช้ร่วมกัน → a เปลี่ยนด้วย
print(a)              # [[1, 2, 9], [3, 4]]
print(b)              # [[1, 2, 9], [3, 4], [5, 6]]
```
กฎง่าย ๆ: การ `append`/`insert` ที่ **ชั้นนอก** ของสำเนาตื้นปลอดภัย แต่การแก้ **ชั้นใน** กระทบต้นฉบับ

### วิธีแก้
```python
import copy
table_show = copy.deepcopy(scores)              # วิธี 1: สำเนาลึก
table_show.insert(0, ["Name"] + subjects)       # ["Name"] + subjects สร้างลิสต์ใหม่โดยไม่แตะ subjects
```

เรื่องนี้จะกลับมาในเกม: ถ้าเก็บลูกบอลหลายลูกในลิสต์แล้วใช้ `balls[:]` วนซ้ำเพื่อลบ (บทที่ 8) นั่นคือสำเนาตื้นที่ **ตั้งใจ** ให้วัตถุข้างในเป็นตัวเดียวกัน

## 4. สแตก (Stack) แบบฟังก์ชันและแบบคลาส

### หลักการ LIFO
สแตก (Stack) คือโครงสร้างข้อมูลแบบ **เข้าหลังออกก่อน (Last-In, First-Out: LIFO)** เหมือนจานที่วางซ้อนกัน จานที่วางล่าสุดอยู่บนสุดและถูกหยิบออกก่อน ไพทอนไม่มีชนิดสแตกโดยตรง แต่ลิสต์ที่ใช้เฉพาะ `append()` และ `pop()` ที่ **ท้ายลิสต์** ก็คือสแตก

| การดำเนินการ | ความหมาย | ลิสต์ไพทอน |
|---|---|---|
| `push(x)` | วางข้อมูลบนสุด | `items.append(x)` |
| `pop()` | นำข้อมูลบนสุดออกและคืนค่า | `items.pop()` |
| `peek()` | ดูข้อมูลบนสุดโดยไม่นำออก | `items[-1]` |
| `is_empty()` | ตรวจว่าว่างหรือไม่ | `len(items) == 0` |
| `size()` | จำนวนข้อมูล | `len(items)` |

### แบบฟังก์ชัน (`test_stack.py`)
```python
def spush(stack, item):
    stack.append(item)

def spop(stack):
    return stack.pop()

s = []
spush(s, 'x'); spush(s, 'y'); spush(s, 'z')
print(s)              # ['x', 'y', 'z']  ← 'z' อยู่บนสุด (ท้ายลิสต์)
print(spop(s), s)     # z ['x', 'y']
```
ใช้ได้ แต่ข้อมูล (`s`) กับฟังก์ชัน (`spush`, `spop`) แยกกันอยู่ ใครก็เรียก `s.insert(0, ...)` ทำลายกฎ LIFO ได้ และต้องส่ง `s` เป็นอาร์กิวเมนต์ทุกครั้ง

### แบบคลาส (`stack_v2.py`)
**คลาส (Class)** คือแม่แบบที่รวม **ข้อมูล** (แอตทริบิวต์ `self.items`) และ **พฤติกรรม** (เมท็อด `push`, `pop`, …) ไว้ด้วยกัน ส่วน **วัตถุ (Object)** คือสิ่งที่สร้างจากคลาส เช่น `m = Stack()`

```python
class Stack:
    def __init__(self):                 # คอนสตรักเตอร์: ทำงานอัตโนมัติเมื่อ Stack()
        self.items = []                 # แอตทริบิวต์: ลิสต์เก็บข้อมูลของวัตถุตัวนี้

    def push(self, item):
        self.items.append(item)

    def pop(self):
        if not self.items:              # ลิสต์ว่างมีค่าความจริงเป็น False
            raise IndexError("pop from empty stack")
        return self.items.pop()

    def peek(self):
        if not self.items:
            raise IndexError("peek from empty stack")
        return self.items[-1]

    def is_empty(self):
        return len(self.items) == 0

    def size(self):
        return len(self.items)

m = Stack()
print(m.is_empty(), m.size())     # True 0
m.push('x'); m.push('y'); m.push('z')
print(m.items, m.peek())          # ['x', 'y', 'z'] z
print(m.pop(), m.items)           # z ['x', 'y']
```
- `self` คือ **วัตถุตัวที่กำลังเรียกเมท็อด** — `m.push('x')` ไพทอนส่ง `m` เข้าไปเป็น `self` ให้เอง จึงเขียน `m.push('x')` ไม่ใช่ `m.push(m, 'x')`
- วัตถุแต่ละตัวมี `items` ของตัวเอง: `a = Stack(); b = Stack()` แล้ว `a.push(1)` ไม่กระทบ `b`
- `raise IndexError("...")` คือ **การยกข้อผิดพลาด (Raise Exception)** เพื่อหยุดโปรแกรมพร้อมบอกสาเหตุ แทนที่จะปล่อยให้ `[].pop()` พังด้วยข้อความที่เข้าใจยากกว่า

บทนี้แนะนำคลาสเพียงเท่าที่ใช้กับสแตก เรื่อง `__init__` ที่รับพารามิเตอร์ การสืบทอด และ `super()` อยู่ใน [บท 05](/module/05) และทบทวนพื้นฐานได้ที่ [EN-001-002 บท 08 คลาสและวัตถุ](https://en-001-002-computer-programming.vercel.app/module/08)

### ไล่ลำดับการทำงานเป็นตาราง
| คำสั่ง | `items` หลังทำ | ค่าที่คืน |
|---|---|---|
| `push('x')` | `['x']` | |
| `push('y')` | `['x', 'y']` | |
| `pop()` | `['x']` | `'y'` |
| `push('z')` | `['x', 'z']` | |
| `peek()` | `['x', 'z']` | `'z'` |
| `size()` | `['x', 'z']` | `2` |

![ลำดับเฟรมของสแตก push x y z แล้ว pop สองครั้ง และไทม์ไลน์บั๊ก pop สองครั้งต่อรอบใน stack_v2.py](/infographics/04/stack-lifo.svg)

ครึ่งบนวาดสแตกเป็นถังเปิดด้านบน ช่องล่างสุดคือ `items[0]` (ก้นสแตก) และช่องที่กรอบเข้มคือ `items[-1]` (บนสุด) เมื่อ push ข้อมูลใหม่วางทับด้านบน เมื่อ pop ค่าบนสุดหลุดออกไป (กล่องแดงประ) ลำดับที่ออกจึงกลับกับลำดับที่เข้า ครึ่งล่างคือไทม์ไลน์ของ `stack_v2.py` สีม่วงคือจังหวะที่ `while` ตรวจเงื่อนไข สีน้ำเงินคือ pop ที่สำเร็จ และสีแดงคือ pop ครั้งที่ 4 ที่เกิดขึ้นหลังสแตกว่างโดยไม่มีการตรวจคั่นกลาง

### ทำไม pop ต้องทำที่ท้ายลิสต์
ลิสต์ไพทอนมีทั้ง `pop()` (ท้าย) และ `pop(0)` (หน้า) แต่สแตกเลือกใช้ท้ายลิสต์เป็น "บนสุด" ด้วยเหตุผล 2 ข้อ
1. **ความถูกต้อง**: ถ้า push ด้วย `append` (ท้าย) แต่ pop ด้วย `pop(0)` (หน้า) จะได้ค่าที่เข้า **ก่อน** ออกก่อน ซึ่งเป็นคิว (Queue, FIFO) ไม่ใช่สแตก
2. **ความเร็ว**: จากบทที่ 3 `pop(0)` ทำให้สมาชิกที่เหลือทุกตัวต้องเลื่อนดัชนี แต่ `pop()` ที่ท้ายไม่ต้องเลื่อนตัวใดเลย สแตกที่มีข้อมูลมากจึงยังทำงานเร็ว

> [!bug] ข้อผิดพลาดใน `stack_v2.py`
> ```python
> m = Stack()
> m.push('x'); m.push('y'); m.push('z')
> while not m.is_empty():
>     print(m.pop())
>     print(m.pop())        # pop ครั้งที่สองในรอบเดียวกัน
> ```
> ```
> z
> y
> x
> IndexError: pop from empty stack
> ```
> รอบที่ 1: สแตกมี 3 ตัว pop ได้ `z` แล้ว `y` เหลือ `['x']` → เงื่อนไข `not is_empty()` ยังจริง → รอบที่ 2: pop ได้ `x` สแตกว่าง แล้ว **pop อีกครั้งโดยไม่ได้ตรวจ** จึง `raise IndexError` เพราะเงื่อนไขของ `while` ตรวจแค่ **ต้นรอบ** ไม่ได้ตรวจก่อน pop ทุกครั้ง แก้โดยเหลือ `print(m.pop())` บรรทัดเดียวต่อรอบ หรือตรวจ `is_empty()` ก่อน pop ครั้งที่สอง

### การประยุกต์
**1. กลับลำดับข้อมูล** — push ทุกตัวแล้ว pop ออกจะได้ลำดับย้อนกลับ
```python
def reverse(text):
    s = Stack()
    for ch in text:
        s.push(ch)
    out = ""
    while not s.is_empty():
        out += s.pop()
    return out

print(reverse("ABC"))      # CBA
print(reverse("Python"))   # nohtyP
```

**2. ตรวจวงเล็บสมดุล** — push เมื่อพบ `(` และ pop เมื่อพบ `)` ถ้า pop ตอนว่างแปลว่ามี `)` เกิน ถ้าจบแล้วไม่ว่างแปลว่ามี `(` เกิน
```python
def balanced(text):
    s = Stack()
    for ch in text:
        if ch == "(":
            s.push(ch)
        elif ch == ")":
            if s.is_empty():       # มี ) ก่อน ( → ไม่สมดุล
                return False
            s.pop()
    return s.is_empty()            # เหลือ ( ค้าง → ไม่สมดุล

print(balanced("(a+b)*(c-d)"))     # True
print(balanced("((a+b)"))          # False  (เหลือ '(' 1 ตัว)
print(balanced("a+b)("))           # False  (pop ตอนว่าง)
```

| ข้อความ | ลำดับ `items` | ผล |
|---|---|---|
| `(a+b)*(c-d)` | `['(']` → `[]` → `['(']` → `[]` | ว่างตอนจบ → `True` |
| `((a+b)` | `['(']` → `['(', '(']` → `['(']` | เหลือ 1 → `False` |
| `a+b)(` | `[]` แล้วพบ `)` | pop ตอนว่าง → `False` |

**3. ปุ่มย้อนกลับ (Undo/Back)** — เก็บสถานะล่าสุดไว้บนสุด กด Undo = pop; ในเกม ลำดับหน้าจอ (เมนู → เล่น → หยุดชั่วคราว) ก็จัดการด้วยสแตกได้

> [!question]- ฝึกทำ: เริ่มจากสแตกว่าง ทำ `push(1), push(2), push(3), pop(), push(4), pop(), pop()` ค่าที่ pop ได้ตามลำดับคืออะไร และเหลืออะไรในสแตก
> > [!success]- เฉลย
> > pop ได้ `3, 4, 2` ตามลำดับ เหลือ `[1]`

> [!question]- ฝึกทำ: จงบอกผลลัพธ์
> ```python
> s = Stack()
> for v in [10, 20, 30]:
>     s.push(v)
> s.pop()
> s.push(40)
> print(s.peek(), s.size(), s.is_empty())
> ```
> > [!success]- เฉลย
> > `40 3 False` — หลัง pop เหลือ `[10, 20]` push 40 ได้ `[10, 20, 40]`

> [!question]- ฝึกทำ: ถ้าลบ `if not self.items: raise IndexError(...)` ออกจาก `pop()` แล้ว pop สแตกว่าง จะเกิดอะไร
> > [!success]- เฉลย
> > ยังเกิด `IndexError` อยู่ดี แต่ข้อความเป็น `pop from empty list` ของลิสต์ภายใน — การ raise เองทำให้ข้อความสื่อว่าเป็น "สแตก" และตรวจเงื่อนไขได้ชัดเจน (สำหรับ `peek()` ถ้าไม่ตรวจจะได้ `list index out of range`)

## 5. การหารปัดลง มอดุโล และตารางบนเว็บด้วย pandas

### `//` และ `%` กับตาราง
สำหรับจำนวนเต็ม $a$ และ $b > 0$ มีผลหาร $q$ และเศษ $r$ ชุดเดียวที่ทำให้
$$a = b \cdot q + r, \qquad 0 \le r < b$$
`a // b` คือ $q = \lfloor a/b \rfloor$ (ปัด **ลง** เสมอ ไม่ใช่ปัดเข้าหาศูนย์) และ `a % b` คือ $r$ ซึ่งมีเครื่องหมายเดียวกับตัวหาร

| นิพจน์ | ผลลัพธ์ | เหตุผล |
|---|---|---|
| `7 // 2`, `7 % 2` | `3`, `1` | $7 = 2 \cdot 3 + 1$ |
| `-7 // 2`, `-7 % 2` | `-4`, `1` | $\lfloor -3.5 \rfloor = -4$, $-7 = 2 \cdot (-4) + 1$ |
| `17 // 5`, `17 % 5` | `3`, `2` | $17 = 5 \cdot 3 + 2$ |
| `-17 // 5`, `-17 % 5` | `-4`, `3` | $-17 = 5 \cdot (-4) + 3$ |
| `-340 % 360` | `20` | ใช้ทำมุมให้อยู่ในช่วง 0–359 (บทที่ 7) |

**แปลงดัชนี 1 มิติเป็น (แถว, คอลัมน์)** — ถ้าเรียงช่องของตาราง 4 คอลัมน์ต่อกันเป็นลำดับ $k = 0, 1, 2, \dots$ จะได้
$$\text{row} = k \,//\, \text{cols}, \qquad \text{col} = k \,\%\, \text{cols}$$

| $k$ | `k // 4` (แถว) | `k % 4` (คอลัมน์) | `scores[row][col]` |
|---|---|---|---|
| 0 | 0 | 0 | 55 |
| 3 | 0 | 3 | 81 |
| 4 | 1 | 0 | 65 |
| 6 | 1 | 2 | 67 |
| 9 | 2 | 1 | 95 |
| 11 | 2 | 3 | 88 |

```python
flat = [55, 63, 77, 81, 65, 61, 67, 72, 97, 95, 92, 88]
k = 9
print(flat[k], scores[k // 4][k % 4])     # 95 95
```
สูตรเดียวกันนี้ใช้ในเกม: `WIDTH // 2, HEIGHT // 2` หาจุดกึ่งกลางจอ (400, 300) ในบทที่ 5, `col = x // cell_size` หาช่องกริดที่วัตถุอยู่ในบทที่ 8 และ `if time_steps % k == 0:` ทำงานทุก ๆ $k$ เฟรม

> [!warning] อย่าใช้ `//` หาค่าเฉลี่ย
> `265 // 4 = 66` แต่ค่าเฉลี่ยจริงคือ `265 / 4 = 66.25` — `//` ใช้เมื่อต้องการ **ดัชนี** หรือ **จำนวนเต็ม** เช่น แถว/คอลัมน์/พิกเซล เท่านั้น

### ตารางบนเว็บด้วย pandas และ Streamlit (`steamlit_table.py`)
ลิสต์ซ้อนลิสต์แปลงเป็น **DataFrame** ของ pandas ได้โดยตรง โดยระบุชื่อคอลัมน์และชื่อแถว

```python
import pandas as pd
df = pd.DataFrame(scores, columns=subjects, index=names)
print(df)
print(df.shape)             # (3, 4) = (จำนวนแถว, จำนวนคอลัมน์)
print(df.mean())            # ค่าเฉลี่ยแต่ละคอลัมน์
```
```
         Math  Science  English  Computer
Somchai    55       63       77        81
Somsri     65       61       67        72
Sompong    97       95       92        88
(3, 4)
Math        72.333333
Science     73.000000
English     78.666667
Computer    80.333333
dtype: float64
```
`df.mean()` ให้ค่าตรงกับ `col_avgs` ที่คำนวณเองในหัวข้อที่ 1 (ค่าเริ่มต้นหาเฉลี่ยลงตามคอลัมน์ ส่วน `df.mean(axis=1)` หาเฉลี่ยตามแถว ได้ 69.00, 66.25, 93.00) และ `df.loc["Somsri", "English"]` คือ `scores[1][2] = 67`

```python
import streamlit as st
st.title("Score Table")
st.dataframe(df)            # ตารางโต้ตอบได้: เรียงลำดับ ค้นหา ขยายคอลัมน์
```
รันด้วย `streamlit run steamlit_table.py` แล้วเบราว์เซอร์จะเปิดหน้าเว็บที่แสดงตารางให้คลิกเรียงตามคอลัมน์ได้ — `print_table` ของเราคือการทำสิ่งเดียวกันด้วยมือบนเทอร์มินัล ซึ่งช่วยให้เข้าใจว่าไลบรารีทำอะไรอยู่เบื้องหลัง

| | `print_table` (เขียนเอง) | `pd.DataFrame` + `st.dataframe` |
|---|---|---|
| หัวตาราง | แทรกเองด้วย `insert` | `columns=`, `index=` |
| ความกว้างคอลัมน์ | คำนวณ `col_widths` | อัตโนมัติ |
| ค่าเฉลี่ยคอลัมน์ | ลูปซ้อน / comprehension | `df.mean()` |
| แสดงผล | เทอร์มินัล | เว็บเบราว์เซอร์ |

> [!question]- ฝึกทำ: ตารางมี 5 คอลัมน์ ช่องลำดับที่ $k = 13$ อยู่แถวและคอลัมน์ใด และ `-13 // 5`, `-13 % 5` เท่าใด
> > [!success]- เฉลย
> > แถว `13 // 5 = 2` คอลัมน์ `13 % 5 = 3`; `-13 // 5 = -3` (ปัดลงจาก −2.6) และ `-13 % 5 = 2` เพราะ $-13 = 5 \cdot (-3) + 2$

> [!question]- ฝึกทำ: `pd.DataFrame(scores, columns=subjects, index=names)` ถ้า `subjects` มี 3 ชื่อแต่ `scores` มี 4 คอลัมน์ จะเกิดอะไร
