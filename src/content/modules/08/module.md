> [!abstract] สาระสำคัญ
> บทสุดท้ายของเกมยิงยานอวกาศ: ยานยิง **กระสุน (Bullet)** ไปยังตำแหน่งเมาส์ด้วย **เวกเตอร์หนึ่งหน่วย (Unit Vector)** ตรวจว่ากระสุนโดนศัตรูหรือไม่ด้วย **กล่องขอบเขต (Axis-Aligned Bounding Box: AABB)** ลบกระสุนและศัตรูที่ถูกยิงออกจาก **ลิสต์อย่างปลอดภัย** และเมื่อศัตรูมีเป็นพันตัว การตรวจทุกคู่จะช้าเกินไป จึงต้อง **แบ่งพื้นที่เป็นกริด (Spatial Grid)** แล้ววิเคราะห์ด้วย **สัญกรณ์บิ๊กโอ (Big-O)** และวัดผลจริงด้วย `clock.get_fps()`

## 1. ยิงกระสุนไปยังเมาส์ด้วยเวกเตอร์หนึ่งหน่วย

### จากตำแหน่งสองจุดสู่ทิศทาง
ในบทที่ 7 ศัตรูสีแดงไล่ตามผู้เล่นด้วยเวกเตอร์ "ผู้เล่น − ศัตรู" บทนี้ใช้หลักเดียวกัน: **เวกเตอร์จากยานไปเมาส์ = ตำแหน่งเมาส์ − ตำแหน่งยาน**

```python
mouse_x, mouse_y = pygame.mouse.get_pos()        # ตำแหน่งเมาส์บนจอ
dx = mouse_x - space.rect.centerx                 # เวกเตอร์จากยานไปเมาส์
dy = mouse_y - space.rect.centery
direction = pygame.math.Vector2(dx, dy).normalize()   # ทำให้ขนาดเป็น 1 (เหลือแต่ทิศ)
bullet_vx = direction.x * bullet_speed            # คูณอัตราเร็วที่ต้องการ
bullet_vy = direction.y * bullet_speed
```

$$\hat{\mathbf{d}} = \frac{\mathbf{d}}{|\mathbf{d}|}, \qquad \mathbf{v}_{bullet} = \hat{\mathbf{d}} \times \text{bullet\_speed}$$

### ตัวอย่างไล่ค่า: ยานที่ (400, 300) เมาส์ที่ (460, 380) และ `bullet_speed = 10`
| ขั้น | การคำนวณ | ผลลัพธ์ |
|---|---|---|
| 1. เวกเตอร์ยาน → เมาส์ | $(460-400,\ 380-300)$ | $(60, 80)$ |
| 2. ขนาด | $\sqrt{60^2 + 80^2} = \sqrt{10000}$ | $100$ |
| 3. normalize | $(60/100,\ 80/100)$ | $(0.6, 0.8)$ |
| 4. คูณอัตราเร็ว | $(0.6 \times 10,\ 0.8 \times 10)$ | $(6, 8)$ |

ตรวจสอบ: ขนาดของ $(6, 8) = \sqrt{36 + 64} = 10$ = `bullet_speed` พอดี — **ทุกนัดเร็วเท่ากันไม่ว่าเมาส์จะอยู่ใกล้หรือไกล** นี่คือเหตุผลที่ต้อง normalize ก่อน ถ้าใช้ $(dx, dy)$ ตรง ๆ กระสุนจะวิ่ง 60 และ 80 พิกเซลต่อเฟรม และยิ่งเมาส์ไกลยิ่งเร็ว

> [!warning] ห้าม normalize เวกเตอร์ศูนย์
> ถ้าเมาส์อยู่ตรงกลางยานพอดี $(dx, dy) = (0, 0)$ ขนาดเป็น 0 `normalize()` จะเกิด `ValueError` ต้องตรวจ `if direction.length() > 0:` ก่อนเสมอ (เช่นเดียวกับ `input_dir` ในบทที่ 6)

### กระสุนเคลื่อนที่ด้วยความเร็วคงที่ (`bullet.py`)
```python
class Bullet(pygame.sprite.Sprite):
    def __init__(self, x, y, vx, vy):
        super().__init__()
        self.image = pygame.Surface((8, 8))
        self.image.fill((255, 255, 0))
        self.rect = self.image.get_rect(center=(x, y))
        self.pos = pygame.math.Vector2(x, y)      # เก็บตำแหน่งเป็นจำนวนจริง
        self.vel = pygame.math.Vector2(vx, vy)

    def update(self):
        self.pos += self.vel                      # ความเร็วคงที่ ไม่มีแรงเสียดทาน
        self.rect.center = (int(self.pos.x), int(self.pos.y))
        if (self.rect.right < 0 or self.rect.left > SCREEN_WIDTH or
                self.rect.bottom < 0 or self.rect.top > SCREEN_HEIGHT):
            self.kill()                           # ออกนอกจอ → ลบออกจากทุกกลุ่มสไปรต์
```
กระสุน $(6, 8)$ ที่เริ่มจาก (400, 300): เฟรมที่ 1 → (406, 308), เฟรมที่ 2 → (412, 316), เฟรมที่ 3 → (418, 324) … ตำแหน่งหลัง $n$ เฟรมคือ $(400 + 6n,\ 300 + 8n)$

## 2. การตรวจจับการชนแบบกล่องขอบเขต (AABB)

### จุดอยู่ในกล่องหรือไม่ (`basic_list.py`)
จุด $(p_x, p_y)$ อยู่ในกล่องที่มีมุมบนซ้าย $(x, y)$ กว้าง $w$ สูง $h$ เมื่อ
$$x \le p_x \le x + w \quad \textbf{และ} \quad y \le p_y \le y + h$$

```python
if (bullet.x >= enemy.x and bullet.x <= enemy.x + 50) and \
   (bullet.y >= enemy.y and bullet.y <= enemy.y + 50):
    print("Collision detected")
```
ศัตรูขนาด 50×50 จึงมีขอบเขต x: `enemy.x` ถึง `enemy.x + 50` และ y: `enemy.y` ถึง `enemy.y + 50` เงื่อนไขต้องเป็นจริง **ทั้งสองแกน** จึงเชื่อมด้วย `and` (ทบทวน `and`/`or` ที่ [EN-001-002 บท 03 การควบคุมการไหลของโปรแกรม](https://en-001-002-computer-programming.vercel.app/module/03))

### ตัวอย่าง: ศัตรูมุมบนซ้าย (200, 300) ขอบเขต x 200–250, y 300–350
| จุดกระสุน | x อยู่ในช่วง 200–250 | y อยู่ในช่วง 300–350 | `and` (ถูก) | `or` (ผิด) |
|---|---|---|---|---|
| (225, 320) | ✓ | ✓ | ชน | ชน |
| (260, 320) | ✗ | ✓ | ไม่ชน | **ชน** |
| (230, 360) | ✓ | ✗ | ไม่ชน | **ชน** |
| (250, 350) | ✓ (ขอบพอดี) | ✓ (ขอบพอดี) | ชน | ชน |

> [!danger] กับดัก `or`
> ถ้าเขียน `(x อยู่ในช่วง) or (y อยู่ในช่วง)` กระสุนที่อยู่ "แนวเดียวกัน" กับศัตรูแต่ห่างกันเป็นร้อยพิกเซลก็ถูกนับว่าชน เช่น (230, 360) อยู่ใต้ศัตรูแต่ x ตรงกัน ศัตรูจะตายทั้งแถวทันทีที่ยิง — โปรแกรมไม่ error แต่เกมผิด

### กล่องสองกล่องซ้อนทับกันหรือไม่
เมื่อกระสุนมีขนาด (ไม่ใช่จุด) ต้องตรวจว่ากล่อง A กับ B **ซ้อนกันทั้งแกน x และ y**
$$A_{left} < B_{right} \;\land\; A_{right} > B_{left} \;\land\; A_{top} < B_{bottom} \;\land\; A_{bottom} > B_{top}$$

```python
def boxes_overlap(ax, ay, aw, ah, bx, by, bw, bh):
    return (ax < bx + bw and ax + aw > bx and     # ซ้อนกันในแกน x
            ay < by + bh and ay + ah > by)        # ซ้อนกันในแกน y
```
ใน Pygame ทุก Sprite มี `rect` จึงเขียนสั้น ๆ ว่า
```python
if bullet.rect.colliderect(enemy.rect):
    bullet.kill()
    enemy.kill()
```
ตัวอย่าง: A มุมบนซ้าย (10, 10) ขนาด 40×40 (x 10–50, y 10–50) กับ B (45, 30) ขนาด 20×20 (x 45–65, y 30–50) → แกน x: $10 < 65$ และ $50 > 45$ ✓ แกน y: $10 < 50$ และ $50 > 30$ ✓ → **ซ้อนทับ** แต่ถ้า B เลื่อนไปที่ (50, 30) ขอบซ้ายของ B แตะขอบขวาของ A พอดี $50 > 50$ เป็นเท็จ → ไม่ซ้อนทับ (`colliderect` ให้ผลเดียวกัน: แตะขอบไม่นับ)

> [!question]- ฝึกทำ: กระสุนที่ (305, 148) ศัตรูมุมบนซ้าย (260, 100) ขนาด 50×50 ชนกันหรือไม่
> > [!success]- เฉลย
> > x: $260 \le 305 \le 310$ ✓, y: $100 \le 148 \le 150$ ✓ → **ชน**

> [!question]- ฝึกทำ: กล่อง A (10, 10) ขนาด 40×40 กับกล่อง B (20, 60) ขนาด 20×20 ซ้อนทับกันหรือไม่
> > [!success]- เฉลย
> > แกน x ซ้อน (20 < 50) แต่แกน y: A อยู่ 10–50, B อยู่ 60–80 → $A_{bottom} > B_{top}$ คือ $50 > 60$ เป็นเท็จ → **ไม่ซ้อนทับ**

> [!question]- ฝึกทำ: โค้ดต่อไปนี้พิมพ์ "hit" กี่ครั้ง
> ```python

> bullets = [(120, 130), (330, 90), (540, 440), (700, 700)]

>     for ex, ey in enemies:

## 3. ลบวัตถุออกจากลิสต์อย่างปลอดภัย

### กับดักคลาสสิก: ลบจากลิสต์ที่กำลังวนอยู่
```python
xs = [1, 2, 2, 3]
for x in xs:
    if x == 2:
        xs.remove(x)
print(xs)          # [1, 2, 3]  ← ลบไม่หมด!
```
ไล่ทีละรอบ (ไพทอนวนด้วย **ดัชนี** ภายใน):
| รอบ | ดัชนี | ลิสต์ขณะนั้น | x | การกระทำ |
|---|---|---|---|---|
| 1 | 0 | `[1, 2, 2, 3]` | 1 | ไม่ลบ |
| 2 | 1 | `[1, 2, 2, 3]` | 2 | ลบ → `[1, 2, 3]` (สมาชิกเลื่อนซ้าย) |
| 3 | 2 | `[1, 2, 3]` | 3 | ไม่ลบ — **2 ตัวที่สองถูกข้าม** เพราะเลื่อนมาอยู่ดัชนี 1 ที่ผ่านไปแล้ว |

### วิธีที่ 1: วนบนสำเนา (ใช้ในเกม)
```python
for bullet in bullets[:]:          # [:] สร้างสำเนาสำหรับวน
    if bullet.off_screen():
        bullets.remove(bullet)     # ลบจากต้นฉบับ สำเนาไม่เปลี่ยน
```
`bullets[:]` (หรือ `bullets.copy()`) เป็นลิสต์ใหม่ที่มีสมาชิกเดิม การลบจาก `bullets` จึงไม่กระทบลำดับที่กำลังวน ผลลัพธ์ของตัวอย่างข้างต้นจะเป็น `[1, 3]` ถูกต้อง

### วิธีที่ 2: เก็บรายการที่จะลบไว้ก่อน (`mask_to_remove`)
```python
mask_to_remove = []
for bullet in bullets:
    for enemy in enemies:
        if hit(bullet, enemy):
            mask_to_remove.append(bullet)     # จดไว้ก่อน ยังไม่ลบ
for bullet in mask_to_remove:
    if bullet in bullets:                     # กันลบซ้ำกรณีกระสุนโดนหลายตัว
        bullets.remove(bullet)
```

### วิธีที่ 3: สร้างลิสต์ใหม่ด้วย List Comprehension
```python
bullets = [b for b in bullets if not b.off_screen()]   # เก็บเฉพาะที่ยังอยู่ในจอ
```
ทบทวนลิสต์ที่ [EN-001-002 บท 06 การจัดการข้อมูลและไฟล์](https://en-001-002-computer-programming.vercel.app/module/06)

### ใน Pygame: `kill()` ทำให้ง่ายขึ้น
Sprite ที่อยู่ใน `pygame.sprite.Group` เรียก `self.kill()` ได้ ซึ่งจะถอดตัวเองออกจาก **ทุกกลุ่ม** อย่างปลอดภัย เพราะ `Group.update()` วนบนสำเนาภายในอยู่แล้ว — นี่คือเหตุผลที่ `bullet.py` เรียก `self.kill()` เมื่อออกนอกจอ

> [!tip] `remove(x)` ค้นหาก่อนลบ
> `bullets.remove(b)` ต้องไล่หา `b` ในลิสต์ตั้งแต่ต้น จึงใช้เวลา $O(B)$ ต่อครั้ง เมื่อ $B$ คือจำนวนกระสุน ถ้าลบหลายตัวต่อเฟรมควรใช้วิธีที่ 3 ที่สร้างลิสต์ใหม่รอบเดียว

> [!question]- ฝึกทำ: จงบอกผลลัพธ์
> ```python
> xs = [1, 2, 2, 3]
> for x in xs[:]:
>     if x == 2:
>         xs.remove(x)
> print(xs)
> ```
> > [!success]- เฉลย
> > `[1, 3]` — วนบนสำเนา 4 รอบครบทุกตัว ลบ 2 ทั้งสองตัวออกจากต้นฉบับ

> [!question]- ฝึกทำ: กระสุน `[(50, 50), (900, 100), (300, -5), (400, 400)]` บนจอ 800×600 ตัวใดถูกใส่ใน `mask` และ `bullets` เหลืออะไร
> ```python
> mask = [b for b in bullets if b[0] < 0 or b[0] > 800 or b[1] < 0 or b[1] > 600]
> for b in mask:
>     bullets.remove(b)
> ```
> > [!success]- เฉลย
> > `mask = [(900, 100), (300, -5)]` (x เกิน 800 และ y ติดลบ) → `bullets = [(50, 50), (400, 400)]`

## 4. การแบ่งพื้นที่ด้วยกริด (Spatial Grid)

### ปัญหา: ตรวจทุกคู่
กระสุน $B$ ลูกกับศัตรู $E$ ตัว ต้องเปรียบเทียบ $B \times E$ ครั้ง **ทุกเฟรม** เช่น 40 × 2,000 = 80,000 ครั้ง ที่ 60 FPS คือ 4.8 ล้านครั้งต่อวินาที — ไพทอนทำไม่ทัน เกมจะกระตุก

### แนวคิด: ตรวจเฉพาะวัตถุที่อยู่ "ช่องเดียวกัน"
แบ่งจอเป็นช่องสี่เหลี่ยมขนาด `cell_size` กระสุนที่อยู่ช่อง (5, 6) ไม่มีทางชนศัตรูที่อยู่ช่อง (0, 0) จึงไม่ต้องตรวจ

### สร้างกริด (`grid.py`)
```python
class Grid:
    def __init__(self, width, height, cell_size):
        self.cell_size = cell_size
        self.cols = width // cell_size        # 1200 // 150 = 8 คอลัมน์
        self.rows = height // cell_size       # 900 // 150 = 6 แถว → 48 ช่อง
        self.cells = []
        for row in range(self.rows):          # ลิสต์ซ้อนลิสต์ cells[row][col]
            row_cells = []
            for col in range(self.cols):
                row_cells.append([])          # แต่ละช่องเก็บลิสต์ของวัตถุ
            self.cells.append(row_cells)

    def get_cell(self, x, y):
        return y // self.cell_size, x // self.cell_size    # คืน (row, col)

    def clear(self):
        for row in range(self.rows):
            for col in range(self.cols):
                self.cells[row][col] = []

    def add(self, obj):
        row, col = self.get_cell(obj.rect.centerx, obj.rect.centery)
        self.cells[row][col].append(obj)
```

$$\text{col} = \left\lfloor \frac{x}{\text{cell\_size}} \right\rfloor \qquad \text{row} = \left\lfloor \frac{y}{\text{cell\_size}} \right\rfloor$$

> [!warning] ลำดับ (row, col) กับ (x, y) สลับกัน
> แถว (row) มาจากพิกัด **y** และคอลัมน์ (col) มาจากพิกัด **x** — `get_cell(150, 149)` ได้ `(0, 1)` ไม่ใช่ `(1, 0)` และเข้าถึงด้วย `cells[row][col]` เหมือน `table[i][j]` ในบทลิสต์ซ้อนลิสต์

> [!bug] `[[]] * cols` สร้างลิสต์เดียวกันซ้ำ
> `cells = [[]] * 3` แล้ว `cells[0].append(1)` ได้ `[[1], [1], [1]]` เพราะทั้งสามช่องชี้ลิสต์เดียวกัน ต้องใช้ `[[] for _ in range(3)]` หรือวนสร้างทีละช่องแบบข้างต้น

### ตัวอย่างไล่ค่า: จอ 1200×900, `cell_size = 150`
| พิกัด (x, y) | col = x // 150 | row = y // 150 | ช่อง (row, col) |
|---|---|---|---|
| (0, 0) | 0 | 0 | (0, 0) |
| (1000, 820) | 6 | 5 | (5, 6) |
| (150, 149) | 1 | 0 | (0, 1) |
| (1199, 899) | 7 | 5 | (5, 7) ช่องมุมล่างขวา |

> [!warning] วัตถุที่ขอบจอพอดี
> `get_cell(x, 900)` ได้ row = 6 แต่แถวมีแค่ 0–5 → `IndexError` ศัตรูที่สะท้อนขอบอาจมี y = 900 พอดี จึงต้องจำกัด `min(row, self.rows - 1)` หรือใช้ `rect.center` ที่อยู่ในจอเสมอ

### ตรวจการชนด้วยกริด (`main.py`)
```python
grid.clear()                                   # 1. ล้างทุกช่อง (ทุกเฟรม)
for enemy in enemies:
    grid.add(enemy)                            # 2. ใส่ศัตรูลงช่องตามตำแหน่ง
for bullet in bullets[:]:
    row, col = grid.get_cell(bullet.rect.centerx, bullet.rect.centery)
    for enemy in grid.cells[row][col][:]:      # 3. ตรวจเฉพาะศัตรูในช่องเดียวกัน
        if bullet.rect.colliderect(enemy.rect):
            enemy.kill()
            bullet.kill()
            break                              # กระสุนหนึ่งนัดโดนตัวเดียว
```

### เร็วขึ้นเท่าใด
| วิธี | จำนวนการเปรียบเทียบต่อเฟรม |
|---|---|
| ตรวจทุกคู่ | $B \times E$ |
| ใช้กริด | $\sum_{\text{ช่อง}} B_c \times E_c$ (เฉพาะคู่ในช่องเดียวกัน) |

ถ้ากระสุน 40 ลูก ศัตรู 2,000 ตัว กระจายเท่ากันใน 48 ช่อง:
- ทุกคู่: $40 \times 2000 = 80{,}000$ ครั้ง
- กริด: แต่ละช่องมีกระสุน $40/48 \approx 0.83$ ลูก ศัตรู $2000/48 \approx 41.7$ ตัว → $48 \times 0.83 \times 41.7 \approx 1{,}667$ ครั้ง (**ลดลงประมาณ 48 เท่า** = จำนวนช่อง)

จากการทดลองสุ่มตำแหน่งจริงในใบงาน ([/lab/08](/lab/08)) ได้ 80,000 เทียบกับ 1,649 ครั้ง ใกล้เคียงค่าประมาณ

> [!note] ข้อจำกัดของกริด
> วัตถุที่ **คร่อมเส้นแบ่งช่อง** จะอยู่ในช่องเดียวตามจุดศูนย์กลาง กระสุนในช่องข้างเคียงจึงไม่ถูกตรวจกับมัน — การทดลองในใบงานพบการชน 181 คู่เมื่อตรวจทุกคู่ แต่กริดพบเพียง 129 คู่ ระบบจริงจึงตรวจช่องรอบข้างด้วย (เปรียบเทียบเพิ่มเป็น 5,688 ครั้ง แต่ยังน้อยกว่า 80,000 มาก) หรือเลือก `cell_size` ให้ใหญ่กว่าวัตถุ

> [!question]- ฝึกทำ: จอ 1600×1000 ใช้ `cell_size = 200` จะได้กริดกี่แถว กี่คอลัมน์ และวัตถุที่ (1450, 610) อยู่ช่องใด
> > [!success]- เฉลย
> > cols = 1600 // 200 = 8, rows = 1000 // 200 = 5 (40 ช่อง) → (row, col) = (610 // 200, 1450 // 200) = **(3, 7)**

> [!question]- ฝึกทำ: กริดจอ 1200×900 `cell_size = 100` มีกี่ช่อง และวัตถุที่ (1199, 0) อยู่ช่อง (row, col) ใด
> > [!success]- เฉลย
> > 12 คอลัมน์ × 9 แถว = 108 ช่อง; (0 // 100, 1199 // 100) = **(0, 11)**

> [!question]- ฝึกทำ: กระสุน 40 ลูก ศัตรู 2,000 ตัว ถ้าใช้กริด 108 ช่อง (cell_size 100) กระจายเท่ากัน จะเปรียบเทียบประมาณกี่ครั้ง
> > [!success]- เฉลย
> > $80{,}000 / 108 \approx 741$ ครั้ง — ช่องยิ่งเล็กยิ่งเปรียบเทียบน้อย แต่ยิ่งเสี่ยงพลาดวัตถุที่คร่อมเส้นแบ่ง

## 5. ความซับซ้อน Big-O และการวัด FPS

### สัญกรณ์บิ๊กโอ (Big-O Notation)
บอกว่า "เวลาทำงานโตตามขนาดข้อมูลอย่างไร" โดยไม่สนค่าคงที่
| โค้ดในรายวิชา | จำนวนครั้งที่ทำงาน | ความซับซ้อน |
|---|---|---|
| `line(n)` วนซ้ำ n ครั้ง | $n$ | $O(n)$ |
| `block(row, col)` | $\text{row} \times \text{col}$ | $O(\text{row} \times \text{col})$ |
| `triangle(n)` พิมพ์ $1 + 2 + \dots + n$ | $n(n+1)/2$ | $O(n^2)$ |
| ตรวจการชนทุกคู่ | $B \times E$ | $O(B \cdot E)$ |
| ตรวจการชนด้วยกริด (กระจายเท่ากัน $C$ ช่อง) | $B \times E / C$ | $O(B \cdot E / C)$ |
| `bullets.remove(b)` (ต้องค้นหาในลิสต์) | สูงสุด $B$ | $O(B)$ ต่อครั้ง |
| `bullets.append(b)` | 1 | $O(1)$ |

ความหมายในทางปฏิบัติ: ถ้าศัตรูเพิ่มเป็น 2 เท่า การตรวจทุกคู่ใช้เวลา 2 เท่า (เพิ่มเป็นสัดส่วนตรง) เช่น กระสุน 30 ลูก ศัตรู 500 ตัว = 15,000 ครั้ง → ศัตรู 1,000 ตัว = 30,000 ครั้ง ส่วน `triangle(n)` ถ้า $n$ เพิ่ม 2 เท่า งานเพิ่มราว 4 เท่า ($O(n^2)$)

### วัดผลจริงด้วย `clock.get_fps()`
```python
clock = pygame.time.Clock()
font = pygame.font.SysFont(None, 28)
while running:
    ...
    fps_text = font.render(f"FPS: {clock.get_fps():.1f}", True, (255, 255, 255))
    screen.blit(fps_text, (10, 10))
    pygame.display.flip()
    clock.tick(60)                 # ขอ 60 FPS แต่ได้จริงเท่าไรดูจาก get_fps()
```
- `clock.tick(60)` **จำกัดไม่ให้เกิน** 60 เฟรมต่อวินาที (เฟรมละ ≈ 16.7 ms)
- `clock.get_fps()` คือ **อัตราเฟรมจริง** ถ้างานในหนึ่งเฟรมใช้เวลาเกิน 16.7 ms (เช่น ตรวจชน 80,000 คู่) ค่าจะต่ำกว่า 60 — นี่คือเครื่องมือตรวจว่ากริดช่วยจริงหรือไม่
- ทดลอง: เพิ่มศัตรูจาก 200 → 2,000 ตัว ดู FPS ก่อนและหลังเปิดใช้กริด

### นับเฉพาะกระสุนด้วย `isinstance`
`all_sprites` เก็บทั้งยาน กระสุน และศัตรูปนกัน การนับจำนวนกระสุนจึงต้องกรองด้วยชนิด
```python
bullets_on_screen = [s for s in all_sprites if isinstance(s, Bullet)]
text = font.render(f"Bullets: {len(bullets_on_screen)}", True, (255, 255, 255))
```
`isinstance(s, Bullet)` คืน `True` เมื่อ `s` สร้างจากคลาส `Bullet` หรือคลาสลูกของมัน (ทบทวนคลาสที่ [EN-001-002 บท 08 คลาสและวัตถุ](https://en-001-002-computer-programming.vercel.app/module/08)) เช่น `[Bullet(), Enemy(), Bullet(), Bullet(), Enemy()]` นับได้ 3

> [!question]- ฝึกทำ: กระสุน 50 ลูก ศัตรู 2,000 ตัว ตรวจทุกคู่ต้องเปรียบเทียบกี่ครั้งต่อเฟรม และกี่ครั้งต่อวินาทีที่ 60 FPS
> > [!success]- เฉลย
> > $50 \times 2000 = 100{,}000$ ครั้งต่อเฟรม → $6{,}000{,}000$ ครั้งต่อวินาที

> [!question]- ฝึกทำ: `clock.tick(60)` กับ `clock.get_fps()` ต่างกันอย่างไร และถ้า `get_fps()` คืน 35.2 แปลว่าอะไร
> > [!success]- เฉลย
> > `tick(60)` คือเพดานที่ขอ ส่วน `get_fps()` คืออัตราที่ทำได้จริง — 35.2 แปลว่างานในแต่ละเฟรมใช้เวลาประมาณ $1000/35.2 \approx 28$ ms เกินงบ 16.7 ms เกมจึงช้ากว่าที่ตั้งใจ

> > [!success]- เฉลย
